# Frontend Conventions

## Design system
- All UI-related changes (colors, typography, radius, tables, MarkdownPreview, long-form prose in general) must follow `DESIGN.md`.
- When adding new color tokens, radius values, or typography scales, update `DESIGN.md` together with the implementation (do not let the implementation land first).
- Before hardcoding a `max-width` or `font-size`, check whether the scale already exists in `DESIGN.md` §3 / §5.

## Next.js 16
- `params` is now a `Promise`. In Server Components use `await params`; in Client Components use `use(params)` or `useParams()`.
- The top page (`/`) is a Server Component and fetches `http://backend:8000` directly.
- Drive and file pages are Client Components and fetch through `/api/` (rewrites).

## i18n (next-intl)
- Routing: cookie-only (`NEXT_LOCALE`). No locale prefix in URLs.
- Client Component: `useTranslations('namespace')`.
- Server Component: `getTranslations('namespace')`.

## Translation file policy

| File | Role | Git tracking |
|---|---|---|
| `frontend/src/messages-core/{locale}.json` | Core definitions (edit here) | ✅ tracked |
| `frontend/src/messages/{locale}.json` | Merged output, generated | ❌ gitignored |
| `addons/{name}/frontend/messages/{locale}.json` | Addon definitions (edit here) | ✅ tracked (in addon repo) |

- **Core translation keys must only live in `messages-core/`**. Do not edit `messages/` directly — it is generated by `scripts/merge-addon-messages.mjs`.
- **Addon translation keys must only live in that addon's `frontend/messages/`**. Do not let them leak into core.
- The merge script deep-merges `messages-core/` and `src/addons/*/messages/` to produce `messages/` (run during the Dockerfile build and before `pnpm dev`).

## Test library constraints
- Vitest 4 has a rolldown native-bindings issue → **use 3.x**.
- jsdom 29 has ESM compatibility problems → **use 25.x**.
