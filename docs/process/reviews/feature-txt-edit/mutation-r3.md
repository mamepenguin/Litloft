### Bucket A (goes wrong silently in normal use)

**M75 — `MarkdownDocumentLayout.tsx:68`, the split clamp applied to every document (I7).** With the `plainText &&` removed, a `.md` on a desktop-width viewport offers Split, and clicking it (or the Markdown editor's view-mode shortcut that rotates edit → split → preview) lands in Read. A `.md` silently loses Split. No test clicks Split on a `.md` mounted under `MarkdownDocumentLayout` and checks the pressed mode. Pin: render `MarkdownDocumentLayout` (or `FileDetailContent` with a `text/markdown` file and the knowledge-edit slot) at a desktop width with `plainText` false, click `view-mode-split`, expect `aria-pressed="true"` on Split; a sibling row with `plainText` true and a child that calls the chrome context's `setViewMode("split")` expects Read (which also kills M70).

**M50 / M51 — `FileDetailFullScreen.tsx:137,145`, the collection host's own decision (I5).** `FileDetailFullScreen` draws its own `FileDetailChrome` row whenever `ridesFileDetailShell` says the content does not bring one. Forcing that decision to `false` (M50), or feeding the host's hook a drive that never matches the catalogue so it never decides (M51), leaves a `.txt` opened from a collection with two page rows: the host's breadcrumb row above the document layout's own. No test mounts `FileDetailFullScreen` with a `.txt`; the vitest row "draws the same number of page rows on the collection surface as a .md does" mounts `FileDetailContent` directly with `surface="collection"`, so it checks the container's `ridesShell` (M40 is killed) but not the host's. Pin: in `FileDetailFullScreen.test.tsx`, a `.txt` (`text/plain`, small) on a drive whose catalogue has the knowledge-edit slot and policy on; expect exactly one `file-detail-chrome`, the same as the existing `.md` case there.

**M86 — `EditableTitle.tsx:124`, the suffix beside the input while renaming (I3).** Without it, clicking the title of `report.txt` shows an input holding `report` with nothing after it. A viewer who then types `report-2.txt` (the natural thing when no suffix is visible) sends `report-2.txt.txt`. Normal use, silently wrong name. The rename rows check the input value and the name sent for a typed stem, but never look for the suffix while the form is open. Pin: open the rename field on `report.txt` and assert the form contains a `.txt` text node beside the input (and, at e2e level, that it sits to the input's right on the same line).

### Bucket B (odd input, or equivalent under the current code)

**M01 / M02 — `textKind.ts:27`, the mime condition.** The scanner maps `.txt` to `text/plain` unconditionally (`backend/app/services/filetype.py:122`), so in normal use there is no `.txt` with another mime and dropping or widening the check changes nothing visible. The spec does list the mime as a condition (§1, line 30). Pin: a fallback row with `txtFile({ mime_type: "application/octet-stream" })` (or `text/markdown`) expecting the canvas viewer.

**M08 — `textKind.ts:28`, `endsWith` → `includes`.** Only a `text/plain` name with `.txt` in the middle (`notes.txt.c`, `x.txt.bat`) would differ; not normal use. Pin: a fallback row `txtFile({ filename: "notes.txt.bat" })`.

**M18 — `usePlainTextDocument.ts:39`, hold not keyed on the file id.** Equivalent under the current tree: the container instance of the hook is remounted per file by the `key={fileId}` in `FileDetailContent`, and the only instance that outlives a change of file (`FileDetailFullScreen`'s) moves within one collection, whose files share a drive and therefore every input of the decision. It becomes live only if the `key` is removed. Pin: `renderHook(usePlainTextDocument)` with file A then a rerender with file B of a different decision (e.g. B's drive catalogue lacks the slot), expecting B's own decision.

**M70 — `MarkdownDocumentLayout.tsx:68`, the split→preview clamp removed.** Unreachable in normal use with the knowledge addon at `88791f2`: the toggle hides Split (`hideSplit`, M71 is killed) and the addon's `cycleViewMode` alternates only Read/Edit in plain-text mode (`Editor.tsx:1109-1113`), so nothing calls the chrome setter with `"split"`. The clamp is core's second layer for I5 "by the shortcut"; it would matter only if the addon regressed. Pin: the second half of the M75 test (a child calling `setViewMode("split")` under `plainText` expects Read).

**M74 — `MarkdownDocumentLayout.tsx:69`, clamp deps `[plainText]` → `[]`.** Equivalent: the layout is remounted per file (the container `key`), so `plainText` never changes on a mounted layout. Pin: rerender one `MarkdownDocumentLayout` from `plainText` true to false and click Split, expecting Split.
