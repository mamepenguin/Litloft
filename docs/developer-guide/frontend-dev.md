# Frontend development

Next.js 16 (App Router) + TypeScript + Tailwind CSS v4 + next-intl. Code is under `frontend/src/`.

The rules for this code are in [`.claude/rules/frontend-conventions.md`](../../.claude/rules/frontend-conventions.md) and, for anything visual, `DESIGN.md` at the repo root. This page does not repeat them.

## Running locally

`pnpm` is the package manager. Run commands from `frontend/`.

```bash
cd frontend
pnpm install
node scripts/merge-addon-messages.mjs   # merge translations; rerun after editing any messages file
pnpm test                               # vitest run
pnpm test:watch                         # vitest, watch mode
pnpm typecheck                          # tsc --noEmit
pnpm lint                               # eslint
pnpm test:e2e:layout                    # Playwright, layout invariants
pnpm test:e2e:components                # Playwright, components in a browser
```

The translation merge is part of the Docker image build, not of `pnpm dev` or `pnpm build`, so run it yourself.

`pnpm dev` and `pnpm build` do not work in a development checkout: the dynamic `@/addons/<name>/...` imports cannot be resolved through the linked files in `src/addons`. The frontend Dockerfile copies the addon trees in as real files before building. To see UI changes, run the compose stack (`docker compose up -d --build`).

## Code layout

```
frontend/src/
├── app/                   # App Router pages
│   ├── page.tsx           # /  (Server Component; drive picker)
│   ├── setup/             # first-run wizard
│   ├── unlock/            # password entry
│   ├── settings/          # profile and preferences
│   ├── admin/             # layout.tsx: admin gate + restart banner; settings/: Drives, Passwords, Addon policy
│   ├── drive/[name]/      # drive pages, search, collections, drive-scoped addon pages
│   ├── files/[id]/        # file detail
│   └── addons/[name]/     # global addon pages
├── components/
├── hooks/
├── lib/                   # api.ts, tags.ts, safeStorage.ts, …
├── i18n/                  # next-intl config (locales in config.ts)
├── messages-core/         # core translations (tracked)
├── messages/              # merged translations (generated, gitignored)
├── addons/                # addon frontends (generated by setup-addons.sh, gitignored)
└── types/
```

Tests live in `__tests__/` directories beside the code they test.

## Custom server

`frontend/server.js` is the process on port 3000. It:

- answers `/api/internal/*` with 404;
- sends the WebSocket (`/api/ws`) straight to the backend;
- passes everything else to Next.js, whose rewrite in `next.config.ts` forwards `/api/*` to `http://backend:8000`.

## Data fetching

- The home page (`/`) is a Server Component and fetches `http://backend:8000` directly.
- Drive and file pages are Client Components and fetch through `/api/`.
- `params` is a `Promise` in Next.js 16: `await params` in Server Components, `use(params)` or `useParams()` in Client Components.

## i18n

- next-intl with cookie-only locale (`NEXT_LOCALE`) and no URL prefix. Locales are listed in `src/i18n/config.ts`.
- Client Components: `useTranslations('namespace')`. Server Components: `getTranslations('namespace')`.
- Core strings go in `src/messages-core/{locale}.json`. Addon strings go in the addon's own `frontend/messages/{locale}.json`.
- `scripts/merge-addon-messages.mjs` deep-merges `src/messages-core/` and `src/addons/*/messages/` into `src/messages/`. Never edit `src/messages/`; it is overwritten.

## Tags

Always save tags with `saveFileTags(file, tags)` from `@/lib/tags`. It decides between the `.md` frontmatter and the database; UI code must not. The timing rules (500 ms debounce, one retry on `ConflictError`) are in `design-decisions.md` under Tag editing.

## Markdown and wiki links

- Render Markdown with `MarkdownPreview`. It turns `[[X]]` into links with the classes `wiki-link wiki-resolved`, `wiki-unresolved` or `wiki-ambiguous`, using the map passed as `wikiResolution`. Do not build wiki-link DOM anywhere else.
- If you have a file id, use `MarkdownFileViewer`. It fetches the body and the resolutions itself; the body renders first and unresolved-looking links update when the map arrives.
- `getWikiResolutions(fileId)` in `@/lib/api` throws for a missing file (404) or a non-Markdown file (415). Callers that render arbitrary files should catch it and render without the map.

## Navigation

Page transitions use `router.push()` or `<Link>`, never a full reload. The one exception is **Lock** in the sidebar, which reloads the app at `/` (`window.location.href = "/"`) after locking.

## Filters

The folder tree and the file listing both use `<FilterField>` from `@/components/folder/FilterField`. Reuse it for a new filter surface.

## Addon slots

Core renders a slot with `<AddonSlot id="..." />` from `@/components/AddonSlot`. `AddonSlotsProvider` fetches `/api/addons/status?drive=` when the drive changes, so slots already reflect per-drive policy. A slot with no contributions renders nothing. The slot list and each slot's props are in [ADDON-DEVELOPMENT.md → UI Slot System](../ADDON-DEVELOPMENT.md#ui-slot-system). A new slot needs an entry there.

## Keyboard shortcuts

Register page shortcuts with `useShortcuts(id, label, shortcuts, enabled?, priority?, blocksLower?)` from `@/hooks/useShortcuts`. Contexts form a stack; an overlay passes `OVERLAY_PRIORITY` so it wins over contexts that enable later.

## Preferences on `<html>`

An attribute the CSS reads from `<html>` must be set before first paint. Those go in `lib/preferenceInitScript.ts`, the inline script `app/layout.tsx` puts in `<head>` (currently `data-theme` and `data-media-layout`). Read `localStorage` through `lib/safeStorage.ts`; a direct read throws where site data is blocked.

## Testing

- Pin `vitest` to 3.x and `jsdom` to 25.x (see `frontend-conventions.md`).
- jsdom does no layout. Anything about a box's size or shape is asserted in `e2e-layout/` (Playwright against a static fixture). Components that need a real gesture are tested in `e2e-components/`. Both run in CI.
- A new cell shape inside `.justified-grid` needs a row in the `e2e-layout` fixture's markup table; `justifiedGridFixtureParity.test.tsx` fails when the table and the components differ.

See [testing](testing.md).

## Common problems

- **Missing translation keys**: the merge script did not run after a messages file changed.
- **Redirect loop on `/setup`**: the `setup_completed` sentinel and the frontend gate disagree. Change them together.
