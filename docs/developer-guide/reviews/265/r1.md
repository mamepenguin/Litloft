## F-1 [introduced] Unhashable `placement` raises inside `_navigation_error`, so the whole addon is lost instead of only its `navigation` (proposed bucket A: invariants 2 and 3)

`_navigation_error` does `nav.get("placement") not in _VALID_PLACEMENTS`. `_VALID_PLACEMENTS` is a `set`,
so a JSON array or object as `placement` (`"placement": ["primary"]`, `"placement": {"x": 1}`) raises
`TypeError: unhashable type` instead of returning an error string. The function is new in this PR, so
`[introduced]` needs no parent reproduction (at the parent there is no validation and such an addon
registers normally).

Consequences:

- **Manifest path**: the `TypeError` escapes `_without_invalid_navigation`, is caught by the
  `except Exception` in `load_external_manifests`, and `_registry[addon_name]` is never assigned. The addon
  disappears from `/api/addons/status`, its slots vanish, and `get_external_addons()` loses its proxy
  (so `addon_proxy` stops routing it). Invariant 2 says those remain.
- **In-process path**: `register_in_process` raises (invariant 3: "None of these raises at startup or
  import"). In `main._load_addons` the router has already been included; the exception jumps to that
  loop's `except Exception`, so `_loaded_addons[name]` is not set, the addon is absent from the
  catalogue, **and `hasattr(mod, "on_startup")` is never reached — the addon's startup hook is dropped**
  (this last point is from reading `main.py` `_load_addons`; the registry part is reproduced below).

Reproduction (scratch test bind-mounted as `/app/tests/test_r265_repro.py`, reusing the PR's fixtures):

```python
@pytest.mark.parametrize("placement", [["primary"], {"x": 1}])

    proxy = {"target_env": "BADNAV_URL", "target_default": "http://badnav:1", "routes": []}
    manifests(badnav=_meta("badnav", navigation={**VALID_NAV, "placement": placement}, proxy=proxy))
    assert "badnav" in addon_registry.get_external_addons()

@pytest.mark.parametrize("placement", [["primary"], {"x": 1}])

    assert "navigation" not in addon_registry._registry["badnav"]
```

   without `?drive=` and with `?drive=` for a drive whose policy enables the addon (M20, M22 killed; a
   scratch check with an unconfigured-policy drive also passes). **Not held by tests** for placements

   slots and its proxy are all gone (F-1).

   list/object `placement` (F-1); `null` `i18n_key` / `icon` handled correctly but not held by a test (F-3).

   F-1 in the other direction (the bad addon itself disappears), not the good one.

   absent as invalid) survives but is observable only as a spurious warning log per addon without

   covers `index` false, unknown drive, and on-drive. (Already filed, not re-derived:
   `[pre-existing]` unauthenticated `/api/addons/status` reveals locked-drive existence.)
7. Internal keys stay out: **holds** (M24 adding `proxy` killed by

**Is anything missing from this list?**

- **The in-process counterpart of invariant 2.** Invariant 2 names "external proxy registration" but
  nothing for `ADDON_META` addons: an invalid `navigation` must not cost an in-process addon its
  `_loaded_addons` entry or its `on_startup` hook (F-1 shows the path by which it can). Suggested
  wording: "…and, for an in-process addon, its `on_startup` still runs and `register_in_process` returns
  True."
- **Invariant 3's "outside {primary, sources, utility}" should say it includes non-string JSON values**
  (number, array, object), since the unhashable ones are exactly where the implementation diverges.
