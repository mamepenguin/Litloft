## Q1 — did 2b11944b do what it claims

**Yes, r2 F1 is fixed.** Reproduced: with the bc010658 hook and the 2b11944b tests, "does not carry a pinch across a change of picture" fails (1 failed / 53 passed). With the 2b11944b hook it passes.

How `trackpadPinch` is used in each handler and in the reset:
- `onStart` sets it only when no pointer is down. Unchanged from bc010658's local `start`.
- `onChange` reads it into a local on each event, and does nothing if it is null or a pointer is down.
- `onEnd` does nothing if it is null. Otherwise it clears it and settles.
- The reset effect clears it with the other per-gesture refs, then `settle(FIT)`.
- Probe (temporary, deleted): gesturestart → change(2) → resetKey change → change(2.5) gives scale 1. The late gestureend is still `defaultPrevented` and does not settle (settled stays 1). **A new pinch after the reset works:** gesturestart → change(2) gives `translate(-200px, -400px) scale(2)`, and gestureend settles at 2. For the rest of the interrupted pinch Safari sends no new gesturestart, so that pinch does nothing, and the page does not zoom either. That is the intended result.
- Moving the state from a local variable to a ref changes one other thing. bc010658's local `start` was dropped whenever the gesture effect re-ran (a frame detach/reattach or a dependency change). The ref survives that. Probe: closing and reopening the Harness with an unchanged resetKey mid-pinch carries the pinch (`translate(-400px, -800px) scale(3)`). **Neither viewer can reach this.** ImageGallery has `open` in resetKey, so closing clears it. ArchiveImageViewer renders its frame unconditionally inside the portal, so the hook unmounts with the viewer. The dependencies are all stable `useCallback`s. Not a finding. It becomes one if a viewer ever detaches the frame without changing resetKey.
- Lint: 3 warnings in the changed files, all `no-unused-expressions` on the ternary statements in `onPointerUp`. They date from 3f21bbcf and are not from this commit. `tsc` is clean.

The new tests:
- "scales each change from where the pinch began" kills M2 (compounding from `viewRef`, r2 N11).
- "settles when the pinch ends" kills M3 (no settle, r2 N9).
- "does not carry a pinch across a change of picture" kills M1.

## Findings

### F1 — The ImageGallery spread test assumes spreads start off, and leaves them on
- Label: [introduced] (new test in 2b11944b)
- Invariant: none. Test hygiene. Bucket B unless the supervisor counts CI retry behaviour.
- Clicking the toggle calls `writeSpreadMode(true)`. Nothing clears `localStorage`: `src/test/setup.ts` installs one `TestStorage` per worker and never clears it, and the test file has no clear in `beforeEach`/`afterEach`. So `image-viewer:spread-mode` stays `"true"` for every test in the file that runs after this one.
- **Is there order coupling today?** No. I ran 12 seeds of `vitest run --sequence.shuffle --sequence.seed=1..12` on ImageGallery.test.tsx and all 28 tests passed on every seed. No other test in the file turns spreads on, and none depends on them being off.
- **The test depends on its own starting state.** Probe: seed `image-viewer:spread-mode = "true"` at the start of the test, and it fails with `expected 'single' to be 'half'`, because the click turns spreads off. The CI shuffled job runs `--retry=1`, and a retry reuses the same storage. So if the first attempt fails after the click for any reason (a timing flake), the retry starts with spreads on and fails deterministically. The retry cannot absorb a flake in this test. The fix belongs to the author: clearing storage in `beforeEach`, or setting the starting value explicitly in the test.

### F2 — r2 F3 is only partly closed: the pinch origin and the preventDefault on gesturechange are still unheld
- Label: [introduced] (the handler is from bc010658, on this branch; not reachable on develop)
- Invariant: none listed. Trackpad zoom was added by user decision. **M4 is a behaviour a Safari user would hit at once:** the pinch would zoom toward the top-left, not toward the cursor. By "a test that lets an A through is an A", the supervisor decides.
- Survivors (want=kill, result live):
  - M4 (r2 N12): the zoom origin is ignored (`{x:0,y:0}`). Every gesture test asserts only `scale`.
  - M5 (r2 N4): no `preventDefault` on gesturechange. Only gesturestart's `defaultPrevented` is asserted.

### F3 — Trajectory: two consecutive rounds each grew a hand-maintained list that defines "the picture changed"
- Label: n/a (a finding across rounds; assigning C is the supervisor's call)
- Fix diffs in order:
  - **bc010658**:
    - Grew the **resetKey prediction** in both viewers. ImageGallery went from `index:half` to `open:face.kind:index:half`; ArchiveImageViewer went from `index:half` to `face.kind:index:half`.
    - Added **two states**. `frameEl` is structural. The gesture `start` came with a feature the user approved.
    - Did **not** register the new gesture state with the reset. That omission is r2 F1.
  - **2b11944b**:
    - Leaves resetKey unchanged.
    - Adds no new state: the local `start` becomes the `trackpadPinch` ref, so the count stays the same.
    - Adds **one entry to the reset effect's clear list**. The list is now `pointers`, `press`, `pinch`, `trackpadPinch`, then `settle(FIT)`.
- **Answer.** By the rule's letter, yes: each round extended an enumeration tied to "the picture changed". bc010658 extended what counts as a change, and 2b11944b extended what a change must clear. These are two lists, not one. And 2b11944b completes an addition bc010658 made, rather than handling a new case. The next round could not tell the difference in shape, though. Both lists are open-ended, and hand-kept in sync with state spread across separate refs:
  - Every future piece of gesture state (a momentum timer, a double-tap press, a keyboard-pan repeat) must be added to the reset by hand.
  - No test fails when one is left out.
  - `wheelTimer` is already such a piece of state: it is not cleared on reset. Its pending callback only calls `setSettledScale(viewRef.current.scale)`, which reads the view after the reset, so it is harmless today.
- **Shape that would stop the growth.** Keep all per-gesture state in one ref object that the reset replaces in one assignment. Key the reset on the face's identity, which the viewer already computes (`face`), rather than on a string that lists its fields. That is for the author and supervisor. The reviewer only reports it.
- If a round 4 adds another resetKey dimension or another line to the clear list, it is the third such round.
