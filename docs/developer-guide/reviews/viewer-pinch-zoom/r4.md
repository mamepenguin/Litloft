## Q1 — is 0e8d0756 behaviour-preserving apart from what it claims

**Yes.** Every read and write of gesture state now goes through `gesture.current.<field>` at the moment of use. I checked each one:
- **Reset.** `gesture.current = newGesture()` replaces the object. At 2b11944b the reset cleared the same `Map` in place. The difference shows only if something holds the old Map or object across a reset. Nothing does. No handler captures `gesture.current` in a closure, and the hook never returns it.
- **Locals holding a field.** `onPointerMove` keeps `start = gesture.current.pinch`, `onChange` keeps `start = gesture.current.trackpad`, and `onPointerUp` keeps `s = gesture.current.press`. Each is used synchronously inside one handler. A reset could land mid-handler only if the parent's re-render and effects ran synchronously inside it. `settle`/`setView`, `navigate*` and `toggleControls` are all batched state updates, and nothing on these paths uses `flushSync`. The only `flushSync` in `src/` is in `useIsInternalDragging.ts`. **N11** caches the whole `gesture.current` in a local inside `onPointerUp` and survives, which confirms this: want=live, got live.
- **pointerup reads `press` before `endPointer`.** `endPointer` never reads or writes `press`, only `.pinched` through `press?.`. So the order does not matter. **N9** swaps the order and survives: want=live, got live.
- **2→1 finger handoff.** Same logic as the parent. Clearing `pinch` when one finger is left is equivalent today. **N10** never clears it and survives, because the move path requires `pointers.size >= 2` to pinch, a new second finger overwrites `pinch`, and the final lift is already treated as a pinch through `press.pinched`. That was true at 2b11944b as well. Not a finding.
- **`press.pinched` is mutated in place.** This is unchanged. **N12** replaces the object instead and is killed by 3 tests.
- **Trackpad handlers.** Mechanical rename. `onStart` writes to `gesture.current.trackpad` on whichever object is current, and the other handlers read it fresh.
- **Adding a field.** `newGesture(): Gesture` is typed, so a field added to `Gesture` but not to `newGesture` does not compile. The reset's clear list is now held by the compiler.

The new tests hold what they claim:
- The origin test kills **N6** (origin `{0,0}`) and **N7** (no preventDefault on gesturechange). This closes r3 F2.
- The ImageGallery storage clear: **N13** sets spreads on in `beforeEach` and the spread test fails. **N14** seeds `"true"` at module scope, the `beforeEach` clear neutralises it, and all tests pass. This closes r3 F1. Only `SPREAD_MODE_KEY` is cleared, not `LEGACY_SPLIT_MODE_KEY`, but no test in the file writes the legacy key.
