## Findings

### F1 — Folder ImageGallery never attaches its wheel listener when opened after mount (ctrl-wheel zooms the browser page; wheel-pan while zoomed does nothing)
- Label: [introduced] (the wheel listener is new code in this commit)
- Invariant: 6 (Ctrl/⌘ + wheel inside the viewer never zooms the browser page); also the spec's "Plain wheel … zoomed: pan".
- Severity: HIGH (A). Every real caller hits it.
- Cause: `useViewerZoom.ts` wheel effect (`useEffect(..., [measure, localPoint, setView])`) reads `frameRef.current` once. All three deps are stable callbacks, so the effect runs only at mount. `ImageGallery` is mounted with `open={false}` by both callers (`FileDetailFullScreen.tsx`, `folder/RightPaneFile.tsx`: `{file && <ImageGallery open={galleryOpen} …/>}`) and returns `null` while closed, so at mount `frameRef.current` is null, the effect returns early, and it never runs again when `open` turns true (nor after close → reopen, when the frame is a new element). `ArchiveImageViewer` is mounted only when shown, so it is unaffected. The unit tests and the e2e harness all render the hook open-from-mount, so none sees this.
- Reproduction (temporary vitest file, deleted afterwards): render `<ImageGallery open={false}/>`, rerender with `open={true}`, run timers, dispatch `new WheelEvent("wheel",{deltaY:-100,ctrlKey:true,cancelable:true})` on the `.touch-none` frame → `defaultPrevented === false` (control: same test rendered `open` from mount → `true`). Observed: `× opened after mount: ctrl wheel prevented — expected false to be true`, `✓ open at mount`.

### F2 — Zoom survives a spread-mode toggle (single ⇄ pair / half) when index and half do not change
- Label: [introduced]
- Invariant: 4 in spirit (the face changes under a zoomed view); the hook's own contract is "`resetKey` changes whenever the picture changes". Not in the literal list of page changes in invariant 4 — supervisor to decide A vs B.
- Severity: MEDIUM.
- Cause: both viewers use `resetKey = \`${index}:${showRightHalf}\``. Toggling spread mode in LTR keeps `showRightHalf === false` and the index, so a zoomed single page becomes a zoomed pair (or split half) with the old translate/scale, unclamped against the new content until the next gesture. Same when the face shape changes on image load (orientation learned → single ⇄ half/pair at the same index).
- Reproduction (temporary vitest file): ArchiveImageViewer, press `=`, rerender with `spreadMode` and `face={kind:"pair",indices:[1,2]}` at the same `imageIndex`/`showRightHalf` → `data-face="pair"` and content transform still `translate(0px, 0px) scale(1.25)`.

### F3 — Folder ImageGallery reopens zoomed when it was closed zoomed on the first image
- Label: [introduced]
- Invariant: not in the R-0 list; the spec states "Opening the viewer starts at fit" (see "Missing from R-0" below).
- Severity: MEDIUM (A if the supervisor adds the invariant).
- Cause: `ImageGallery` stays mounted while closed, so the hook's view state survives close. On close it does `setCurrentIndex(0)`; if the viewer was already at index 0 (half unchanged), `resetKey` (`0:false`) never changes across close → reopen, and the old zoom is shown.
- Reproduction (temporary vitest file): open gallery on Photo 1, press `=`, rerender `open={false}`, rerender `open={true}` → "1 / 3" shown and content transform still `translate(0px, 0px) scale(1.25)`.

### F4 — Tests let invariant 4 and invariant 5 through (content measurement, split/pair clamp, archive reset)
- Label: [introduced] (the hook and its measurement are new)
- Invariants: 4, 5 (a test that lets an A through is an A).
- Severity: MEDIUM.
- Survivors (want=kill, result live in vitest AND the component e2e): M10 (pan without clamp), M19 (drop the frame intersection of a split half), M20 (do not un-apply the transform), M21 (pair union → last element only), M22 (content rect = whole frame, ignoring the picture), M43/M45 (resetKey drops the half: a split-half step keeps the zoom), M46 (archive resetKey constant: archive paging never resets to fit), M53 (key zoom not clamped).
- The e2e swipe while zoomed moves 0.3 × frame width at 2×, which never reaches an edge, so its "never past the picture's own edge" assertion cannot fail. The e2e harness (`ViewerZoomFrame`) has no split (200% + translateX(-50%)) or pair structure and does not render either real viewer, so it cannot see F1, F2, F3 or a split/pair clamp error.
- Behaviour itself is correct where I measured it: with the harness DOM temporarily rewritten to a split face (200% width, translateX(-50%) for the right half, 1600×1100 picture, Pixel 5), a zoomed wheel pan of ±2000 px stopped exactly at the visible half's edges (half from 0.0 to 653.9 and from -260.9 to 393.0 against frame 0…393) for both halves. A synchronous burst of 10 wheel pans and a 20-event CDP burst also stayed clamped (gap −0.00006 px), so I found no stale-measurement overshoot.

### F5 — Tests let pointercancel handling and one-finger continuation go (invariant 8 / 1)

- Severity: LOW-MEDIUM.

### F7 — e2e "ctrl wheel … not the page" assertion on `visualViewport.scale` cannot fail
- Label: [introduced]
- Invariant: 6 (detector).
- Severity: LOW (B). The vitest `defaultPrevented` check does hold the preventDefault.
- Reproduction: M24 (remove `e.preventDefault()` on ctrl/⌘ wheel) → e2e still passes; headless Chromium ctrl+wheel does browser zoom, which never changes `visualViewport.scale`. The assertion to rely on is `defaultPrevented`.

### F8 — Zoom view not re-clamped when the layout changes under it (resize/rotate, image loads after a zoom)
- Label: [introduced]
- Invariant: 5 only in spirit (not panning).
- Severity: LOW (B).
- The view is stored in px and only clamped inside a gesture. Rotating a phone or resizing the window while zoomed, or zooming with `=` before the picture has loaded (measure falls back to the whole frame), leaves an unclamped view until the next gesture. No resize/load re-clamp exists (read, not run).

### F9 — Safari desktop trackpad pinch is not ctrl+wheel (claim, not reproduced)
- Label: [introduced]
- Invariant: 6 / the spec row "Ctrl/⌘ + wheel (also trackpad pinch)".
- Severity: LOW, unverified. macOS Safari reports trackpad pinch as `gesturestart/gesturechange`, not as ctrl+wheel, as far as I know. If so, nothing prevents Safari's page pinch-zoom there and the picture does not zoom. I could not synthesize a trackpad gesture here. Someone needs to check it on a Mac with Safari.

### Checked, no defect
- The prev/next buttons and the chrome bar are siblings of the frame, not inside it, so their pointerdown never reaches the frame's tap classifier (both viewers).
- Wrapping the content (zoom transform) outside the face div (split `translateX(-50%)`) composes correctly. M49 (ref on the face div) is equivalent because `measure` only queries descendants.
- `pointercancel` mid-pinch: both cancels → settle, no paging (read). A mouse released outside the frame leaves a stale map entry; the `buttons === 0` gate stops hover-panning, and the next mouse down replaces the same id. The only exposure is a touch landing on a hybrid device while the stale mouse entry exists (would form a pinch). That is negligible.
- A slideshow wrap to index 0 in pair mode with 2 images keeps the same face, so no reset is needed.
- `tsc --noEmit` clean. The tree was restored after each mutation: `git status` clean, HEAD 3f21bbcf.
