## 3. What c443451 could break

- **Removal at every width.**
  - The heading is not responsive-hidden, so the link shows on phone and desktop.
  - The link shows with or without a folder, when the folder has no tags, and when the list fails (P2).
  - When the chosen tag differs only in case, the link removes it in one step (P3).
  - The code holds in all of these states. Only the folder-chosen, list-loaded state is tested (R4-2).
- **Accent fill (§2.2):** `bg-accent-teal/15` is not `bg-accent`/`bg-accent-cta`, so no accent fill is spent. The chip matches the read-only tag pill's colours. Unlike the Editable Tag Chips pattern, the whole chip is the target, not a separate round `×` button. That fits "a destination is a link".
- **Touch target:** `pointer-coarse:min-h-11` gives the 44px height. The width of a short tag works out to about 45–50px from padding + icon. Not measured in a browser. The `h2` uses `items-baseline`, so a 44px chip in a baseline row may shift the folder label on coarse pointers. That needs a browser measurement, which this round did not do.
- **Focus:** activating the link navigates. `AllNotesList` is keyed on the scope, so it remounts and the focused element disappears. Focus falls to `body`, where the rail link used to keep it. Recorded under R4-3.
- **Anything that relied on the removed entry:**
  - The phone menu is still gated on `tags.length`, now without the synthetic entry. It hides when the folder has no tags. The heading link covers that case (P2).
  - The rail "choose again removes" rule still works and is still held (N8).

## Findings

### R4-1 [introduced] A (invariant 5) — the heading link's "keep the rest of the scope" is not held for `sort` and `q`

The href is `allNotesHref(pathname, { ...scope, tag: null })`, which is correct. But the only test of it uses `folder=Inbox&tag=ai`, with no sort and no search, so N2 (drops `q`) and N2b (resets `sort`) survive. The heading link is a new scope control that changes one part. Invariant 5 names "rail link and menu choice"; if the supervisor reads it as every scope control, this is A. Otherwise it is B. The existing "changes one part from every rail link…" test uses the `FULL` scope and is the natural holder.

### R4-2 [introduced] A (8b "the chosen tag can always be taken off") — the heading link is now the only remover in states no test renders

After c443451, the rail lacks the chosen tag in two cases: the tag differs in case, or it has no active text note in the current scope (for example a stale link, or all its notes trashed). On desktop the phone menu is `md:hidden`. So the heading link is the only one-step remover. Two gates on it survive:
- **N4:** link shown only when a folder is chosen. The unfiltered scope loses its remover, and P2's `tag=Gone` could not be taken off on desktop.
- **N6:** heading shown only after the list answers. A failed or slow list leaves no remover.

The code is correct in both states (P2). What is missing is a test at the unfiltered scope and with a failed list. If 8b's "always" is scoped to "with a folder chosen", N4 drops to B, and N6 stays A only when a folder is chosen.

### R4-3 [introduced] B — the scope heading's accessible name is now an action, and focus is lost on activation

- The `aria-label` replaces the link's visible text inside the `h2`. The heading name therefore becomes "Knowledge / AI Remove the tag filter “AI”" instead of "Knowledge / AI #AI". The author's test change from a name match to `toHaveTextContent` follows from this.
- The label does not contain the visible "#AI" (label-in-name).
- After activation, focus falls to `body`, because the list remounts.

None of this breaks a declared invariant. A remedy that does not add state: keep the visible text as the name and put the action in a visually hidden suffix, or move the link out of the `h2`.

### R4-4 [pre-existing] B — F4 still survives (R3-4 remainder)

Removing `setTags([])` still leaves the previous folder's counts on screen until the reply arrives, and no test notices. This was recorded in round 3, and c443451 did not change it.
