## Findings

### F1 — caller `className` can move the title, and nothing notices
- Label: `[introduced]` (PageFrame is created by this commit)
- R-0: #1 (title Y is the header's `py-2` and nothing more) — not broken by the code as committed; the tests do not hold it.
- Where: `frontend/src/components/PageFrame.tsx:28` merges an arbitrary `className`; callers use it for vertical padding today (`TrashView.tsx:112`, `MissingView.tsx:76` `pb-4 sm:pb-6`, `CollectionDetail.tsx:247` `pb-6`).
- Reproduction: M17, M18, M22, M23 — adding `pt-4`/`py-*` through the caller's `className` on any of the five screens survives the five touched unit files, the full vitest suite (M29), and `page-frame.spec.ts` (the e2e renders a fixture arrangement, not the callers). `PageFrame.test.tsx` "adds no vertical padding above the header" inspects only a frame it renders itself with `className="flex-1"`; the per-screen tests assert only `data-page-frame`.
- The spec's "held structurally (every destination renders inside PageFrame)" is only as strong as the frame's refusal to take top spacing, and the `className` escape hatch is exactly where the old `py-4 sm:py-6` / `py-6` used to live.
- Severity: medium. Suggested bucket: A (a test that lets an R-0 #1 break through). Supervisor decides.

### F2 — the children inset (R-0 #2) is tested on Home only
- Label: `[pre-existing]` for the untested wrappers — at `8d46f8ad` those bodies were already `px-4` and no test asserted their inset (not re-run at the parent: `git show 8d46f8ad` of `TrashMissingHeader.test.tsx`, `FolderBrowser.header.test.tsx`, `CollectionDetail.test.tsx` holds no inset assertion, and this commit only adds frame-attribute tests to them). Reachable as an R-0 #2 break because PageFrame deliberately does not own the inset, so each caller carries it.
- R-0: #2
- Where: `TrashView.tsx:131`, `MissingView.tsx:103`, `CollectionDetail.tsx:360`, `FolderBrowser.tsx:621` (and `FolderToolbar`'s own `px-4`, the first element under the Library header). Only `DriveHome.test.tsx` "insets the rows under the header exactly as far as the header" compares insets.
- Reproduction: M25, M26, M27, M29 live across the full suite.
- Severity: low–medium. Suggested bucket: A if R-0 #2 is meant per screen (the invariant says "each header"); otherwise ledger.

### F3 — the e2e fixture lays the frame out in a block parent; every real caller is a flex parent
- Label: `[introduced]` (fixture and spec created by this commit)
- R-0: none directly (header and body still share one column, so #2 holds)
- Where: `frontend/e2e-components/fixtures/app.tsx` `PageFrameArrangement` (mounted straight into `#root`); `PageFrame.tsx:28` `w-full`.
- Reproduction: M11 (remove `w-full`) passes all 8 e2e cases. Wrapping the `page-frame-wide` arrangement in `<div className="flex flex-col">` (the shape of `UploadZone`/`TwoPaneLayout` around the real callers): with `w-full` intact 8 pass; with `w-full` removed `wide at 1425px` fails — `mx-auto` in a flex parent stops the column stretching, so a capped frame shrinks to its content. The spec therefore does not measure the layout the screens actually use.
- Severity: low. Suggested bucket: B.

### F4 — a failed Library listing shows `drive · 0 items`
- Label: `[pre-existing]` — at `8d46f8ad` the same failure showed `0 items`; the drive prefix is new, the 0 is not.
- R-0: none as worded (#4 covers "not known yet"); contradicts spec rule 4 / DESIGN.md §6 "An unknown count shows the drive alone, never 0" for the failed case.
- Where: `frontend/src/hooks/useInfiniteScroll.ts` catch branch sets `total` 0 and `loading` false; `FolderBrowser.tsx:508-509` then settles `settledTotal = 0`.
- Reproduction (by code path): fetch rejects -> `setTotal(0)`, `finally setLoading(false)` -> `settled = {subject, total: 0}` -> `tCommon("driveScope", { drive, detail: "0 items" })`. The hook exposes no error state, so an empty drive and a failed fetch are indistinguishable at this call site.
- Severity: low. Suggested bucket: B; candidate for an R-0 #4 revision (see below).

### F5 — the Library root no longer carries a link to the drive picker
- Label: `[introduced]` — at `8d46f8ad` `FolderBrowser.tsx:512-519` rendered `Breadcrumb` (whose head is `Link href="/"`) at the Library root; at `df4f5734` `FolderBrowser.tsx:521` renders none there.

- The spec's per-screen table discusses the lost drop target (covered by the tree root band, `FolderTreePane.tsx:400-403`) but not the lost `/` link. Home already accepted the same trade (its comment); the Library root now matches it, leaving the sidebar as the only way to the drive picker from both destinations.
- Severity: low. Suggested bucket: B (record; likely intended).
