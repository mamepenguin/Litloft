- **r1-F1 (press over the book).** The wrapper is gone; the panel is DismissScrim's
  `nextElementSibling` and carries `data-swipe-exempt`, `absolute inset-x-2 z-20`,
  `bottom` and `max-height` itself. The positioning equals the old wrapper's

  Measured in a static replica of the boxes (Tailwind border-box preflight),

  The sibling rule is held: putting the wrapper back (P1) or any element between
  cover and panel (P2) fails "is the only thing a press does not close it on".
- **r1-F2 (focus after leaving full screen).** Done. The effect now runs
  `closeTypography` (which focuses the book) only when the panel was open.
  `closeTypography` depends only on `focusBook` -> `reader.frameRef` (a `useRef`),
  so the effect runs on mount and on a full-screen change only; on mount the ref
  is false, so it neither closes nor focuses. Opening the panel does not re-run
  it. Dropping `closeTypography` from the deps (E4) is equivalent (lived, want=live).
  The render-time ref write has precedent (`PdfPreview.tsx` `pageRef.current = page`)
  and eslint does not flag it; a discarded render's write is overwritten by the
  committed render before effects run. No break found.
- **r1-F3.** dd95cc1e2 uses r1's probe sequence; R8 now fails both engines.
  Stable under `--repeat-each=5`.
- **r1-F4 / F5.** C4, C9, C1, L1, N1, N2 now all killed (table).
- **r1-F6 (gap).** Gap is set only when it differs. On first open the renderer
  has no `gap` attribute (foliate's 7 % is a CSS default, not an attribute), so
  `null !== "6%"` sets it; a new renderer per book starts unset again. Gap is
  never left unset. Measured location messages per theme change: 1 with the
  guard, 3 without. The `<= 1` bound matches the measured 1.

## Findings

### 1. `expect(at.pLineHeight).not.toBe("")` cannot fail

- [introduced] by b0ad152b2 (`typography.spec.ts`, the theme test). Bucket B.
- A computed `line-height` is never the empty string, so no mutation of the
  reader can fail this line. Invariant 9's "a theme change keeps the typography"
  is already held by `pFamily` after the theme change. Suggest deleting the line
  (or asserting a value, if line-height after the second change is meant to be held).

### 2. The panel's new box is held by no real-browser test

- [introduced] by b0ad152b2 (the panel now owns `bottom` / `max-height`). Bucket B.
- P3, P4 and S2 live: no test reaches the panel's position, its cap to the frame,
  or its clearance above the full-screen chrome (jsdom lays nothing out; the
  e2e-epub suite loads the reader page alone, without `EpubPreview`). r1's fix
  direction for F1 suggested an `elementFromPoint` check in `e2e-layout`; the
  fix used the structural sibling test instead, which does hold F1's shape
  (P1, P2 killed).
- The current code is correct as measured in a static replica (Q1 above), so no
  user-reachable defect; this is only that a future edit to the box would go
  unnoticed. The author's pre-r1 real-browser measurement was of the old wrapper.

## Q3: trajectory

One fix round so far (b0ad152b2; dd95cc1e2 is tests only).

- F1: **removes** an element (the wrapper). Converging shape.
- F2: **adds state and a branch**: `typographyOpenRef` plus `if (typographyOpenRef.current)`.
  The ref exists only so that the effect's mount run, and a mode change with the
  panel closed, do not focus the book (E1 shows the unconditional form breaks
  "leaving does not focus"). That is the effect guarding against its own
  firing, which is the patching shape in miniature: "close on a mode change"
  expressed as an effect on a boolean needs a second piece of state to tell a
  real close from a no-op. A shape without it would be to record the mode the
  panel was opened in and derive `open = openedIn === isFullscreen`, but focus
  hand-back would still need a trigger, so it is not clearly smaller.
- F6: **adds a branch that encodes a prediction** about foliate (re-renders on
  any `setAttribute`, same value or not). It is measured (3 vs 1 layouts) and
  held by a test (G1 killed).
- Answer: yes, this round adds one state and two branches. It is the first fix
  round, so the "two rounds in a row" condition is not met. What to watch: if a
  later round adds another guard around the full-screen close (a previous-value
  ref, an "opened in this mode" flag, a check of where focus is), that would be
  the second round and should go to the supervisor.
