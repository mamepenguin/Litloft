### 1. Nothing holds "Skip only while nothing is stored" when the stored values equal what an unstored drive shows — MEDIUM (test lets an A through) — [introduced]

`frontend/src/app/setup/steps/AddonPolicyStep.tsx:81` (`storesAnything`); tests `AddonPolicyStep.test.tsx` "offers Skip while nothing is stored for the drives shown" / "offers Next once something is stored, even with every switch off", `SetupWizard.test.tsx` untouched path.

L6 replaces the condition with "some shown switch is Off" and all 124 tests pass. Every label fixture distinguishes the two readings only in states where "stored" and "some switch Off" coincide (`{}` vs `{main: {intelligence: false, knowledge: false}}`, `{elsewhere: ...}`). The state that separates them is a drive stored with values that read On.

Reproduced with a temporary wizard test (deleted): press `media / knowledge` twice, so `addonPolicy = {media: {knowledge: true}}`.
- HEAD: buttons `["Back","Next"]`; PUT `{"media":{"knowledge":true}}` — consistent with invariant 8.
- L6 applied: buttons `["Back","Skip"]`; pressing Skip, then Finish, PUTs `{"media":{"knowledge":true}}` — Skip offered while something is stored, and pressing it stores it. Invariant 8, both halves.

The code at HEAD is correct; the new label tests are titled for exactly this property and do not observe it. A fixture that kills L6: render the step with `{ main: { intelligence: true } }` and expect Next (or the wizard double-press above). The label tests are new in this commit, so `[introduced]` without a parent run.

## Trajectory

Fix diffs in order: `0b6aa86b` changed how stored shapes are read (`isAddonOn`, default-on) and left the label on "any switch On"; `ee2f99f9` swapped that one expression for "any shown drive has a key". No branch or state was added in code this round, and only one fix round exists, so the two-rounds-in-a-row test cannot be met yet.

What the new expression is, though, is a **prediction**: the label predicts what the Complete-step PUT will store, computed from a different set (drives shown) than the PUT sends (all keys). Finding 2 is exactly that gap. `0b6aa86b` also added a prediction of the same kind (the frontend's reading of what the backend will enforce, tied by the table). If the next round answers finding 2 by adding another condition to the label (e.g. "and no key for drives not shown"), that is the second round in a row adding a prediction; a shape that removes it is the label and the PUT reading the same object (e.g. the PUT sending only the shown drives' keys, which keeps the label as it is). The other direction, the label reading all of `addonPolicy`'s keys (L3), is what the new test "offers Skip while nothing is stored for the drives shown" rejects on purpose, so it would contradict a test this round added.
