## Findings

### F1 `[introduced]` — `auto_tags._build_system_prompt` is no longer tied to its template

`app/workers/auto_tags.py:113`. M20 swaps `"auto_tags/system.jinja2"` for
`"summaries/short_long_system.jinja2"` — the auto-tagger would send the
summary-writing instructions to the model — and **every test stays green**.

Reproduction at the parent `9a6f2a2^`: the same mutation is killed by
`test_auto_tags_system_matches_golden[ja]`, `[en]` and `[auto]`, which this
commit deleted.

Why nothing catches it now:

- `test_render_returns_string` does assert `"tagging assistant"`, but it calls
  `render("auto_tags/system.jinja2", …)` directly. It holds the template file,
  not the builder's choice of template.
- all three `TestAutoTagsSystemPrompt` cases assert only on the language line,
  and the builder injects that line into whatever template it renders.

So no assertion anywhere reaches the body of the auto_tags system prompt
*through the builder*. Breaks R-0 #1 (a decision the builder makes is unheld)
and R-0 #5 (a branch the deleted goldens held has no successor).

One line inside `TestAutoTagsSystemPrompt` closes it without reintroducing a
golden: `assert "tagging assistant" in auto_tags._build_system_prompt()`.

### F4 `[introduced]` — the six retained goldens still fire on rewording outside the shared include

M29 rewords `You are a summary assistant for a file management system.` in
`short_long_system.jinja2` — a line that is **not** in `_common_rules.jinja2` —
and all three short/long goldens fail. Against R-0 #4.

The goldens are kept for one stated reason: `_common_rules.jinja2` is included
by two system prompts, so an edit there moves both without naming either. But
the assertion is `builder() == <whole file>`, which also covers the ~30 lines of
each template that are not shared. That is precisely the "you changed a prompt
and did not regenerate" failure the commit retires everywhere else.

What the goldens *do* buy uniquely, measured: M31 rewords a heading inside
`_common_rules.jinja2`; all six goldens fail and
`test_summaries_system_prompts_carry_the_shared_rules` **survives** (it renders
the include fresh, so both sides move together). So the two are not redundant —
the goldens catch the edit, the shared-rules test catches the removal. But
removal is already held three ways (M8a/M8b: goldens, the shared-rules test, and
two pre-existing `test_summaries.py::TestBuildSystemPrompt::test_proper_noun_rules_*`),
so only the edit case is theirs alone.

A golden over `render("summaries/_common_rules.jinja2")` on its own, asserted
`in` both prompts, keeps the unique catch and drops the collateral. The module
docstring's "rewording a template does not force a regeneration" would then be
true; as written it is not, for these two templates.

## The specific suspicions in the brief

**`test_omits_a_title_that_only_repeats_the_filename` (auto_tags) and its
`.replace("Filename: f.mp4", "")`** — it works. M1 kills it; it is not
vacuously true. Dropping the guard puts `Title: f.mp4` in the output, which
survives the replace. Worth noting only that its summaries twin, three classes
up, holds the same thing with the plain `assert "Title:" not in out`; the same
shape reads better here and needs no fixture-specific string.

**`assert "none" in out`** — `none` occurs nowhere else in the auto_tags *user*
prompt (`Filename: f.mp4 / Type: video / body text / Existing tags: none`); the
system prompt is a separate string the test never sees. M3 (drop the fallback)
and M32 (delete the whole `Existing tags:` line) both kill it. It holds.

**`TestVisionSystemPrompt`'s `'"ja"' in out`** — it holds that
`configured_language_requirement` quoted the BCP 47 tag into the prompt. See
F7: `test_output_language.py` already holds that, more precisely, for the same
inputs.

**`TestRagParameterisedSystemPrompts`'s `"4"`** — neither
`clue_generator_system.jinja2` nor `category_expander_system.jinja2` contains
any other digit, so there is nothing else for it to hit. The second value in
each pair (`9`, `12`) is what makes the assertion non-trivial, and M34 confirms
the kill. The gap is the caller, not the digit — F5.

**Do the six remaining goldens detect what the shared-rules test does not?** Yes,
partly — F4. Removal of the include is caught by both (and by two pre-existing
tests). An *edit* to the include is caught only by the goldens. A reword outside
the include is also caught by the goldens, which is the cost.
