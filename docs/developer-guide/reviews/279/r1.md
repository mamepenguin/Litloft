## Findings

### 1. Overlap and "beside" are measured on the x axis only; a non-fixed aside passes every case

- Severity: medium. Bucket A (a break of invariant 2 passes all tests). `[introduced]` (new file).
- `frontend/e2e-layout/sidebar-shell.spec.ts:43-60` — `first.left >= aside.right` / `first.left < aside.right`, `aside.left`, `aside.width`; nothing reads `top`/`bottom` or the aside's position.
- Reproduction: G1 (append `aside { position: sticky; }` to `src/app/globals.css`) → parity 4/4, spec 5/5 green. Probe on the rebuilt sheet: at 375 overlay-open the aside is {x 0–240, y 0–800} and `#first` is {x 0–375, y 800–826}: the boxes do not overlap, the sidebar pushes the page down a full viewport. Same at 1280 inline-open: the page sits *below* the sidebar, not beside it, yet `first.left (240) >= aside.right (240)` holds. F3 (dropping `fixed` from the fixture's class lists) is the same survivor on the spec side; on the `.tsx` side it is killed only by the parity class list, so any cause outside the class string (a base-layer rule, a utility override) goes through.
- Invariant: 2 ("the aside overlaps the content"), and 1 in spirit.
- Suggested shape: assert the vertical axis too (e.g. `first.top < aside.bottom` in overlay and inline, or `getComputedStyle(aside).position === "fixed"`), or a 2-D box intersection rather than a left-edge comparison.

### 2. Invariant list is missing: the open overlay sidebar sits above its scrim (answer to "is anything missing?")

- Severity: medium (user-reachable: with the scrim over the sidebar, every tap on a sidebar row lands on the scrim's `onClick={close}` and closes it instead). Bucket B against the declared list; raised as an R-0 revision candidate for the supervisor. `[introduced]` (the spec and fixture are new; the gap is in what they measure).
- `frontend/e2e-layout/sidebar-shell.spec.ts:52-60` — no stacking check.
- Reproduction: G2 (append `aside { z-index: 10; }` to `globals.css`) → parity 4/4, spec 5/5 green; probe at 375 overlay-open: `document.elementFromPoint(100,100)` is the scrim (baseline: the aside). F4 (fixture `z-40` → `z-10`) also survives the spec.
- Invariant: none declared. Proposed addition: "At 375px overlay-open, a point inside the aside hit-tests to the aside, and a point outside it hit-tests to the scrim."
- Other candidates considered and not raised: route-requested overlay at ≥1200px (content class carries no width-dependent utility, so nothing width-specific to measure); `MenuButton` z-50 above the sidebar (not part of this change).

### 3. "No scrim" in the parity test sees only the aside's immediate previous sibling

- Severity: low. Bucket A only in a contrived shape (lets a break of invariant 1 through at the class-parity layer). `[introduced]`.
- `frontend/src/components/__tests__/sidebarShellFixtureParity.test.tsx:88-90`, asserted null at `:100` and `:115`.
- Reproduction: M12 — render an extra `fixed inset-0 z-30 bg-black/50` div after the `<aside>` when inline-open → 4/4 green. The lookup returns null because the aside's previous sibling is absent, so `expect(s.scrim).toBeNull()` holds nothing about scrims elsewhere in the shell. An element inserted *between* scrim and aside (M11) does fail, loudly, via the overlay case.
- Invariant: 1 ("no scrim") and 5.
- Suggested shape: find scrims by what they are (`container.querySelectorAll("div[aria-hidden].fixed")` or similar) and assert the count (`toHaveLength(0)` / `toHaveLength(1)`), per detector rule 1.

### 4. The spec's boundary is read from the fixture it measures

- Severity: low. Bucket B. `[introduced]`.
- `frontend/e2e-layout/sidebar-shell.spec.ts:16-20`, `:62-65`.
- Reproduction: F7 — change `inlineMinWidth` to 1100 and the class to `min-[1100px]:pl-60` in the fixture → spec 5/5 green. Detector rule 5 ("never build the expected value out of the observation"). It is held today only because parity case 4 pins `inlineMinWidth` to `SIDEBAR_INLINE_MIN_WIDTH` and the class to `min-[inlineMinWidth]` (F7 killed there), so no invariant breaks; recorded so the pin in parity case 4 is not removed as redundant with `sidebarOverlayDismissal.test.tsx` (which already holds M13/M14/M16 on its own).
- Invariant: 3 (held via parity).
