## Findings

### 1. `.coverage` binary committed
- File: `.coverage` (repo root, new in `c5ee843`)
- Label: [introduced]
- Bucket: B (no invariant is broken, but it must not merge)
- Scenario: a 968 KB SQLite coverage database from a local pytest run goes into the addon history. Every clone pays for it. The next local test run modifies it, so `git status` in the addon is dirty after every run and the file gets re-committed by accident. Remove it from the commit and add `.coverage` to `.gitignore`.

### 2. Markers the model puts inside items get doubled
- File: `app/workers/summaries.py:151-157` (`_normalise_long`), rendered by `frontend/SummarySection.tsx:43-49`
- Label: [introduced]
- Bucket: B
- Scenario: the spec rejected a Markdown string because gemma "drifts between `-`, `・`, `1.`". The same habit can show up inside array items: `["- 価格は…", "・評価は…", "1. …"]`. `_normalise_long` stores `- - 価格は…\n- ・評価は…\n- 1. …` (reproduced), and `bulletItems` renders a list whose items visibly start with `- `, `・` or `1. `, as a double marker. No invariant is broken, because invariant 1 says "the stripped item". It is a likely model behaviour, so it should be checked in the R-5 run over the 11 videos. If it appears, strip one leading list marker per item.

### 3. An empty `- ` line in an edited summary renders an empty bullet
- File: `frontend/SummarySection.tsx:43-48`
- Label: [introduced]
- Bucket: B
- Scenario: the user edits the long summary in the textarea, starts a new line with `- `, and saves without typing text, or leaves a trailing `- `. `"- a\n- ".split` keeps `"- "`, because `"- ".trim()` is `"-"`, which is non-blank. It matches the prefix, so `bulletItems` returns `["a", ""]` (reproduced) and an empty `<li>` bullet dot is drawn. The worker cannot produce this, since it drops blank items. Only the edit path reaches it.

### 4. Nothing holds the array output format in the prompt
- File: `app/prompts/summaries/short_long_system.jinja2:8`; test `tests/test_summaries.py` `TestBuildSystemPrompt`
- Label: [introduced]
- Bucket: B (weak test)
- Scenario: reverting the output-format line to `"long": "paragraph summary"` (B16) leaves all 117 tests green. The worker accepts strings on purpose (invariant 3), so this regression is completely silent: every summary comes back as a paragraph and renders as one, and nothing fails. The `"3-5 items"` and `"40-80"` substrings the test does check are softer than the one line that decides the shape. A single assertion that the rendered prompt contains `"long": [` would kill B16.

### 5. Long rules pull against three type-specific common rules
- File: `app/prompts/summaries/short_long_system.jinja2:18-28` vs `app/prompts/summaries/_common_rules.jinja2` ("Informational", "Conversational", "Documentary")
- Label: [introduced]
- Bucket: B (prompt quality; the R-5 comparison is where it would show)
- Scenario:
  - **Informational.** The new rule says "events the source reports: state them plainly, with no attribution". The common rules for news say "When there are multiple sources, distinguish the origin of each piece of information" and "Distinguish confirmed information from unconfirmed ("reported that ...")". For a news roundup the model gets opposite instructions. The common rule's own example `reported that ...` is also an agentless form that the new passive ban forbids.
  - **Conversational.** The common rule says "Always identify whose statement it is". The long rule says facts are stated plainly. In an interview, a factual claim made by one speaker will lose its speaker.
  - **Documentary.** The common rule says "Follow the chapter structure of the source". The long rule exempts only "procedures and narratives" from most-important-first, so reports, theses and contracts are told to reorder.

  The spec says the long rule "defers to" the common ordering rules, but the text as written only defers for two of the types. The cheapest fix is to make the long rule defer to the type-specific notes in general: "where the type-specific notes below require source order or attribution, they take precedence".
