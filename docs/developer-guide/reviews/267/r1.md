## Findings

### F1 [introduced] A — the tie-break by addon name is not held by a test (M04 live)

Invariant 2: "ties by addon name". In `SidebarAddonNav.test.tsx` the only tie is `beta` ("Beta source") vs `media_import` ("YouTube & Feeds") at sources/10; name order and label order agree, so sorting ties by `navigation.label` renders the same column. A fixture where they disagree (e.g. `alpha` labelled "Zulu", `beta` labelled "Alpha", same placement and priority) makes M04 change the rendered order. Test gap letting an invariant-2 violation through.

### F2 [introduced] A — "no top-level `href`" and "drive-scoped with no current drive" are not held by tests (M05, M06 live)

Invariant 3. The "no href" case checks `rowFor("knowledge")`, which only looks for `${ENCODED}/addons/knowledge`, and `navText()` not containing "Knowledge" while the fixture label is "Notes". Under M05 a row "Notes" linking to `/addons/knowledge` is drawn and both assertions still pass. No test renders the sidebar with `useCurrentDrive() === null` and a drive-scoped navigation addon, so M06 is invisible too. Fixtures: assert no anchor whose `href` ends in `/addons/knowledge` and no "Notes" text; add a no-drive render with a drive-scoped navigation addon expecting no row.

### F3 [introduced] A — lighting on the decoded spelling is held only for a page under the addon (M13, M14 live)

Invariant 8. `isAddonNavRowActive` handles the decoded pathname for both the own route and the prefix boundary, but tests use decoded only for `/drive/{decoded}/addons/knowledge/some-note`. Fixtures: `pathname = /drive/${DRIVE}/addons/knowledge` expecting `lit()` = `["Notes"]` (kills M14); `pathname = /drive/${DRIVE}/addons/knowledgebase` expecting no lit row (kills M13). The existing encoded `knowledgebase` test asserts `not.toContain("Notes")` rather than the declared lit set (S2-4 asks for the full expected set).

### F4 [introduced] A — overlay-only dismissal is held for sources/primary rows, not utility rows (M27 live)

Invariant 10. The dismissal test clicks `media_import` (sources). Utility rows are wired separately in `Sidebar.tsx`; passing the raw `close` there closes an inline sidebar on press and no test fails. Fixture: click the `zeta` (utility) row inline and expect `mockClose` not called.

### F5 [introduced] B — only one known icon token is asserted (M18, M19, M20 live)

Invariant 6 (fallback) holds (M17 killed). But dropping `rss`, `notebook-pen` or `download` from `ADDON_NAV_ICONS` draws `Package` for the addon that declares it (knowledge's P2-4 manifest declares `notebook-pen`) with all tests green. The icon `it.each` could list every token with its declared lucide class.

### F6 [introduced] B — addon rows on a page with no current drive are untested (M26 live)

Primary rows render outside the `driveBase &&` block, so off-drive a global/both-scope primary addon draws right after Home (probe in F10: rows `Litloft, <drive switcher>, Home, Glob`). Moving them inside the block keeps every test green; same for the Sources heading and utility rows off-drive. No bundled navigation addon is global-scope today (intelligence, knowledge: `scope: drive`), so no user reaches it now.

### F7 [introduced] B — the name-neutral detector reads string literals only, so an identifier naming a bundled addon passes (M29 live)

`codeStrings` collects string literals, template pieces and JSX text. `addons.knowledge` / `addons.media_import` (valid identifiers) is a host branching on a bundled addon and is not seen. Including `ts.isIdentifier(node)` text would cover it without matching comments (M31 confirms comments are ignored, as intended). The regex is also case-sensitive (a `"Knowledge"` literal is not a hit). The `toBe(7)` host count is declared — fine.

### F8 [pre-existing] B — `sidebar-sections` slot position has no test (M28 live)

Invariant 10, second sentence. Deleting the slot keeps every test green; at `3bc36dab` the string also appears only in `SidebarLibrarySection.tsx` (`git grep -l sidebar-sections 3bc36dab -- frontend/src`), and every sidebar test mocks `AddonSlot` to `null`. The diff does not move the slot. Ledger only.

### F9 [introduced] B — switching to a drive whose catalogue is already cached hides its addon rows for one commit

`getAddonsStatus` returns an already-resolved promise for a cached drive, but `.then` still runs after the effect, so for one commit `catalogueDrive` (A) differs from `currentDrive` (B) and `navAddons` is `{}`. With the same addons on both drives the parent kept rows through that commit; this SHA removes primary rows and restores them, shifting the Views block once. Reasoned from effect/microtask order, not measured in a browser. Invariant 11 (no stale rows) holds; this is the opposite direction.

### F10 [pre-existing claim contradicted] B — a global-scope addon row off-drive does light

The brief/PR body says a global-scope row does not light when no drive is current because `isSidebarLinkActive` requires a drive. Addon rows do not use that path: `AddonNavRows` passes `isAddonNavRowActive(pathname, href)` explicitly, which needs no drive. Probe (temporary copy of `SidebarAddonNav.test.tsx` with `useCurrentDrive: () => null`, catalogue `g: {scope: "global", href: "/addons/g", navigation: primary}`, pathname `/addons/g/deep`, deleted afterwards): `LIT ["Glob"]`. So the stated known issue does not exist at this SHA for `global`/`both`-scope rows on `/addons/{name}` (where `CurrentDriveProvider` yields `null`). Remedy: delete the claim from the PR body; do not add drive-less lighting code for it.
