## Findings

### F1 [introduced] medium (unverified in a real browser) — "/" during IME composition enters browse mid-composition
- Invariant: none on the list directly; spec §1 "The '/' is not inserted".
- Reproduction (jsdom, temporary test, deleted): `compositionStart` then `change` to "/" → chip "Drive root",
  value `""`. `onChange` does not look at composition state, so with an IME that holds a half-width "/"
  as marked text, React resets the controlled value to "" while the IME is still composing.
- Observation: what Chrome/Safari then do (commit the marked "/" into the now-browsing input → filter "/"
  → "Nothing here matches"; or duplicate text) cannot be observed in jsdom. The spec decision chose
  `onChange` precisely for kana IMEs, so this needs an R-5 check with the macOS Japanese IME (half-width
  symbol setting) in Chrome and Safari. If it misbehaves, the obvious shape is to decide on
  `compositionend`/non-composing change only.

### F2 [introduced] low, B — the › button leaves focus on `<body>`
- Invariant: none.
- Reproduction (jsdom, temporary test): focus the "Browse trips" button, click → chip "trips",
  `document.activeElement` is BODY (the pressed row unmounts). The chip's ‹ and × call `focusInput()`;
  `onEnterFolder` from a row does not.
- Observation: on an iPad with a keyboard (coarse pointer shows ›) the arrow keys/Enter no longer reach
  the input after tapping ›; on a phone the soft keyboard closes. Escape still closes (editingOnly:false).
  Possibly deliberate on phones; asymmetric with the chip's buttons.

### F3 [introduced] test gap on invariant 7 — the history assertion cannot fail
- Surviving mutations: G13 (`openBrowseRow` routed through `handleSelect`, which records history) and
  G18 (`return` after `handleBrowseKey` removed, so Enter also falls into `handleSubmit(query)`).
- Every Enter test presses Enter with an empty query, and `addToHistory` ignores an empty term, so
  `localStorage.getItem("search-history:main")` is null under both mutations. With a filter typed
  (e.g. "read" + Enter, measured on the real code: push `/drive/main`, history null, no file request)
  the mutations would record "read". Code is correct; the test declared for inv 7 is vacuous.

### F4 [introduced] test gap on invariant 2 — neither "other level" nor "other drive" is held
- Surviving mutations: H17 (drop `loaded.path === current.path` from `arrived`), H18 (drop
  `loaded.drive === current.drive`), H15 (drop the `[drive]` reset effect).
- H17: while a child level loads, the parent's rows would render under the child's chip; the
  "never shows a level it has already left" test only asserts after returning to the parent.
  H18: browse root on drive A, switch drive, "/" on drive B → A's rows would show until B answers
  (drive boundary). H15: switching back to the first drive would resume browse at the old path.
- Code is correct at `2365027f6`; these are the invariant's only guards and nothing fails when one goes.

### F5 [introduced] test gap on invariant 8 — "filter before cap" not held

## Drive boundary (Q3)

No path found that points into or reveals another or a locked drive. The fetch drive is the level's
drive and the level only counts while it equals the current drive; `loaded` is shown only when both
drive and path match; pins and the folder index come from `useDriveOwned` (drive-keyed); collections
and smart folders carry no `folderPath`; the backend `folder-tree` validates the drive against unlocked
groups (locked → 404 → rendered as an empty folder, nothing revealed). File rows open `/files/{id}`,
which is access-checked server-side. The guards themselves are untested (F4).
