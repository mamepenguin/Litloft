## Findings

### F1 — [introduced] invariant 2 — low/medium
Nothing checks any more that the viewer is `position: fixed`, i.e. that it covers the viewport rather than a box. The commit deletes `expect(viewer).toMatch(/fixed inset-0/)` from `archiveJustifiedCells.test.tsx` along with the no-`createPortal` assertion, and the new e2e spec can't tell `fixed` from `absolute`. The fixture scrolls an inner `h-dvh overflow-auto` div, so body-level `absolute inset-0` still lands on the first viewport.
Reproduction: M14 (`fixed inset-0` -> `absolute inset-0` in `ArchiveImageViewer.tsx`).
- At 8ebe48a2: every unit and component test passes.
- At a33d7364 (viewer + both archive test files checked out from the parent, same mutation): `the canvas viewer's floor > keeps the unportalled fixed overlays that the containment would have caught` fails.

User-visible when it matters: on any layout where the document itself has scrolled before the viewer opens, a body-level `absolute` viewer sits at the document top, above the screen.
Suggestion: don't restore the source-text match (detector rule 4). Add a case to `immersive-viewer-layer.spec.ts` that scrolls the fixture's document (or a scroller that is the window) and asserts that the dialog's bounding box equals the viewport.

### F2 — [pre-existing] no declared invariant (DESIGN.md Layering: "The resting strip owns the bottom edge… Anything anchoring to the bottom goes above it") — medium
The same defect class, still unportalled inside the player box. `ArchivePreview` renders `ArchiveToolbar` inside `FilePreview`, which is inside `.media-detail-player`, where `[data-sheet-snap]` makes it sticky at z-index 10. Below 640px the toolbar's "More" menu and `ViewMenu` use `useMenuSurface`, whose `MENU_SURFACE_BASE` is `fixed inset-x-2 bottom-4 z-40`: a bottom sheet in the "Floating surfaces" tier. Its z-40 ranks inside the sticky z-10 context, so the page's resting strip (`MobileInspectorSheet` peek, `fixed bottom-0 z-40`, 56px) paints over the menu's bottom ~40px. The strip is still hit-testable there, because nothing is inert while a menu is open.
Reproduction: M5. A box with the menu's positioning classes, placed in the new fixture's player box: strip at y=671..727, box at y=551..711, and a pixel at (40, strip.y+10) is 255,255,255, the strip's colour, not the box's black.
Not touched by 8ebe48a2. `archiveJustifiedCells.test.tsx` still pins `DismissScrim` as deliberately unportalled for the canvas-floor containment reason, so any fix has to weigh that.
Other unportalled `fixed` scrims inside FilePreview descendants (`EditableTagChips` z-30, `ContextMenu` scrim) have the same shape. I did not measure them.

### F3 — [introduced] none (bucket B) — low
