## Findings

### F1 [introduced] low — getWatchHistory is now requested before the Go to / Folders fetches on open

- Invariant: arguably 2 ("timing"); count, arguments and tick are unchanged, only the order inside one passive-effect flush moved. Nothing a user can see. Bucket B candidate.
- Reproduction: temporary probe test (since deleted) that logs every `lib/api`, `lib/semanticSearch`, `lib/searchCache` call, every `scrollIntoView`, every React commit (`<Profiler>`), and a hash of `document.body.innerHTML` plus the `[data-search-item]` rows after each step. Run once at `227f8b02b` and once with `GlobalSearch.tsx` checked out from `05df6a566` (the new hook files are then unused), and diffed.
- Observation: at `05df6a566` the open sequence is `getPins, getCollections, getSmartFolders, getDriveSummary, getAuthStatus, getFolderTree, getWatchHistory`; at `227f8b02b` it is `getWatchHistory, getPins, ...`. The same move happens on a drive change while open and on reopen. Cause: `useRecentAndHistory` (and its effect) is now called before `useLauncherRows` -> `useJumpDestinations` / `useJumpFolders`, whereas the old recent-files effect was declared after them. All requests still leave in the same flush, so there is no latency or UI difference, and no existing test depends on the order.

### Probe result: no other observable difference (not a finding)

Three scripted sequences, identical traces old vs new except F1's line moves (every commit, every DOM hash, every scroll, cache read/write, getDriveFiles / semantic call):
- S1: open with history, arrow onto a term, late recent reply lands, arrow again, drive changes while open, stale reply for the old drive resolves, new drive's reply, arrow + Enter (record on the new drive).
- S2: cached hit for a new query renders before debounce, arrow to the "View all" tail, debounce fires, filename stage reorders rows, arrow, late semantic stage reorders again (tail highlight follows), second cached query, retype mid-debounce, an old stage resolving after abort, empty filename reply, semantic reply, arrow + Enter.
- S3: stages in flight at close, late filename reply after close, reopen, recent reply, both stages reject (with and without cache), clear, submit with Enter (record), reopen, remove a history term (forget).

Why the effect move cannot interleave: every state write the moved effects make (cache-hit `setMerged`/`setTotal`, the guard-path clear, `setRecentData`, `setHistoryData`) is a batched update inside the passive-effect flush, so it is rendered only after every effect in the commit has run; and none of the moved effects reads or writes `highlightedRef`, which is the only shared mutable the highlight effects consult. Cleanups for the whole component still all run before any mount effect in the same commit.
