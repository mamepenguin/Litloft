## 4. New findings

### R3-1 [introduced] inv 5 (dev only): under React StrictMode, an in-place move now fires `recordFileView` twice for the next file
- **Where:** `FileDetailContent.tsx`. The key now remounts the container, and with it the hook's open effect, on every change of file.
- **Measured** (`<StrictMode>`; the parent run uses the same repro):
  - f1 → f2: `views f2=2` at the SHA, `views f2=1` at `c9b31c6a`.
  - A→B→A: `views f1=3` at the SHA, `2` at the parent.
  - `GET` stays at 1 in both, because the request is shared.
- **Why:** StrictMode double-invokes effects on a newly mounted fiber, and it does not on an update. At the parent, the container survived and its `[fileId]` effect re-ran as an update. Now it is a new mount.
- **Reach:**
  - Development only. Next's App Router enables StrictMode by default and `next.config.ts` does not turn it off. Production builds do not double-invoke.
  - `recordFileView` is a view-only POST that only refreshes `last_played_at`.
  - No user-visible effect in production.
- **Test gap:** no test exercises StrictMode. Recorded so that nobody reads a doubled POST in the dev network panel as a regression of inv 5. Suggested bucket: B.

### R3-2 [introduced] inv none (layout, unmeasured in a browser): the next file's first render has no `--rail-avail` / `--player-avail`
- **Where:** `useCompanionMetrics` state now lives in a mount keyed per file. `railAvailable` and `playerAvailable` start `null` and are measured only in a passive effect.
- **Measured** (jsdom; the presenter stub logs `metrics.railAvailable` per render after f1 → f2):
  - SHA: `f2:null f2:768`
  - `c9b31c6a`: `f2:768 f2:768`, where the previous file's measurement carries into the first render
- **Consequence:**
  - With `null`, `mediaHostStyle` omits the custom properties, so the first commit of the next file sizes the player and companion from the CSS fallback `100dvh` (`globals.css`: `--rail-avail, 100dvh` / `--player-avail, 100dvh`) instead of the pane's measured height.
  - In the right pane, or anywhere the scroll root is shorter than the viewport, the player box can be drawn larger for a frame and then shrink.
  - This bears on inv 1's spirit (the player box drawn at once) for in-place navigation: next/prev, and the collection's next track.
  - A first open from a list already had this since `b1dcf95d`. That is round-1 scope.
- **Not verified:**
  - Whether that frame is painted depends on when passive effects flush. A `router.replace` / `selectFile` transition is not a discrete event, so it may paint first.
  - Per review-workflow ("Layout … need a named instruction to measure in a real browser"), this needs a browser measurement before triage. jsdom shows only that the state resets.

## 6. Trajectory

Reading the fix diffs in order:
- **`c9b31c6a` added:**
  - states: `failed`, the entry's `id`
  - branches: the id guard in `setFile`, the not-found branch, the seed skip, the fullscreen catch
  - a prediction: "an entry whose id is not the current file is the seed of the current file"
  - a key on the presenter
- **`a0064c92` removes more than it adds:**
  - Removed from the hook:
    - the entry `id` state and `seededEntry`
    - the id guard branch and the `stored.id === fileId` prediction
    - seven reset calls
    - both `cancelled` branches
  - Removed from the container:
    - the `[fileId]` capture reset effect
    - the key on the presenter
  - Added:
    - one wrapper component that carries the key
    - three tests and a harness hook
  - Kept from round 2: `failed` (now a plain state) and the not-found branch. Neither was re-added in a new form.

**Plainly: this round removes branches, a state and a prediction. It does not add one that the round before also added. The loop is converging.**

- The two findings above are consequences of the remount itself: a StrictMode double effect, and metrics state reset per mount. Neither is a new case being patched in.
- A fix for R3-2 that added "carry the last measurement across mounts" state would be the patching shape again. Measure in a browser before deciding it needs a fix at all.
- The same move makes one more branch removable: `useSlotAvailability`'s `reportedFor` reset (SA, live).
