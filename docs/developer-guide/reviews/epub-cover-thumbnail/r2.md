#### Note on N12 / N13 / N18 / N20 (guard-to-crash mutants, survived)

With `except Exception` around `read_cover_bytes`, turning a guard that returns `None` into a crash has no observable effect: there is still no thumbnail, nothing escapes, and the bytes are untouched. So these are equivalent mutants with respect to invariant 1:

- N12: drop the `opf_path not in entries` guard (the read then raises `KeyError`).
- N13: make an absent container raise.
- N18: make `_resolve`'s escape check raise instead of returning `None`.
- N20: drop the `cover_path not in entries` guard (`KeyError`).

N20 is round-1 M18, which was **killed** at `bdff51c1f` only because the `KeyError` escaped the old tuple; the broad catch turned it into an equivalent mutant. The `opf_named_but_absent` and `container_absent` fixtures reach their guards, but they can no longer tell a guard from a crash. That follows from the design. The test names claim only "yields no thumbnail and leaves the file alone", so this is not a finding.

A mutation that removes a guard *and lets the read go on to something it should not read* is still caught. N19 (drop the resolved-escape check) is killed by `dotdot_href`, `encoded_dotdot_href`, `escaping_opf_path` and the scan test, and N21 (no percent-decode) is killed.

## Q2. What did the fix break?

Full backend suite at `68f0c370c`: 3499 passed, 44 skipped, 1 failed. The failure is the known environment one (`test_safe_image_fetch.py::...[https://0177.0.0.1/a.jpg]`).

**The broad `except Exception`:**

- **Scope.** It wraps only `read_cover_bytes(epub_path)`. The Pillow block after it was already `except Exception` at `bdff51c1f`, like the PDF generator. So the fix makes the generator uniformly broad and widens nothing else. `BaseException`s (`KeyboardInterrupt`, `SystemExit`, `asyncio.CancelledError`) still propagate. `MemoryError` is caught, which is the desired outcome for a hostile book.
- **Programming errors are still visible.**
  - N16: a `NameError` on every call to `read_cover_bytes` is swallowed as a warning, but it is killed by all the positive `TestCoverDiscovery` cases and by the scan test's `good.epub` assertion.
  - N17: a `NameError` only on the EPUB2 `meta name="cover"` branch is killed by `test_epub2_meta_cover`.
  - A bug is hidden only if it crashes *solely* on an input that should yield no thumbnail anyway. That is the N12/N13/N18/N20 class above, and invariant 1 permits that outcome.
  - At `bdff51c1f` no test used `pytest.raises` or `caplog` against the generator, so no test depended on seeing an exception come out.
- **Atomic-write contract.** `write_thumbnail_atomically` turns a `False` return into `AbandonWrite`, and the generator writes nothing before the read. Probe `scratchpad/epubr2/atomic.py` runs all 24 hostile books through `write_thumbnail_atomically` against a pre-existing destination holding `OLD`. Every one returns `False`, the destination still holds `OLD`, and no temporary file is left in the directory. N15 (a read failure returns `True`) is killed by 20+ tests.
- **ffmpeg.** No new path. `run.assert_not_called()` still guards every hostile case, including the seven new ones.

**The new tests hold what their names say.** The reachability table in Q1 shows each hostile fixture reaching its named path. The mutation table shows the bomb test, the container-cap tests, the scan test and the PUT test each killed by the mutation they exist for.

## Q3. Trajectory

There is one fix diff (`68f0c370c`). In `thumbnail.py` it **removes** a prediction: the round-1 tuple `(EpubCoverError, zipfile.BadZipFile, OSError, RuntimeError, ValueError)`, which predicted which types a damaged archive raises. The fix replaces it with `except Exception` and drops the two imports the tuple needed. It adds no branch and no state, and `epub_cover.py` is untouched. Everything else in the commit is test fixtures and tests, plus one prose paragraph in `known-issues.md`.

So this round does not add a branch, a state or a prediction that the round before also added. It deletes the one prediction round 1 got wrong (F1 was that prediction failing). The loop is converging, and the design is not being patched.

The side effect is that four `None`-returning guards (N12, N13, N18, N20) no longer change any observable outcome. They are now defence-in-depth that no test can hold. That is the price of removing the prediction, not a new special case.
