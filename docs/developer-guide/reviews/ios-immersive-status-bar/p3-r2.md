## Trajectory

Rounds in this phase: `b17a600ea` (feature) → `b860cadb6` (fix). The fix adds one guard (a new early return in `.catch` reading `mountedRef` and `phaseRef`) and removes one (`"opening"` in `enter`). It adds no state and no phase. Net branch count is unchanged; the check moved from where the press is read to where the hold is taken, which is the place round 1 said the race lived. That is not a design being patched: it is one round, and it moved a guard rather than adding a new case. But the moved guard now also does work other guards did (N4 and N8 are live), so two older guards are now partly redundant, and one guard reads `mountedRef`, which was not built to be read from an async path (finding 1). If round 3's fix adds another condition to this same `.catch` line, that would be two rounds adding to it and should be read as patching.

## Question 3: every path during "opening" without the `enter` check

- Second press / swipe up / pinch out: `isFullscreenRef` is false during "opening" (`isFullscreen` counts only `"on"`), so `enter` runs and calls `requestNativeFullscreen` again. On an iPhone it rejects in microtasks and the `.catch` guard returns. Safe, but a second element-fullscreen request is now made (finding 3).
- Rotation to landscape: same path; `entryReasonRef` stays `"manual"` only because the guard sits above the assignment, and no test holds that order (finding 2, P1).
- Rotation back to portrait: `leave(false)` → `settleOff` only if the entry was a rotation; a manual entry is kept (P1).
- Swipe down / pinch in: `exit()` → `leave` → `settleOff`; no marker, hold released (P5).
- Escape: the shortcut is enabled only on `pseudoOpen`, so nothing happens (P7).
- `closing` turnaround: unchanged; a stale refusal arriving during "closing" is stopped by the guard. A refusal that arrives after the session has settled back to "off" is not (finding 5).
- `isFullscreenRef`: now redundant on the pseudo path; its remaining job is element fullscreen, untested (finding 4).

## Findings

### 1 — Under React StrictMode, pseudo-fullscreen never opens on a touch device
- **Label:** [introduced]
- **Invariant:** none of this change's R-0 as worded (it only bites in development). In a dev server it removes the whole feature: #379 item 1 never gets an entry to settle, and nothing in invariant 2/5/6 can happen.
- **Evidence:** `useFullscreen.ts:150-156` sets `mountedRef.current = false` in an effect cleanup and never sets it back to `true` in the effect body. StrictMode (on by default for the App Router: `next/dist/build/define-env.js`, `__NEXT_STRICT_MODE_APP`, "enabled by default" when `reactStrictMode` is unset, and `next.config.ts` does not set it) runs mount → cleanup → mount in development, so `mountedRef.current` is `false` for the component's whole life. The new guard at `:248` (`if (!mountedRef.current || …) return;`) then returns on every refusal.
- **Reproduction:** P2 / P2b. With `renderHook(..., { wrapper: ShortcutsProvider, reactStrictMode: true })`, a press in a v4 shell posts nothing and never opens; in a plain browser with a coarse pointer the press also does nothing. Both pass at `b17a600ea` and P2b passes at `develop`.
- **Reachability:** `pnpm dev` (and anything else running a development build) on an iPhone, an Android phone, or the shell pointed at a dev server: the fullscreen button, swipe up and pinch out all do nothing. Production builds do not double-invoke effects, so the Docker image is not affected.
- **Note:** the history effect's `if (!mountedRef.current) return;` (`:484`) already had the same dev-only flaw before this fix ([pre-existing]): under StrictMode an exit does not unwind the history entry.
- **Direction:** set `mountedRef.current = true` in the effect body (the pattern `useInlineRename.ts:94` uses), or track unmount in a way StrictMode's re-run restores. Add P2 as a test.

### 2 — Nothing holds that a rotation during a manual "opening" keeps the session manual
- **Label:** [introduced] (test gap; before the fix, the `enter` check returned before `requestNativeFullscreen`, so `entryReasonRef` could not be touched; now it depends on the guard sitting above the assignment)
- **Invariant:** none declared. The behaviour is the one `enter`'s own comment and the test "keeps a manually opened fullscreen when rotated to portrait" defend: someone who pressed the button is not ejected on sitting up.
- **Evidence:** N5 (guard below `entryReasonRef.current = reason`) is live. Under N5, press → "opening" → rotate to landscape relabels the session `"rotate"`, and sitting back up after the widening exits it.
- **Reproduction:** P1 passes at the SHA and fails under N5.
- **Reachability:** iPhone shell, video playing (`autoRotateEnabled`), press fullscreen and turn the phone within the wait (up to 1000 ms). Realistic.
- **Direction:** add P1's shape as a test.

### 3 — A second press during "opening" now makes a second element-fullscreen request
- **Label:** [introduced]
- **Invariant:** 2 only in theory ("element fullscreen never makes it immersive"); none on an iPhone.
- **Evidence:** with the `enter` check gone, `isFullscreenRef` is false during "opening", so `enter` reaches `requestNativeFullscreen(frame)` again (P4: called twice). Where that second request *succeeds*, `.then` sets `entryReasonRef` and element fullscreen opens while the first press's hold is still waiting; the rAF then pins the pseudo frame inside it, with a hold taken.
- **Reachability:** the iPhone WKWebView has no `Element.requestFullscreen` (round 1 F1), so every call rejects and nothing is observable. Needs an engine where a first request is refused and a second, moments later, is granted. No device known.
- **Direction:** for the supervisor: either accept (N4 shows the removed check is otherwise redundant), or restore the `"opening"` return in `enter` alongside the `.catch` guard.

### 5 — A refusal that lands after the session has closed reopens it
- **Label:** [pre-existing] for this fix (P3 fails identically at `b17a600ea`; the hold it takes was introduced in `b17a600ea`)
- **Invariant:** 2 and 6 (an unasked session opens and holds immersive)
- **Evidence:** the guard is `phaseRef.current !== "off"`. A refusal still in flight while another press opened, and then closed, a session finds the phase back at "off" and takes a hold and opens.
- **Reproduction:** P3.
- **Reachability:** needs asynchronous rejection with two presses whose rejections settle out of order; not reachable on an iPhone shell (same premise as round 1 F1).
- **Direction:** ledger. If ever addressed, compare against a per-entry token rather than the phase.
