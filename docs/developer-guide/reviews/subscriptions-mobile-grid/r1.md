The bug reproduces at the parent at every phone width and is gone at f9ba8aa. Below `sm` the parent has no explicit template, so the single implicit `auto` track sizes to the `<li>`'s min-content contribution. That contribution includes the whole nowrap title: `min-w-0` on the text column lowers its used minimum but not its intrinsic contribution. `grid-cols-1` = `minmax(0, 1fr)` caps the track at the container. At `sm` and up the parent already used `minmax(0, 1fr)` tracks, which is why 640 and 1280 were fine before the change.

## Findings

### F1 [introduced]: nothing guards the fix; removing `grid-cols-1` passes every committed test

- Evidence: M1-suite above. With `grid-cols-1` removed (the parent's markup), the addon's `SubscriptionsDashboard.test.tsx` and `Page.test.tsx` pass 15/15, and no spec under `frontend/e2e-layout/` renders this dashboard (`grep -rn "SubscriptionsDashboard\|media_import" frontend/e2e*` returns nothing). The same holds for M3, M7, M8 and M10, which each break an R-0 invariant.
- Label: `[introduced]` because the omission belongs to this change: it fixes a reported layout bug and ships no detector for it. At the parent there was no fix to guard, so the parent-vs-f9ba8aa reproduction does not apply. The fix commit adds no test file (`git show --stat f9ba8aa`: 1 file, the component).
- Why it matters: jsdom cannot hold this (review-workflow "What a test here cannot hold"). The only guard would be a real-browser layout check. The fixture used for this review already does that, but it lives in a scratchpad and nothing in CI runs it.
- Suggested bucket: A under "a test that lets an A through is an A", if the supervisor treats R-0 invariant 1 as needing a standing detector. B if a one-class fix is accepted as verified by this review's measurement alone. Supervisor's call. If a detector is added: measure `scrollWidth === clientWidth` and title truncation at 320 in a real browser (M1, M3, M7 and M8 are the mutations it should kill), and assert column counts with `toBe(N)`.

- **The detail panel opened from a long-titled card.** It renders inside this dashboard and is the next thing a phone user sees. Measured and holds at 320 and 393 (ja and ascii). Worth adding as: "with the detail panel open for the long-titled subscription at 320 px, `scrollWidth === clientWidth`."

- **The summary header with every segment present** (attention + paused + syncing all > 0). M11 survived only because the fixture shows three segments. Invariant 4 as written can pass on data that never exercises the wrap. Consider stating the summary with all five segments.
- Nothing else found. Invariant 3 already catches the width-independent breakages (M3 and M8 overflow at 640 too).
