## Findings

### F1 — a drive change shows the previous drive's count until the new one arrives
`[pre-existing]` · R-0 #3 · `addons/intelligence/frontend/AskFindHeader.tsx:20-40` · severity: low

`useDriveFileCount` does not reset `count` when `drive` changes, so between the change and the new response the scope line pairs the new drive's name with the old drive's `file_count`.

Reproduction (temporary probe test, removed): render with `drive="family"` (getDrives resolves 619), rerender with `drive="work"` while the second `getDrives` is pending.
- `124cd55`: `"work · 619 items"`, then `"work · 3 items"`.
- `dbdcbcf` (`DriveScopeLine`): `"619 files in work"`, then `"3 files in work"`.

Reachability not measured: the page is keyed under `/drive/[name]/`, and a change of that segment probably remounts the page, which would make this unreachable from the sidebar. The slow-answer test covers the opposite ordering (old response late), not this one (new response late).

### F2 — the Ask page's count assertion no longer waits for the count
`[introduced]` · R-0 #3 (detector) · `addons/intelligence/frontend/Page.test.tsx:864-871`, `addons/intelligence/frontend/pages/find.test.tsx:171-176, 427-431` · severity: low

The scope line now renders immediately with the drive name alone, so `await screen.findByTestId("drive-scope")` resolves before `getDrives` has answered; `toContain("619")` then passes only if the mocked promise happened to land first.

- P11 (50 ms delay after `getDrives`, correct behaviour) fails "says which drive it will read, and how many files" at `124cd55`; the same delay in `DriveScopeLine` at `dbdcbcf` leaves it green, because there the element did not exist until the count did.
- Observed once without touching `Page.tsx` or `AskFindHeader.tsx` (during P9), so it is also a load flake.
- In `find.test.tsx`, `renderSettled` and "says which drive and how many files" wait on the same element, so they no longer settle the fetch, and the latter passes when the count never arrives. `not.toContain("3 files")` in Page.test is vacuous now that the line never says "files" (the `toContain("619")` beside it still holds the other-drive case).
- `find.test.tsx:421-425` states that waiting for the scope line makes the assertions run against the finished screen; that is no longer true and invites the next test to rely on it. Delete.
