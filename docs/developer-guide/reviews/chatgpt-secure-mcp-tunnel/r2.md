## Findings

### F1 — [introduced] Ask's disclosure assertion accepts the opposite privacy claim — A

Severity: medium. Invariant 3 requires the advertised Ask description to
disclose that retrieved file excerpts may leave Litloft for its configured LLM
provider.

`mcp-server/src/__tests__/toolMetadata.test.ts:114-117` checks only that the
description contains the disconnected substrings `file excerpts` and
`LLM provider configured in Litloft`. M6 changed the shipped description to
say that retrieved file excerpts “are never sent to” that provider; all three
metadata tests passed. A client would therefore receive a false assurance at
the exact privacy boundary the invariant is intended to hold.

This is [introduced] because the disclosure assertion is new in fix commit
`a3e4b7b`; its parent has no corresponding assertion. Per
`review-workflow.md` R-4, a test that lets a declared invariant break is an A
finding.

Remedy shape: assert the transfer relationship, not just the two entities. For
example, require a stable phrase such as `file excerpts may be sent to the LLM
provider configured in Litloft`, while still reading it from the real
`tools/list` result.
