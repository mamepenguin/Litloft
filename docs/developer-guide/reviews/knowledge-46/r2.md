## Trajectory

### A-1（ClipSection を常時マウント）: 分岐は消えた。代わりに「隠れたままマウントされている」状態が 1 つ増えた

- **消えたもの**: `{clipFirst && <ClipSection />}` / `{!clipFirst && <ClipSection />}` という 2 箇所の条件付きマウントと、results 状態で ClipSection を描画しない分岐。今は `clip` 要素が 1 つだけあり、どの状態でも描画される。「条件付きマウントがなくなった」という主張はコード上正しい。
- **残ったもの（置き換え）**: clipFirst の位置の選択（`clipFirst ? [clip, ...notes] : [...notes, clip]`）と、results / landing の分岐。数は変わっていない。
- **増えたもの**: `hidden={inResults}` が作る新しい状態「results ページで、表示されないまま ClipSection がマウントされている」。この修正はこの状態への対処コードを追加していない（追加すべきでもない）。ただ、ClipSection の子の状態（BookmarkletDialog が開いている、paste フォームが開いている、重複プロンプトが開いている、ショートカットの文脈が登録されている）が、この状態のまま results ページに持ち越される。これが R1。対処を足すと、それは「もう 1 ケース分の処理」になる。
- 結論: A-1 は分岐を消した修正で、パッチの積み増しではない。ただし新しい状態を 1 つ持ち込んでいて、次のラウンドでその状態のケース処理（開いているダイアログを閉じる、Escape の文脈を外す等）を足すと、それは積み増しの形になる。

### A-2（NoteResults）: 大部分は置き換え。分岐が 1 つ純増し、prediction が 1 つテストなしで残った

- **消えたもの**: `pages` を deps に持つ effect、クロージャの `cancelled` と、それを見る 2 つのガード、ボタン条件の `&& !failed`。
- **置き換え**: `pages`（effect を動かす状態）→ `nextPage`（次に要求するページ）。effect の再実行 → マウント時とクリック時に呼ぶ `loadNext`。
- **増えたもの**:
  - 状態 `loading` と `disabled={loading}`。消えた `cancelled` と数の上では入れ替わり。
  - 分岐 `more = total === null ? failed : files.length < total` の `total === null ? failed` の側（1 ページ目が失敗したときに再試行を出す）。これは F2 の「再試行手段がない」への直接の答えで、「想定外のもう 1 ケース」ではない。ただし分岐としては純増。
- **残った prediction**: `nextPage === 1 ? res.data : [...prev, ...res.data]`（1 ページ目は置き換える）。1 マウントで 1 ページ目が 2 回読み込まれるのは StrictMode の effect 二重実行だけで、そのケースのための prediction。どのテストもこれを保持していない（M9 が生存）。さらに `cancelled` を外したので、StrictMode では 2 本の 1 ページ目リクエストの結果が混ざる（R2）。
- `NoteResults` の key に drive を足した変更（G3）は分岐でも状態でもない。ただしテストで保持されておらず（M3 / M4 が生存）、G5 と同じ到達性の判定では inert（R3）。
- 結論: A-2 は「状態の組み合わせを置き換えた」という主張がおおむね成り立つ。純増は、F2 に直接答える分岐 1 つと、StrictMode 用の prediction 1 つ（元からあり、テストで保持されていない）。
