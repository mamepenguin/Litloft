## Findings

### F1 [introduced] 「Show more」を応答前に 2 回押すと 2 ページ目が永久に欠落し、以後ボタンが空振りし続ける

- 不変条件: 3（All notes / Find は同じクエリを 30 件ずつページングし `meta.total` を示す）
- 箇所: `NoteResults.tsx` の effect（`[drive, query, pages]`）と Show more ボタン
- 原因: ボタンは読み込み中も押せる。1 回目で `pages=2` の fetch が走り、2 回目で `pages=3` になると cleanup が `pages=2` の応答を `cancelled` で捨てる。`pages=3` の応答は `prev`（1 ページ目）の後ろに append される。2 ページ目を取り直す経路はない。
- 再現（スクラッチテスト、`view=all`、total 90、2・3 ページ目を deferred にして 2 連打）:
  - 要求ページ `[1, 2, 3]`、表示行 60、`Note n30` なし、並びは `n28, n29, n60, n61, n62…`
  - その後 Show more を 3 回押す: `files.length (60) < total (90)` が崩れないため、ボタンは残り続け、4・5・6 ページ目（空）を取りに行くだけで行は増えない（`rows 60 showMore true calls 6`）
- 利用者への影響: 遅い LAN / 大きいドライブで Show more をダブルクリックすると、ノート 30 件が一覧から消え、件数表示（90）と行数（60）が食い違ったまま回復しない。消えたノートは All notes からは辿れない。
- 新規コードなのでラベルは `[introduced]`（parent に `NoteResults.tsx` はない）。
- 既存テスト: 1 クリックずつ待ってから押すケースのみで、この経路は保持されていない。

### F3 [introduced] ブックマークレットで開いた後に Find（または All notes）→ ブラウザの Back で戻ると、重複クリップのダイアログが勝手に開く

- 不変条件: 10（`autosubmit=1` はちょうど 1 回だけ submit）、11（重複プロンプトは従来どおり）
- 箇所: `NotesPage.tsx` の分岐。`q` / `view=all` 状態では `ClipSection` をアンマウントし、ランディングに戻ると再マウントする。URL に `prefill` と `autosubmit=1` が残っているので、`ClipForm` のマウント時 effect（`if (autoSubmit && initialUrl) void submit(initialUrl)`）がもう一度走る。
- 再現（スクラッチテスト、同一インスタンスを `rerender` で URL だけ切り替え）: `prefill=https://example.com/a&title=A&autosubmit=1` で描画 → `createClip` 1 回 → `findClipsByUrl` が既存クリップを返すようにする → `q=kyoto` に切り替え → 元の `prefill…autosubmit=1` に戻す。
  - head `d85c2a7`（NotesPage）: `createClip 1`、`findClipsByUrl` 3 回（初回 submit、再マウント時の pending lookup、再 autosubmit）、`dialog` 1 個（重複ダイアログ）
  - parent `5835bba`（KnowledgeDashboard、同じ手順・同じモック）: `createClip 1`、`findClipsByUrl` 1 回、`dialog` 0 個
- 利用者への影響: ブックマークレットでクリップ → 同じタブで「Find a note」や「All notes」を使い → Back で戻ると、今クリップしたばかりの URL について「既にクリップ済み」ダイアログが出る。既存クリップがまだ登録されていない（`findClipsByUrl` が空を返す）タイミングだと、2 本目のクリップが作られる。スクラッチテストで `findClipsByUrl` を空のままにして同じ手順を踏むと、head は `createClip 2`（parent は同手順で 1）。
- 備考: 「別ページへ行って戻ると再 submit」は parent にもあるクラスの問題だが、ページ内の `router.push` / `Link` で同じ `NotesPage` の中を行き来する経路はこの変更で新しく到達可能になった。`[introduced]` は上の差分に基づく。
