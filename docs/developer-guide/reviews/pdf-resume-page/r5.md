## Question 2: what this round broke

Behaviour: nothing reachable found. Test coverage: R5-1 and R5-2.

- **A link in the gap after full screen mounts and before its ref effects run.** Not reachable. The viewer's pages, and so its links, exist only after the commit that mounts it. The mount comes from a click (a discrete update), so React flushes the passive effects that set both refs synchronously at the end of that commit. Nothing inline can be clicked while the dialog is up (inert backdrop). Forced in one `act` (G1: click Full screen and `itemClick(6)` in the same batch), the link takes the inline branch, stores 6, and the viewer opens on 6. That is the correct result anyway.
- **A link while full screen is closing.** Not reachable, because Escape and a click are separate discrete events. Forced in one batch (K2), the link goes to the dying viewer and is dropped: inline 1, nothing stored. That is at least consistent with the page shown (at 22fe the same forced batch stored 4 while showing 1). After a real close (K1), links take the inline branch and are saved (stored 3).
- **Controller move in full screen.** C1: `controller.goToPage(5)` shows 5 in the dialog and stores 5. C2: `goToPage(8)` on `?page=8` stores nothing. `PdfDocumentStore.goToPage` rejects out-of-range pages before `turnTo`. The store's `page` still reflects the inline page while full screen is open. That was already so before this round and is not a finding.
- **The viewer's page box through `turnToPage`.** Same calls as the inline arrow it replaced (`countTurn` then `enterPage`). M68 (`onCommit={enterPage}`) is killed. M61 (swap the order) survives and is equivalent: `enterPage` only queues state and `faceIndexRef` does not move before the next render.
- **A restore landing in full screen after a no-op link.** The author's test covers it. R1 (a link to 3 during the read, then `{5,8}`): dialog 3, saves `[…,3,8]`. Correct.
- **`turnTo` stability.** Deps are `[pageTurned]`, which is stable. The ref is read at call time, so react-pdf's captured `onItemClick` always sees the current route. M7b (from r4) is still killed.
- **Restore after close**: correct at HEAD (X2), but no longer held by a test (R5-2).
