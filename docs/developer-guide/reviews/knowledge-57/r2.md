## Findings

### G1 [introduced] The fallback branch in `lowercaseWithOffsets` is unreachable, and if it were reached it would mark the wrong letters — low, B (no invariant broken today); relevant to the trajectory answer

The fix adds `if (starts.length !== lower.length) { …identity offsets clamped to text.length… }`. That condition is
true only when the whole-string `toLowerCase()` of the title has a different UTF-16 length from the sum of its
per-code-point lowercases.

Measured (Node v25.8.2, V8): every code point that has a case mapping, is a mark (`\p{M}`) or format char
(`\p{Cf}`), plus lone surrogates and emoji (5,759 code points), combined into 2- and 3-character strings around
Σ/σ/ς/İ/U+0307/I/J/Ì/Í/Ĩ/Į, plus 300,000 random strings of length 1–6 from that pool: **0 strings** where the lengths
differ. This is what the language spec predicts: `String.prototype.toLowerCase` applies SpecialCasing's
unconditional mappings plus the Final_Sigma context only, and Final_Sigma maps to `ς`, the same length as `σ`
(the locale-sensitive Lithuanian/Turkish rules are only in `toLocaleLowerCase`). Other engines are unmeasured.

Consequences:
- N1 (delete the fallback) survives every test and changes no output in the probe.
- N2 (force the fallback) shows what it does when reached: identity offsets, so after any İ the mark is shifted onto
  neighbouring letters. It fails to wrong marks, not to no marks. A title whose engine did disagree would get wrong
  letters highlighted, which is the failure R-0 #5 forbids.

So the branch is a prediction about a disagreement that does not occur, held by no test, whose chosen behaviour on
that path is the wrong one. Removing it holds every invariant this SHA holds (see trajectory).

### G2 [introduced] Unmount after a focus/visibility event is not held: dropping `clearTimeout` in `onVisible` leaves a self-rearming timer behind — low (test gap), R-0 #7

C5 survives. `onVisible` reassigns `timer` through `schedule()`; the cleanup clears only the latest `timer`. Without the
`clearTimeout` in `onVisible`, every focus or visibility change before unmount orphans one timer, and that timer's
callback calls `schedule()` again, so it re-arms every midnight forever and calls `setNow` on an unmounted component.
The new test "leaves no timer or listener behind when the page goes away" unmounts without ever firing `focus` or
`visibilitychange`, so it cannot see this.

Reproduction: a temporary copy of that test with `window.dispatchEvent(new Event("focus"))` inside `act` before
`unmount()` passes at this SHA and fails under C5 at `expect(vi.getTimerCount()).toBe(0)`. Probe deleted. The code
at this SHA is correct; the gap is the test. `useNoteClock.ts` was created in this PR, hence `[introduced]`.

### G3 [pre-existing] A query that ends in Σ does not mark a title where that Σ is not word-final in the same way — low, B

Whole-string lowercasing applies Final_Sigma to the query and the title independently, so they can disagree:

| title | query | server returns (title `ilike`, SQLite ASCII-only `lower`) | PR parent | round 1 | this SHA |
|---|---|---|---|---|---|
| `ΟΔΟΣΚΑΙ` | `ΟΔΟΣ` | yes | no mark | no mark | no mark |
| `ΟΔΟΣ` | `Σ` | yes | no mark | `Σ` | no mark |
| `AΣ` | `Σ` | yes | no mark | `Σ` | no mark |
| `ΑΣ́Β` | `ΑΣ` | yes | no mark | no mark | no mark |

A user can hit this: the row is listed but has no mark. It does not break R-0 #5 (the PR parent did not mark these
either). The round-1 SHA marked the single-`Σ` rows; the fix gives that back, which is why this is recorded rather
than labelled a regression. The only shape found that marks all of them is folding ς and σ together on both sides
(Unicode case folding, which `String` has no API for); a per-code-point lowercase of both sides marks these but loses
rows the PR parent marked (e.g. title `Ως`, query `ΩΣ`, reachable through a folder-path match), so it is not an option.

## Trajectory answer

cases where the map and the search position disagree (`Math.max(starts[at], from)` and `if (end > start)`; round-1

that part is a real fix and is killed by tests — and then adds **a fallback branch for when the map disagrees with the
lowercased text**. That is a new branch and a new prediction layered on round 1's map, the pattern named in the brief.
