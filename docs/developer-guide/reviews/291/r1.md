## Findings

### F1 — A scoped modal outlives its drive: after back navigation, Enter and the see-all link go to the previous drive `[introduced]` — bucket A (R-0 #5; also #4)

`GlobalSearch` snapshots the scope into state on opening (`setScope(nextScope)` in `openWith`) and nothing
clears it except closing or ×. The modal is not closed by a route change, so the snapshot, including
`seeAllHref` with the old drive baked in, survives the registrant unmounting and the current drive changing.
Results follow the new drive; the destination does not.

Reproduction (preview, Playwright, client-side navigation only):
1. `/drive/テスト画像` → click `/` → click `/drive/動画` → Cmd+K, type `2026-08-10`, click the note row
   (now `/drive/動画/Captures?file=cPyL5lljH5k2`).
2. Press **ノートへ移動**, type `Lens`.
3. `history.back()` twice, then once more → URL `/drive/テスト画像`; the modal is still open with the ノート chip.
4. Observed: requests `drives/テスト画像/files?search=Lens&type=text` (row `Di36BQOY-8oW` Lens Choice from
   テスト画像), but the footer link is `/drive/%E5%8B%95%E7%94%BB/addons/knowledge?view=all&q=Lens` and Enter
   navigates to `/drive/動画/addons/knowledge?view=all&q=Lens`.
   At the intermediate `/` step (no drive), the input is disabled but the see-all link to 動画 is shown and clickable.

So a scope registered on drive 動画's page carries its see-all destination into drive テスト画像, and Enter changes
the drive. On a phone the modal is a full-screen sheet where the system back gesture is the natural way to leave,
which makes this path ordinary there (measured at 1440px only; the sheet uses the same state).

Parent: the modal also stayed open across back navigation `[pre-existing]`, but Enter built
`/drive/${drive}/search` from the *current* drive, so it stayed in the drive being viewed. The carry-over of a
destination is new with the scope.

Security: no access widening measured — the destination page does its own access check, and the drive named is one
the viewer had open in this tab. The named security concern (seeAllHref crossing drives after navigation) holds as
stated, though. No test covers a drive change while scoped.

### F2 — Clicking a scoped row is untested `[introduced]` — bucket B

p7 (`onSelect('/files/' + file.drive)`) survives all 1125 related tests. Only Enter on a highlighted row is held.

### F3 — The see-all link's `preventDefault` is untested `[introduced]` — bucket B

p4 survives. Without it the browser follows the `<a href>` after `router.push`, a full document load (the
SPA-navigation policy). jsdom does not navigate, so no vitest test can see it; the browser measurement above shows the
current code is correct.

### F4 — Focus returning to the input after × is untested `[introduced]` — bucket B

n11 survives. Without `focusInput()`, the × button unmounts under focus and typing goes nowhere. Measured correct in
the browser.

### F5 — The scope stack's pop-by-identity is untested `[introduced]` — bucket B

q1 (`slice(0, -1)`) survives: the provider test only unmounts the *later* registrant. Unmounting the earlier one
while the later stays would, under q1, remove the survivor's scope. No path in the app was found that does this today
(one `GoToNoteAction` mounted on the note page at 1440px; moving between notes keeps the same instance), so the test
gap is the finding.

### F6 — R-0 is missing items `[introduced]` — bucket B (for the supervisor)

- Clicking a row opens that file (F2); the see-all link navigates in-app without a document load (F3).
- Removing the scope leaves focus in the input (F4).
