## Findings

### F1 [introduced] A — a note from yesterday is grouped under Today (and shown with a clock time) across a DST change

`noteDates.ts` `noteAgeGroup` computes `Math.floor((startOfDay(now) - startOfDay(then)) / DAY_MS)`.
Local midnights are not 24 h apart across a DST transition: after spring-forward the gap from
yesterday's midnight to today's is 23 h, so `floor(23/24) = 0` → `"today"`. Every boundary
shifts the same way (7 calendar days ago falls into `week`, 30 into `month`).

Reproduction (probe test, `TZ=America/New_York`, now = 2026-03-09 12:00 local, the day after US DST start):

```
noteAgeGroup(2026-03-08 12:00) -> "today"   formatNoteTime -> "12:00"
noteAgeGroup(2026-03-02 12:00) -> "week"    (7 calendar days ago)
```

Same probe under `TZ=Asia/Tokyo`: `"week"`, `"Mar 8"`, `"month"` (correct). Breaks invariant 3
("by calendar day"). Reachable only for a viewer whose browser zone observes DST, for the week
after spring-forward (and never with JST). The existing test "counts calendar days, not hours"
cannot see it because it runs in the CI/host zone and uses a date with no transition; mutation
M13 (`Math.floor` → `Math.round`, which fixes it) survives, as declared.

### F2 [introduced] A (test) — nothing holds the search field in step with `q` after in-page navigation

`FindNote` is one keyed instance for the page's lifetime and relies on
`useEffect(() => setQuery(initialQuery), [initialQuery])` to follow the URL. The only test of the
field ("shows only the matches…") checks the value on first render, which `useState(initialQuery)`
already satisfies. Mutation M35 (delete the `setQuery` in the effect) survives the whole suite.
Under M35, going `?q=kyoto` → `?q=osaka` (history back/forward, or a link) leaves the field reading
`kyoto` above osaka's results, and the clear link / back link leaves `kyoto` in the field on the
landing — invariant 6 ("keeps the query"). The code at `3e81b79` is correct; the gap is the test.

Reproduction: probe `rerender` with `q=kyoto` → `q=osaka` → no `q`, asserting the searchbox value
each time: passes at `3e81b79`, fails under M35. In the running preview (Playwright, 390px):
landing → type `AI` + Enter → `?q=AI` field `AI` → `goBack()` → field `""` (correct).

### F3 [introduced] B (test) — the excerpt's failure paths are not exercised

"draws no excerpt line when the body is empty or cannot be read" stubs `{ ok: false, text: "" }`,
so the `res.ok` check is unobservable (M17 `res.ok ? res.text() : ""` → `res.text()` survives) and
no test rejects `fetch` (M18 `.catch` → set `"__failed__"` survives). Under M17 an error body such as
`{"detail":"Not Found"}` is drawn as the row's excerpt; under M18 the literal string is. Probes with a
non-empty non-ok body and a rejecting `fetch` kill both. Neither mutation removes other parts or adds
an alert, so invariant 9 itself is not broken — hence B.

### F4 [introduced] B — results-page highlighting has no page-level test and no invariant

`NoteResults` passing `query` to `NoteRows` is untested: M23 (drop `query`) and M52 (pass
`query.slice(1)`) both survive. Only `NoteRow.test.tsx` renders marks, directly. Spec P1 lists
`<mark>` on title and folder matches as part of Find results; R-0 does not mention it. See
"Missing from R-0" below.

### F5 [introduced] B — `markMatches` misplaces marks when lower-casing changes string length, and its test does not hold the unmarked text

`markMatches` finds offsets in `text.toLowerCase()` and slices the original `text` with them.
`"İ".toLowerCase()` is two UTF-16 units, so every offset after it is shifted:

```
markMatches("İstanbul ai", "ai") -> İstanbul a<mark>i</mark>
```

Also M53 (`from = at + needle.length + 1`, which silently deletes the character after every match
from the title) survives: the test asserts the list of `<mark>` texts only, not the full text.
Japanese/ASCII titles and folders are unaffected by the first part.

### F6 [introduced] B — Continue writing cards show the modification date, formatted differently from the rows

`ContinueCard` renders `formatRelativeDate(file.updated_at)`. Spec P1 says the card shows
`folder · viewed N ago`; the history rows carry `watch_progress` (last viewed) which is not used.
`formatRelativeDate` also yields `09/02` (older than 7 days) while the rows beneath render the same kind
of date as `9月2日` (`landing-1440.png`, `landing-390.png`). Possibly an intentional change during
implementation — raising it as a question, not a defect.

### F7 [introduced] B — the page's "today" is frozen at mount

`NotesPage` takes `now = useMemo(() => new Date(), [])` once for the page's lifetime; the page stays
mounted across `q=` / `view=all` navigation (measured: clip form state survives a search and back).
A Notes tab left open over midnight keeps yesterday's notes under Today with clock times, including
on results pages opened the next day, while `ContinueCard` (live `new Date()` inside
`formatRelativeDate`) moves on. Order and single-heading membership (invariant 3) are unaffected.

### F8 [introduced] B — `findSubmit` message key is now unused

The submit button was removed; `knowledge.notes.findSubmit` remains in `en.json` / `ja.json` with no
reader.
