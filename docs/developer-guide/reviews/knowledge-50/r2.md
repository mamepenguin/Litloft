## Findings

### G1 [introduced] A (test) — the DST test lets the 7- and 30-day boundaries shift after spring-forward

Mutant N2: `calendarDay` returns `new Date(y, m, d).getTime()` (local midnight, i.e. the parent's
`startOfDay` with the parent's `Math.floor` removed). It survives the whole suite under host TZ unset,
UTC and America/New_York. It is not equivalent — measured with `r2/n2.ts` in New_York:

```
now 2026-03-09, note 2026-03-02 (7 days)   N2=week   fix=month
now 2026-03-20, note 2026-02-18 (30 days)  N2=month  fix=earlier
```

Breaks invariant 3 ("by calendar day") for a week after each spring-forward. The new DST test only
exercises ages 1, 6, 1, 29, where a 23 h / 25 h error never crosses an integer without `floor`; F1 itself
named the 7- and 30-day shift. Cases at 7 and 30 days with `now` just after spring-forward would kill it.
The code at `ffc4b4a` is correct; the gap is the test.

### G2 [introduced] B — the DST test leaks `TZ="undefined"` into the rest of its file

`process.env.TZ = zone` with `zone === undefined` stores the string `"undefined"` (Node coerces env
values), which Node/ICU treat as UTC. With `TZ` unset (local dev; CI does not set it either), every test
after the DST test in `noteDates.test.ts` runs in UTC. Probe (appended test in a copy of the file):
`process.env.TZ === "undefined"`, `getTimezoneOffset() === 0`, Intl zone `undefined`; with `TZ=Asia/Tokyo`
set explicitly, restore works (-540). Other files are unaffected (`pool: "forks"`, per-file isolation;
a sibling file saw TZ unset, offset -540). The test does not depend on other tests.

Observable cost, measured against the parent's test file in the same run: mutant L1 (add
`timeZone: "UTC"` to the clock format in `formatNoteTime`) is **killed** by `3e81b79`'s
`noteDates.test.ts` and **live** with `ffc4b4a`'s, host Tokyo. No R-0 invariant covers the clock format,
hence B. (Under CI's UTC host it was live at both SHAs.)

### G3 [pre-existing] B — nothing holds "local" versus "UTC" calendar day on a UTC host

Mutant N5 (`calendarDay` uses `getUTCFullYear/Month/Date`) is killed on Tokyo/New_York/Sydney hosts by
"counts calendar days, not hours", but live on a UTC host — which is what CI runs. In UTC local and UTC
getters coincide, so the same holds for the equivalent mutant on the parent's `startOfDay` with the parent's
test. The new DST test sets its own zone but uses noon timestamps, so it does not discriminate either.
