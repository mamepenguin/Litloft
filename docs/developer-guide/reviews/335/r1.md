## 1. Nothing tests that the hook sets the frame mark  [introduced]

`frontend/src/components/player/hooks/useFullscreen.ts:355-356`

The line that makes the whole fix work — `if (frame) frame.dataset.pseudoFullscreen
= "true";` — is killed by no test in the repository.

Mutation (`want=kill`): delete line 356 entirely.
Result: **survived.** `pnpm test --run src/components` → 235 files / 3537 tests
passed, unchanged from baseline.

Nothing else can catch it:

- `grep -rn "pseudoFullscreen" frontend/src frontend/e2e-layout` returns only
  `useFullscreen.ts:356`, `useFullscreen.ts:365` and
  `e2e-layout/fixtures/pseudo-fullscreen.html:80`. No assertion anywhere reads
  the attribute off a frame the hook marked.
- `useFullscreen.test.tsx:349` ("marks the document while the frame is pinned")
  asserts `document.documentElement.dataset.playerFullscreen` only. The frame
  `renderFullscreen()` passes in (`frameRef: { current: frame }`, line 87) is a
  real `div` appended to the body, so the assertion is one line away and was not
  written.
- The e2e-layout suite cannot substitute for it: the fixture **sets the
  attribute itself** (`pseudo-fullscreen.html:80`), so it measures the CSS given
  the mark — never that the hook produces the mark. It is a fixture of the CSS,
  not of the hook.

Failure scenario: a later edit drops the frame-side mark, or renames it in the
hook only (the CSS keeps `[data-pseudo-fullscreen]`). Every suite stays green.
On iPhone the `.loft` frame is back at its own `z-50` inside `[data-sheet-snap]`,
loses to `ChromeButtons` (`fixed left-3 z-50`, later in the DOM), and the
regression this commit exists to fix returns — invariant 1 — with no signal.

That the `z-60` half of the pair *is* load-bearing was confirmed separately:
mutating `[data-sheet-snap] [data-pseudo-fullscreen] { z-index: 60 }` to
`z-index: auto` (`want=kill`) failed both "a marked pinned frame is on top
everywhere" tests. So the CSS half is held and the hook half is not.

Suggested kill: in `useFullscreen.test.tsx`'s "marks the document" test, add
`expect(frame.dataset.pseudoFullscreen).toBe("true")` and, after `exit()`,
`expect(frame.dataset.pseudoFullscreen).toBeUndefined()`.

## 2. Nothing tests that the frame mark is removed  [introduced]

`frontend/src/components/player/hooks/useFullscreen.ts:365`

Mutation (`want=kill`): delete the cleanup line
`if (frame) delete frame.dataset.pseudoFullscreen;`.
Result: **survived.** 235 files / 3537 tests passed.

Related mutation (`want=kill`): replace the effect-time capture in the cleanup
with a cleanup-time read (`const atCleanup = frameRef.current; if (atCleanup)
delete atCleanup.dataset.pseudoFullscreen;`).
Result: **survived**, same counts. Effect-time capture is the right choice here —
a cleanup-time read would leave the mark on a swapped-out node forever — but
nothing records that choice, so it can be "cleaned up" away silently.

This is invariant 4 verbatim ("the mark is present only while pseudo-fullscreen
is active, and does not survive unmount") and no test holds it. The sibling
assertions for the *root* attribute are held, at `useFullscreen.test.tsx:352`
(after `exit()`) and `:370` ("cleans up everything on unmount"); the frame mark
was simply not added to either.

**What the leaked mark actually does, measured** (I predicted worse and was
wrong; recording the measurement rather than the prediction). I built the
e2e-layout fixture with `pinned: false, marked: false`, scrolled the player
under the resting strip, then set `data-pseudo-fullscreen` on the inline frame:

```
BEFORE {"overlap":true,"hit":"strip"}
AFTER  {"frameZ":"60","over":{"overlap":true,"hit":"strip"}}
```

The frame does take `z-index: 60`, but `[data-sheet-snap] .media-detail-player`
is `position: sticky; z-index: 10` again once the root attribute is gone, and
that is a stacking context, so the 60 is trapped inside it and the strip still
wins. So on the surfaces the fixture can reach, a leaked mark is currently
inert — invariant 2 is not observably broken today.

The defect is therefore the missing test, not a live symptom: the guard that
keeps the leak inert is the box's own `z-index: 10`, which is in a different
rule from the one this commit added, and nothing ties the two together. Note
that `[data-sheet-snap] [data-pseudo-fullscreen]` is *not* qualified by
`:root[data-player-fullscreen]`, unlike its sibling rule two lines above it in
`globals.css:1016`; qualifying it would make the leak unreachable by
construction rather than by a coincidence in another rule.

Suggested kill: the assertions in finding 1, plus the `unmount()` variant.

## 3. `DESIGN.md`'s stacking table still describes the mechanism this commit removed  [introduced]

`DESIGN.md:708`

The "Immersive viewers" row reads: "… a phone player pinned to fill the screen,
**whose sticky box is lifted to this tier while it is**". After this commit the
box is not lifted — it is unstuck (`position: static`) and the tier is carried by
the frame. `frontend/e2e-layout/pseudo-fullscreen.spec.ts:74` now asserts the
box is `static`, and the spec's `## Checked, no action` states the lift is
deliberately *not* kept.

This is reportable prose under `review-workflow.md` R-3 ("report prose only when
it would lead a reader to a wrong code change") because `DESIGN.md` is not a
comment: `.claude/rules/frontend-conventions.md` makes it the record of the
design rules, and directs anyone adding a layered surface to read it. A reader
adding the next immersive surface on a phone follows the sentence, lifts a
sticky box to `z-[60]`, and reproduces on iOS exactly the defect this commit
fixes — a `fixed` box inside a `sticky` box holding a cross-origin iframe is not
painted over the chrome whatever its `z-index`.

Remedy per `comments.md`: delete the trailing clause. If the row is to keep
saying something about the phone player, the checked sentence is that the frame
itself takes this tier and its box is unstuck while it does.
