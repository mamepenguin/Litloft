## Findings

### F1 [introduced] A — the `?` cheat sheet still lists the Global section (⌘K / ⌘⇧F search) while a viewer is open
Breaks R-0 #1 ("none is listed in the `?` cheat sheet"); also contradicts the new user-guide sentence "`?` still shows the list, which then holds only what the viewer answers".

`ShortcutCheatSheet.tsx` builds `sections` from `orderContexts(stack)` but then re-appends the global context found in the **raw** stack:
```ts
const globalCtx = stack.find((c) => c.id === "global");
const sections = orderContexts(stack).filter((ctx) => ctx.id !== "global");
if (globalCtx) sections.push(globalCtx);
```
`orderContexts` drops `global` (priority 0) under a blocker, but `stack.find` brings it back.

Reproduced:
- jsdom probe (temporary test, deleted): viewer at OVERLAY_PRIORITY + blocksLower, plus `global` and `quick-note` contexts; sheet text = `ViewerSection … Esc GlobalSection SearchLabel CtrlK` — quick-note is dropped, global is not.
- Running app (headless Chromium, localhost:3000): PDF "Full screen" on `動画/Inbox?file=QDpWH-0a5M8K` → `?` → sheet ends `…Fit to screen0 GlobalSearch⌘⇧FSearch⌘K`. Gallery on `テスト画像/docs/legacy?file=nvv5a898nKrR` → same trailing `GlobalSearch⌘⇧FSearch⌘K`. Pressing ⌘K in both viewers correctly does nothing (focus stays on the viewer DIV), so the sheet advertises a key that is dead — the exact thing the change set out to stop.
- `[introduced]`: at the parent nothing blocks, so listing Global under a viewer was accurate there.
- Test gap: M12 (cheat sheet ignoring blocking entirely) survives — no test renders the sheet with a blocking context.
Fix direction (not applied): take `globalCtx` from the ordered/filtered list, not from `stack`.

### F3 [introduced] B — the interval panel now beats the viewer's Escape by push order, not by tier; the archive half of R-0 #3 is held by no test
Before this change the gallery and archive viewers sat at priority 0 and the slideshow interval panel (`OverFrameSettingsPanel`, OVERLAY_PRIORITY) outranked them by tier. Now both are at OVERLAY_PRIORITY, so the panel wins Escape only because its effect pushes after the viewer's (`orderContexts` breaks ties by index). `lib/shortcuts.ts` itself says `NESTED_OVERLAY_PRIORITY` exists because "push order within one component is just hook order".
- Not user-reachable today: the viewer contexts re-push only when `enabled`/`label`/`priority` change, none of which moves while the panel is open. Measured in the running app: gallery and archive viewer both — open panel, Esc closes the panel only, 2nd Esc closes the viewer, ⌘K works again afterwards.
- Test coverage: M13 is killed by the ImageGallery test only. `ArchiveImageViewer.test.tsx` renders the viewer without `useImageViewer`, so nothing in the suite checks panel-over-archive-viewer Escape. Bucket B unless the supervisor wants the panel moved to `NESTED_OVERLAY_PRIORITY` (a one-line change that would make M13-style regressions tier-proof).
