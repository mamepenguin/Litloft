## Findings

### F1 [introduced] High — protected-mode first run can no longer be finished
Invariants broken: 7 (the user cannot correct the cause and finish), and 6 in spirit (the wizard cannot complete).
- Every protected-mode Finish sends a password whose groups end in `__admin__`. The backend always rejects that with 422 `unknown_group` (B1).
- Before this commit the rejection was ignored and setup completed (P1 at dd40eadf and develop). Since this commit the rejection stops completion (P1 at f574831a). The message names a group the user never typed, and no field in the wizard can fix it. The only exit is going back and choosing Public.
- The new passwords test mocks a made-up rejection (`json_syntax` / "passwords entry is invalid"). No test runs a protected Finish against the real validation, and nothing asserts the passwords body (N9 lives). The whole suite stays green while every real protected run fails.
- The underlying mismatch is **[pre-existing]**, and it is itself serious. On develop, a protected-mode setup "completes" with no password saved. `passwords.json` stays `[]`, so every drive is public and every viewer is admin, and the wizard shows success.
- This commit makes that defect reachable as a hard block. Following R-4 Scope ("where the change makes a pre-existing defect reachable … raise it"), this goes to the supervisor. The two options are:
  - accept `__admin__` in the passwords validator, which is a backend change outside this diff;
  - stop sending it, which loses the admin-sentinel behaviour.
- Reverting the fix is not a remedy: it restores the silent unprotected install.

### F2 [pre-existing] Low (test gap) — the drives-then-passwords order is not held by any test
Invariant: 7 (a wrong order turns a valid setup into a rejected one).
- The backend validates password groups against the drives **on disk** (`put_passwords` reads `_read_drives_from_disk()`).
- If passwords were saved before drives, an `access_group` typed in this run would not yet exist, and the save would be rejected.
- Since this commit such a rejection blocks completion. Before it, the rejection was silently dropped.
- N11 (swap the order) survives. The parent had no order test either.
