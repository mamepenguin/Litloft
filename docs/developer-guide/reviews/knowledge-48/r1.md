## Findings

### F1 [introduced] Zoom direction is not held: swapping zoomIn/zoomOut passes every test
- Summary: the "zooms on %s when no field has focus" tests assert only `zoomPill().textContent !== before`. Any zoom, in either direction, satisfies them.
- Observation: M1 (`+`/`=` bound to `panZoom.zoomOut`, `-` to `panZoom.zoomIn`) leaves `ConnectionsGraph.test.tsx` 17/17 and the knowledge dir 873/873 green. A probe that parses the pill (`+` -> greater than before, then `-` -> less than before) passes at `ec75bd2` and fails under M1.
- Invariant: 2 ("`+` / `=` zoom in and `-` zooms out"). The test lets an invariant-2 break through.
- In new test code, so `[introduced]` without a base run.

### F2 [introduced] `hidden: true` is not held: the zoom entries can appear in the `?` cheat sheet with no test failing
- Summary: nothing asserts what the cheat sheet lists with the graph mounted.
- Observation: M4 (`hidden: false` on `+`) passes 17/17 and 873/873. A probe that renders the graph inside `ShortcutsProvider`, presses `?`, and asserts `queryByText("Zoom in")` / `queryByText("Graph")` are null passes at `ec75bd2` and at `0eee1a5`, and fails under M4.
- Invariant: 6.
- `[introduced]`: the registration that can leak into the sheet is new in this PR (at `0eee1a5` the zoom keys never touched the stack).

### F3 [introduced] Coexistence with `knowledge-graph-selection` is not held: an id collision or a selection-dependent `enabled` disables zoom keys with no test failing
- Summary: all zoom-key tests run with nothing selected, so the case where the second "Graph" context is on the stack is never exercised.
- Observation: M6 (reuse id `knowledge-graph-selection`) and M7 (`enabled` false while a node is selected) both pass 17/17 (M6 also 873/873). Under M6 the provider's `push` filters by id, so selecting a node replaces the zoom context, and Escape's `pop` then removes it for good: `+` stops zooming after the first selection. Probe: select node fA, press `+` (expect pill change), Escape (expect detail card gone), press `+` again (expect pill change). Passes at `ec75bd2` and `0eee1a5`; fails under M6 and M7.
- Invariant: 2 (zoom while no field has focus, with or without a selection).
- `[introduced]`: the second context and its id are new in this PR.

### F4 [pre-existing] Invariant 3 has no test at all
- Summary: removing `editingOnly: false` from the selection Escape shortcut (M13) passes 17/17 and 873/873. Nothing in the knowledge tests selects a node and presses Escape.
- Observation: probe "select fA, keyDown Escape on the search input, detail card disappears" passes at `ec75bd2` and at `0eee1a5`, fails under M13.
- Invariant: 3 is declared but held by no test. The code is untouched by this PR, so `[pre-existing]`; listed because the PR's invariants name it.

### F5 [introduced] With the `?` cheat sheet open, `+` / `=` / `-` no longer zoom the graph behind it
- Summary: `ShortcutsProvider` returns before the stack while `cheatSheetOpen`, so the zoom keys are now swallowed while the sheet is up.
- Reproduction: render graph in `ShortcutsProvider`, keyDown `?` on body (dialog appears), keyDown `+` on body, wait two frames, read the pill. `0eee1a5`: `484%` -> `606%`. `ec75bd2`: `484%` -> `484%`.
- Invariant: none broken (6 is about the listing only). Arguably the better behaviour for a modal; recorded because it is an undeclared behaviour change alongside the declared Cmd/Ctrl one. Bucket B unless the supervisor wants it declared.
