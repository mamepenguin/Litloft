## Findings

### F-1 [introduced] Invariant 5's test cannot catch the attribute being set in native fullscreen

- **Invariant:** 5 (native fullscreen does not set the root attribute).
- **Where:** `frontend/src/components/player/hooks/__tests__/useFullscreen.test.tsx`, "leaves the document unmarked in native fullscreen" (new in this commit).
- **What:** the test calls `toggle()` with native support set to `"ok"` but never dispatches `fullscreenchange`. So the hook's `nativeActive` never turns true, and `isFullscreen` stays false for the whole test. The test only proves that the promise's `.then` branch does not write the attribute. It does not prove that being in native fullscreen leaves the attribute unset. The most plausible way to break invariant 5 is to key the side-effect effect on `isFullscreen` instead of `pseudoActive`, for example to "lock the body in both modes". That change survives every test.
- **Reproduction (mutation M7):** in `useFullscreen.ts`, change the side-effect effect's guard from `if (!pseudoActive) return;` to `if (!isFullscreen) return;`, with deps `[isFullscreen]`. Result: the full `pnpm test` passes (498 files, 7257 tests). In a real browser, native fullscreen fires `fullscreenchange`, `nativeActive` becomes true, and the attribute and the body lock are applied during native fullscreen.
- **Proof that a stronger test holds (T7):** add `act(() => { document.dispatchEvent(new Event("fullscreenchange")); }); expect(result.current.isFullscreen).toBe(true);` before the attribute assertion. It passes on `95e6ac97` and kills M7 (1 failed: "leaves the document unmarked in native fullscreen"). Tree restored.
- Suggested bucket: A (a test that lets an invariant break through).

### F-2 [introduced] The layout fixture leaves out the real ancestors between the shell and the canvas, so an ancestor stacking context that traps the lifted box goes undetected

- **Invariant:** 1.
- **Where:** `frontend/e2e-layout/fixtures/pseudo-fullscreen.html` (new), and the chain parity it relies on (`MediaShell.test.tsx` "SPEC.pageRoot/canvas/…", `mobileInspectorSheetFixtureParity`).
- **What:** the fix only works if **no ancestor** of `.media-detail-player` creates a stacking context. `z-index: 60` is compared in the root context only when every ancestor up to the root has `z-index: auto` and no `isolation`, `transform`, `contain`, `filter` and so on. On a real phone file page the chain is:
  `AppShell main` → `TwoPaneLayout section` (or `FileDetailFullScreen`'s div, or `PaneShell`) → `[data-sheet-snap]` shell → **`div[data-testid=inspector-fit-host].relative.flex.min-h-0.flex-1`** → `main` canvas → `.media-detail-host` → `.media-detail-player`.
  The fixture builds `#root > shell > main > host > player` and drops `inspector-fit-host` and everything above the shell. The parity test only checks `canvas` with `querySelector("main")` / `toContainElement`, not as the shell's child. Today none of the omitted wrappers creates a stacking context (I checked AppShell, TwoPaneLayout, RightPaneFile/PaneShell, FileDetailFullScreen, FileDetailShell, FilePreview, MiniPlayerContainer, and globals.css for `container-type`, `contain`, `isolation` and `transform` on these classes), so the fix holds at this SHA. The problem is regression coverage: the Markdown layout already uses `relative isolate` wrappers, so adding one to the media path is a plausible edit.
- **Reproduction:**
  - **M9:** in `FileDetailShell.tsx`, change `inspector-fit-host`'s class to `relative z-0 flex min-h-0 flex-1`. Full `pnpm test` → 498 files / 7257 tests passed. `e2e-layout/pseudo-fullscreen.spec.ts` → 6 passed. Nothing catches it.
  - **F1** shows the defect is real: add the same wrapper to the fixture (`const fit = el("div", "relative z-0 flex min-h-0 flex-1"); fit.append(shell); root.append(header, fit);`). Both "a marked pinned frame is on top everywhere" cases then fail, because the header, the strip and the menu button cover the frame again, as before the fix. Tree restored.
- Suggested bucket: A (a test that lets invariant 1 break through). The spec's own verification plan listed an "ancestor stacking-context walk" on the real app, which was not done because it needed Docker. A cheap, containerless substitute: a jsdom test that renders the phone `MediaShell` and asserts the exact class list of every ancestor from `.media-detail-player` up to `file-detail-shell`. Parity by exact class list, not by containment, would catch M9.

### F-3 [introduced] A z-50 surface opened while the player is pinned is now drawn under the player

- **Invariant:** none of the six. Raised as a candidate for "missing from the list", below.
- **What:** before this commit the sticky box sat at root level 10, so any modal-tier surface (z-50) portalled to `body` drew over the (broken) pinned player. Now the box is at 60, so the same surface opens invisibly underneath it and takes focus and Escape. `useFullscreen` still assumes the opposite: its Escape binding sits on the plain tier "so a dialog opened over the player wins the press". Escape does still reach the dialog first, but the viewer cannot see the dialog it closes.
- **Reachability:** touch has no route, because every control outside the frame is covered. A hardware keyboard on an iPhone does: `ctrl+k` / `ctrl+shift+f` (GlobalSearch, `GlobalSearch.tsx`, not gated on viewport, and the focused frame is not an editing element) opens the mobile search, a `createPortal(… "fixed inset-0 z-50" …, body)`. The same applies to any other shortcut that opens a z-50 dialog, and to the z-40 overlay sidebar. Toasts (z-100), quick note (z-100), the cheat sheet (z-100) and the capture basket (z-70) stay above the player.
- **Reproduction (temporary probe spec, since deleted):** build the fixture with `{sheet: "peek", pinned: true, marked: true}`, append `div.fixed.inset-0.z-50#probe-dialog` to `body`, and call `elementFromPoint(195, 422)`:
  - at `95e6ac97` → `frame`;
  - with the new rule removed (M1, which is `c0e87c50`'s stylesheet; the commit's only CSS change is this rule) → `probe-dialog`.
  - z-[60] / z-[70] / z-[100] probes → `probe-dialog` in both.
- DESIGN.md's tier table puts immersive viewers above modal dialogs, so this may be intended. The same trade exists for the image gallery. Suggested bucket: B, unless the supervisor wants "a surface the viewer opens while pinned is drawn above the player" as an invariant, in which case it becomes C, because no single z-index satisfies both that and invariant 1's "menu button (z-50) under the frame".

## Is anything missing from the invariant list? (round 1)

1. **What a surface opened while pinned is drawn relative to the player** (F-3). The list is silent on it, and the change reversed it for z-40/z-50 surfaces. Either declare "modal-tier surfaces opened while pinned are drawn under the player (immersive tier)", or declare the opposite and accept that it conflicts with invariant 1's menu-button clause.
2. **The lift is tied to the phone file page's own ancestor chain.** Invariant 1 is only as good as "no ancestor of `.media-detail-player` creates a stacking context". An observable version: *"From `.media-detail-player` up to `<html>`, no ancestor on a phone file page establishes a stacking context."* That sentence can be violated by a mutation (M9), and it is what F-2's missing test would hold.
3. Optional: **"Toasts stay above a pinned player"** (z-100 > 60; probe confirmed). It holds today and costs one probe to declare.

## Checked, not reported

- **Other readers and writers of `data-player-fullscreen`** in core and in the checked-out addons (`addons/*/frontend`, `frontend/src/addons`): only `useFullscreen` writes it and only the new CSS rule reads it. `useMiniPlayer` no longer reads it (it observes `fullscreenchange`), so the comment this commit replaced was already stale; the replacement is accurate.
- **Players outside `[data-sheet-snap]`:** the collection surface (`FileDetailFullScreen` → `FileDetailPresenter` → `FileDetailCanvas`, no `FileDetailShell`) and phone landscape ≥ 768px (`useIsMobile` false). The box is not sticky there and no ancestor makes a stacking context, so the frame's own `z-50` competes in the root context, and it follows `ChromeButtons` in DOM order. Unchanged by this commit.
- **The Markdown `relative isolate` wrappers** (`ShellLayout.tsx`): the only `FilePreview` inside them is the HTML preview, not a player. `LoftPlayer` / `VideoPlayer` are mounted only through `MediaPlayerBlock`.
- **Two players on one page:** none found. Every player mount goes through a single `MediaPlayerBlock`.
- **Fixture differences that do not matter today:** the fixture puts `ChromeButtons` after the shell, while the real DOM puts them before the column (this only matters at equal z, and M12 shows the spec pins 60); it omits `-mx-4 -mt-4` and `MiniPlayerContainer`'s two `w-full` wrappers, which sit inside the box and so cannot trap it. The strip mounts inline in the shell and the drawer is portalled to `body`, both as in the real DOM.
- **10 → 60 → 10 timing:** the attribute is written in a passive effect, one commit after the frame gets `fixed`. When entry comes from the promise's `.catch` (not a discrete event), a single painted frame with the frame pinned and the box still at 10 is possible. Not measured; jsdom `act` flushes effects, and no real-browser run was possible without Docker. Not raised.
- **Exit via popstate, Escape, rotation, unmount mid-fullscreen:** covered by the existing hook tests (M6, M13). Invariant 6: the hook's history code is untouched by the diff (comment-only change in the hook), and M13 is killed by the history tests.
