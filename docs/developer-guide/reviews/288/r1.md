## Findings

### F1 — Related tab listing is tested only for files with a player `[introduced]` bucket A

R-0 #3 ("listed iff the file has a relation…") is held only by `MediaShell.test.tsx`. Mutation F29 (`content: relatedListed && hasPlayer ? …` in `ShellLayout.tsx`) removes the tab from every Markdown note, text file, PDF and image, and all 368 `src/components/FileDetail` tests pass; F28 (`&& usesCanvasViewer`, which drops it from the Markdown document layout — the note detail this phase is for) passes 2659 tests. This change deleted the one assertion that covered the eight non-media kinds (`ViewerShell.test.tsx`: `expect(screen.getByTestId("related-files"))…` in "gives it the same fixed inspector as every other kind") without a replacement, and no test renders the `MarkdownDocumentLayout` path with relations. `[introduced]`: the tab entry and its condition are new code; the removed assertion is in this diff.

### F2 — Relations endpoint access control is held by no test `[pre-existing]` bucket A by R-0 #6 — raise (scope rule)

Mutation B11 (look the source up by id without `unlocked_groups`) survives the entire backend suite (2323 passed). B6 (drop `File.drive == source.drive` on counterparts) survives both relations test files. So R-0 #6 is asserted by nothing: `test_file_relations_public.py` has no locked-drive or other-drive case, and it is the only file besides `test_relation_ownership.py` that calls `/relations` (`grep -rln "/relations" backend/tests`). Same at the parent `93b4bf28`: the test files there contain no such case, and this change only appended tests that do not touch locks. The code itself is correct (`_get_file_or_404(db, file_id, unlocked_groups)` and the drive filter are present), and the added `title`/`duration` are same-drive metadata of the same class as the already-returned `filename`/`folder_path`/`file_size`, so no new exposure. Declared as an invariant for this change but pre-existing, so it's for the supervisor to decide.

### F3 — On existing data, a note's own body links show under "Related files" `[introduced]` bucket B (user-reachable)

On `cPyL5lljH5k2`, the body links to おでかけ子ザメ 第59話 (hh_45I_sgMVC), 書籍のocr… (YRGbq5Jb8xGW) and 交通教本.pdf (-fvB62RqDwQ8), and they are its 情報源. All three rows are origin NULL (hh_45I_sgMVC even `incoming`, a knowledge source→note seed), so they are drawn under 関連ファイル, not このノートからのリンク. This is what the spec says (NULL → related) and the ownership spec converts NULL rows on the note's next save, so it corrects itself per note. Until then, most existing notes put their links in the "wrong" list. That is noted here so the supervisor or user sees it on real data. It is not a defect against R-0 #1, which is defined by origin.

### F4 — A type-conditional slot entry can list an empty Related tab `[introduced]` bucket B (C candidate)

`relatedListed = relations.length > 0 || getSlotEntries("file-relations").length > 0`. Knowledge now publishes `knowledge-connections-link` for every file, and it renders null unless `isTextKind`. With knowledge installed and intelligence not installed, a video, PDF or image with no relations lists a 関連 tab whose panel is empty. That contradicts DESIGN §Inspector tab strip "A tab with nothing to show is not a tab", and ADDON-DEVELOPMENT's own "a section that is only ever a placeholder does not belong in this slot". Not reachable on the current install: intelligence's `SimilarFilesSection` always renders its disclosure. Addon tabs have `available`/`onAvailability` for this, but slot entries don't. If a second conditional entry is expected, the listing rule is the thing to revisit.

### F5 — Thumbnail duration conditions not fully held `[introduced]` bucket B

F15 (badge shown when `duration == null`, which renders `--:--` over the thumbnail) and F19 (audio loses its duration) both survive. `RelatedPanel.test.tsx` has no video-with-thumbnail-and-null-duration case and no audio case. Neither is an R-0 item.

### F6 — Related lists are not refreshed after the note is saved in place `[pre-existing]` bucket B

`useFileRelations` depends only on `[fileId]`, and so did the parent's `RelatedFilesSection` (`useEffect(…, [fileId])` at `93b4bf28`). Adding or removing a link in the note and saving leaves このノートからのリンク stale until the file is reopened. Code-derived, not reproduced in the browser (that would mean writing to the preview DB). It is more visible now that the tab names the note's own links. Worth an R-0 decision: invariant or explicit non-goal.

### F7 — Knowledge link off the type scale and small on touch `[introduced]` bucket B

`ConnectionsLink` uses `text-[13px]` with no weight. DESIGN §3.2 has 11–12px labels and 14px `text-sm`, and §The Related tab asks addon entries for `text-xs font-medium text-text-muted`. At 390px the link's box measured 21px high on a coarse pointer, next to 53–74px rows.

## R-0: what is missing

1. #3 should name kinds: the tab is listed for a Markdown note, a non-media viewer file (PDF/image/text) and media alike (F1 shows the gap is real).
2. Freshness: whether the lists follow a save of the note without reopening it (F6) — invariant or stated non-goal.
3. The knowledge entry: rendered only for the text kind, and its href is the current drive's connections page.
4. The collection route shows the same sections under one Related heading (tested, but not declared).

## Implementer's decisions (1)–(11)

1. `title`/`duration` on `RelatedFileSummary`: sound. Same-drive metadata of the same class as existing fields, tested (B7/B8 killed).
2. `origin: str | None`: sound. An unknown future origin falls into "Related files" in `groupRelations`, which is the safe default.
3. No backend dedupe, frontend collapse per section: sound. `uq_file_relations_a_b_kind` makes (counterpart, kind, direction) unique by construction. Note it supersedes the ownership spec's invariant 7 ("each (counterpart, kind) at most once"), deliberately.
4. Thumbnails for video/audio/image, duration for video/audio: sound. Test gaps in F5.
5. `line-clamp-2` + `wrap-anywhere`: sound. Measured by the layout spec (two lines inside the row).
6. `RelatedStack` under an h2 on the collection route: sound. Its own fetch only mounts on that route, so there is no double fetch.
7. 45rem container query: sound, measured.
8. Tab hidden while loading, failure = empty, previous rows discarded: sound and tested (F8/F9/F10/F26 killed). With a published slot the tab stays listed through loading and failure, as observed in the browser.
9. `px-2.5 flex flex-col gap-5 empty:hidden`, priority 90: sound. The stack layout renders a fragment, so `:empty` matches when every entry returns null. At 90 the link sits after the Similar files disclosure.
10. `isTextKind` for the link: sound. It matches the backend text kind and excludes `.c`/`.html` (tested, F20 killed). Side effect in F4.
11. i18n: `relatedLinksFrom/To`, `relatedDriveRoot`, `inspector.tabs.related` added, `inspector.sections.relatedGroup` removed. No remaining reference to the removed key in core or the addons. `file.relatedFileSizeBytes` is unused both before and after (pre-existing, not counted).
