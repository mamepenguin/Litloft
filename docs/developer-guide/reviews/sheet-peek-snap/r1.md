## Findings

### F1. Tab and Shift+Tab still loop inside the raised sheet (keyboard focus cannot leave it by Tab)

- Label: `[pre-existing]` (see note). Invariant broken: **1** ("focus is not trapped in the sheet").
- Mechanism: Radix `DialogContentImpl` always renders `FocusScope` with `loop: true`;
  `modal={false}` only sets `trapped: false`. `FocusScope.handleKeyDown` returns early
  only when `!loop && !trapped`, so on the last tabbable element Tab is
  `preventDefault`ed and focus goes to the first (Shift+Tab on the first goes to the last).
  vaul exposes no way to turn `loop` off.
- Reproduction (component fixture, sheet at half with buttons s1, s2, open, s3; page
  has p1 and an input):
  - HEAD: focus s3, Tab x4 -> `s1, s2, open, s3`; focus s1, Shift+Tab -> `s3`.
    Focusing p1 programmatically -> `p1` (stays); Tab from p1 -> the page input.
  - `2957e640`: the same Tab/Shift+Tab sequence (`s1, s2, open, s3`, `shift:s3`);
    focusing p1 -> pulled back to `s3`; Tab -> `s1`.
- So this change removed the "focus pulled back" half of the trap and kept the
  Tab loop. A keyboard user (hardware keyboard on a phone/tablet, or a narrow desktop
  window, where `isMobile` is also true) who tabs or clicks into the sheet can only get
  out with Escape (which collapses the sheet) or a pointer.
- Label note: the observation is byte-identical on the parent, where it was the
  intended modal trap, so by the R-4 evidence rule this is `[pre-existing]`; it is
  listed first because invariant 1, which this change declares, is false as worded.
  The supervisor decides whether that makes it an A.
- Test gap: the unit test for invariant 1 (`leaves the page exposed, operable and
  undimmed at …`) only calls `page.focus()`; nothing presses Tab. The loop is not
  reachable in jsdom anyway (no real Tab navigation); only a browser test would hold it.

### F2. A dialog opened from inside the sheet at `half` is laid out entirely below the screen, and is now neither blocking nor dismissed by an outside tap

- Label: `[pre-existing]` for the off-screen position; the change alters what the
  user can do about it (below). Invariant broken: none of the 8 as written (see
  "Missing from the list").
- Mechanism: `FileActions` (Rename / Move / Trash confirm / collection picker) and
  the addon dialogs that use `useDialogPortalTarget` portal into
  `<div ref={setDialogHost} />` inside `Drawer.Content`. That element carries vaul's
  `transform`, so the dialogs' `fixed inset-0` resolves against the drawer's box, not
  the viewport. At `half` that box extends `--snap-point-height` below the fold, and
  the centred panel lands under it.
- Reproduction (component fixture, Pixel 5, `innerHeight` 727, `halfSnap` 0.4, real
  `ConfirmDialog` portalled via `useDialogPortalTarget`): panel rect
  `top 754, bottom 918` — fully off screen. Same numbers on `2957e640`.
- What changed with this commit:
  - Parent: the point above the sheet hits vaul's overlay (`z-[45] bg-black/50`),
    `body` has `pointer-events: none`; a tap there collapses the sheet, which
    unmounts the invisible dialog (`dialogOpen: unmounted`, sheet `peek`,
    page clicks `0`).
  - HEAD: the same point hits the page (`underneath`), `body` `pointer-events: auto`;
    the tap reaches the page (clicks `1`), the sheet stays at half, and the invisible
    dialog stays mounted (`dialogOpen: 1`) with its Escape shortcut registered and
    focus on its (off-screen) confirm button. On a phone without a keyboard the only
    ways back to it are dragging the sheet to `full` (where the box is on screen) or
    collapsing the sheet.
- Why this belongs to this round: the in-sheet host exists only because vaul was
  modal (`DialogPortal.tsx`'s docblock says so). With `modal={false}` the reason is
  gone, and portalling these dialogs to `document.body` would put them in the viewport
  at `z-50` above the sheet. Keeping the host now also keeps every in-sheet "modal"
  dialog inside the sheet's `z-[25]` stacking context, below the sidebar, its
  backdrop and anything else at `z-30`+ (DESIGN.md's `z-50` tier no longer holds for
  them). Raising it as a design question (possible **C**), not fixing it here.

### F3. `DialogPortal.tsx` docblock now states the opposite of the code

- Label: `[introduced]` (the prose was true on the parent; this change made it false).
  Invariant broken: none. Bucket B unless acted on.
- `frontend/src/components/DialogPortal.tsx` says "The mobile Bottom Sheet runs vaul
  in `modal` mode, which puts `pointer-events: none` on `<body>` and
  `aria-hidden="true"` on every other body child, so a dialog … portalled to
  `document.body` would be … completely inert." After `b1aded11` none of that happens.
  A reader deciding whether the in-sheet host (F2) is still needed would be told it is.
  Suggest deleting the docblock (whatever is decided for F2).

### F4. Escape with the overlay sidebar open over the raised sheet closes both

- Label: `[pre-existing]`-shaped mechanism, new reachable state; see note.
  Invariant broken: none (5 covers stacking only). Bucket B.
- Radix's Escape listener is on `document` in the capture phase and
  `preventDefault`s; `ShortcutsProvider`'s bubble-phase listener does not check
  `defaultPrevented`, so the sidebar's `useShortcuts` Escape also fires.
- Reproduction (fixture, sheet at half, stand-in sidebar using the same
  `useShortcuts("sidebar-overlay", …, escape → close)` as `Sidebar.tsx`): one Escape
  -> `{sheet: "peek", sidebar: closed}`. Same result with the parent component, but
  on the parent the menu button that opens the sidebar is under the modal layer, so
  this state is new to users. The user sees the sidebar on top and presses Escape
  once; the sheet underneath collapses as well. Within the accepted "Escape while
  raised collapses the sheet first"; recorded because it happens while the sheet is
  not the topmost surface.

### F5. Pseudo-fullscreen player is drawn under the raised sheet, and the fullscreen button is now reachable while raised

- Label: `[pre-existing]`. Invariant broken: none. Bucket B (raise if seen in R-5).
- `VideoPlayer` pseudo-fullscreen (every Apple phone browser) is `fixed inset-0 z-50`
  inside `.media-detail-player`, which under `[data-sheet-snap]` is
  `position: sticky; z-index: 10` — a stacking context — so the "fullscreen" frame is
  effectively `z-10`. Probe (sticky `z-index:10` box holding a `fixed inset-0 z-50`
  frame, sheet at half): `elementFromPoint` 60px under the sheet's top returns the
  sheet body, both at HEAD and on the parent. On the parent this was reachable only
  by rotating to landscape (auto-rotate is not gated by the modal); at HEAD the
  player's own fullscreen button is live while the sheet is up, so a tap on it gives
  a fullscreen video with the sheet over its lower half. (The resting strip at
  `z-40` covers the pseudo-fullscreen frame too, by reading the code on both commits;
not measured.)

### F6. The safe-area arithmetic and the "above the page's chrome" tier are held only by style/class strings

- Label: `[introduced]` (the tests are new in this range). Invariants: 4 and 5 (test gap, not a break). Bucket B.
- Measured in a real browser with CDP `Emulation.setSafeAreaInsetsOverride`
  (bottom 34, Pixel 5): strip `top 637, height 90`, row centre 665.5 (inside the
  56px band above the inset), page's last content `bottom 637` = strip top. With 0:
  `top 671, height 56`, last content `bottom 671`. So invariant 4 holds today.
- But no committed test sets a non-zero inset: `popup-dismiss.spec.ts` asserts
  `height: 56` (inset 0) and the `paddingBottom` *string*; the unit tests match
  `calc(56px + env(` against the style attribute. Consequences from the mutation table:
  M5 (strip height back to `56px`) is live in the browser suite and killed only by
  unit string matches; M6 (strip padding removed) is live in the unit suite and killed
  only by the browser test's string compare. A change that keeps the strings but breaks
  the box (e.g. `box-sizing`, the padding moved to the wrong element, the reserve put on
  a non-scrolling ancestor) would pass. `review-workflow.md` ("matching the text of a
  stylesheet cannot verify a layout property") applies; the CDP override makes a real
  measurement possible in `e2e-components`.
- Same shape for the tier: M4 (`z-[25]` -> `z-[5]`, under the sticky player's
  `z-index: 10`) passes every browser test and is killed only by the unit test that
  compares the class token. No browser case stacks the sheet against the sticky player
  or the header.

### F7. Surviving mutation: the dismissing surface's `pointer-events: none`

- Label: `[pre-existing]` (the line is context, unchanged, in `b1aded11`'s diff; only
  the overlay half next to it was removed). Invariant: 7 at most. Bucket B.
- M12 (delete `surface.style.pointerEvents = "none"`) passes unit and browser suites.
  With the overlay gone, this line is now the only thing its adjacent comment relies on
  ("a second gesture cannot catch a sheet that is already on its way out"), and nothing
  holds it. It may be redundant with the `isDismissing()` guards; either way no test
  says which.

### Observations that are not findings

- Page scroll under the raised sheet (DESIGN: "the page scrolls … while the sheet is
  up") works: CDP touch drag on a scrollable `main` beside a half sheet -> `scrollTop 230`
  at HEAD, `0` with the parent component. No committed test holds it (invariant 2 only
  taps).
- A focused page field + Escape collapses the raised sheet and leaves focus and the
  typed value in the field (`{sheet: peek, active: pfield, value: abc}`) — the accepted
  behaviour, not worse than stated; nothing of the drawer is mounted at rest (M16 killed
  by 8 browser cases and 2 unit cases).
- Escape while an in-sheet dialog is open cancels the dialog and collapses the sheet —
  identical on the parent.
- Invariant 6 across file types: every shell surface (media, image, PDF, archive via
  `FileDetailShell`; Markdown/HTML via `MarkdownDocumentLayout`) receives the one
  `sheetPeek` built in `FileDetailContainer` with `compact`, and the raised sheet's
  header is the same `FileMetaBlock` with a non-compact `FileActionRow`. While metadata
  editing is open, the raised sheet shows `MetadataEditor` instead of the row, so addon
  entries are absent there until editing ends (unchanged branch; noted, not a finding).
- Dockerfile: CI builds `frontend/Dockerfile`. Simulated both Docker mutations with
  `pnpm install --frozen-lockfile --offline` on copies: without `patches/` ->
  `ENOENT … patches/vaul@1.1.2.patch`; without `pnpm-workspace.yaml` ->
  `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`. Both fail loudly, so the build cannot silently
  ship unpatched vaul.
- vaul `exports` maps `import` to `dist/index.mjs`; the client bundle and tests use it.
  Reverting the patch only in `dist/index.js` (CJS) is invisible to every suite (M19,
  expected).

## Is anything missing from the invariant list?

1. **A dialog or popup opened from inside the raised sheet is on screen and above the
   sheet and the page.** Nothing in the list covers it, and today it is false at `half`
   (F2).
2. **Invariant 1 should name keyboard navigation**: "Tab and Shift+Tab can move focus
   from the sheet to the page." As worded it is false today (F1) and the test that holds
   it only calls `focus()`.
3. **The page scrolls while the sheet is raised** — the stated purpose (DESIGN, user
   guide), measured true, held by nothing.
4. **The raised sheet is drawn above the sticky player and the file-page chrome** (the
   lower half of invariant 5's "between" rule); only a class-string test holds it (M4).
