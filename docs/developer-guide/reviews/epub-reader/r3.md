### R3-F1. The strict pass now refuses legitimate sections that used to render, and a refused section wedges the reader: nothing after it (or before it) can be reached

- Labels: `[introduced]` for the reach (the strict pass + `parsererror` refusal in `916ba3a72`); the wedge on an empty section is `[pre-existing]` mechanism (`EMPTY = { text: "" }` since `15e18db86`). Invariant: none declared covers availability; it also contradicts 12 in spirit (a `next` shows a blank page and writes nothing). Severity **Medium**: one stray character in a real book makes the rest of the book unreadable, with a blank screen and no message.
- What is newly refused (measured in Chromium and WebKit, `scratchpad/r3-legit.cjs` against the rebuilt :3000): any section whose sanitized XML is not well-formed — a C0 control character in text (`\u000b` vertical tab, which Word-derived books use for line breaks; `\u000c`), one in an attribute (`\u0008`), an HTML-fallback comment containing `--` (`<!-- ---------- -->`), an HTML-fallback attribute name XML refuses (`1a="x"`). All other 23 realistic cases (epub:type, XHTML 1.1 doctype + entities, `&nbsp;` without doctype via foliate's fallback, MathML, SVG cover page with `xlink:href`, nav doc, standalone SVG, `&` in HTML fallback, CRLF, …) still pass raw and after foliate's own HTML fallback. NCX is read by foliate's `#loadXML` and never reaches the transform.
- Before/after (`zz-r3-render`, deleted): at `12fc6fc1a` these sections were accepted and the browser rendered the XML prefix with an error banner (vtab mid-chapter: 6 of 11 paragraphs; bad attribute: 5 of 11; dash comment in `<head>`: 0). At `916ba3a72` they are refused, and an empty XHTML blob renders nothing.
- The wedge (`zz-r3-ctl`, deleted; a 3-chapter book whose chapter 2 has one `\u000b`, 40 × `turn("next")` then 5 × `turn("prev")`): at `12fc6fc1a` the walk goes c1 → c2 (partial) → c3, 8 `turned` messages. At `916ba3a72` it goes c1 p1 → c1 p2 → blank (`section 0, page 0/1`, no document) and **stays there in both directions**; 1 `turned`; foliate throws `Cannot read properties of null (reading 'lang')` / `getComputedStyle … not of type 'Element'` on the document-less section. Same result in both engines. Pre-existing form of it: at `12fc6fc1a` a section refused for an unknown-namespace root keeps the reader in the chapter before it (next bounces back), so chapter 3 was already unreachable behind any refused section.
- Shape that removes the reach without adding a branch (measured, then restored): make the refusal value a minimal well-formed document (`<html xmlns=…><head><title></title></head><body></body></html>`) instead of `""`. With only that constant changed, the control-character book walks c1 → (blank c2, 1/2) → c3 and back in both engines, 8 `turned`. It changes the meaning of the `!once.text` test, so the author has to check that line.

## Question 3 — trajectory

Reading `15e18db86` → `12fc6fc1a` → `916ba3a72`:

- **Sanitizer — yes, it is being patched.** Round 1 added two attribute-drop branches and a new state (refuse when a second pass changes the document). Round 2 added another refusal condition (refuse when the strict second pass does not parse). It also removed something — the HTML fallback from the second pass — so round 2 is half removal, half addition. But the addition is the part that reached new ground: it closed the attack (S6 killed) and in doing so started refusing a class of legitimate books, whose refusal wedges the reader (R3-F1). That is the pattern the rule describes: each round adds a refusal for the case the round before did not foresee, and each new refusal has its own reach. The mutation table shows the result: three mechanisms, each individually redundant for every known vector (S1, S2, S3-in-browser, S4 all live), only pairs killable. What drives it is the first pass's HTML fallback. An HTML tree is serialized as XML and the browser reparses it as XML, so every round is about the difference between the two parsers. A shape that removes predictions instead of adding them would stop crossing parsers. For example, when the XML parse fails, emit HTML-typed output (`text/html`) serialized by the HTML serializer and check it by reparsing as HTML. Or refuse fallback sections outright, as a design decision, and render the refusal as a visible, non-empty placeholder. That is for the supervisor to weigh.
- **CSP probe — yes, a prediction was added in each round.** The design proved the policy with two predictions (eval refused, inline refused). Round 1 added a third check plus an environmental prediction (the probe file exists, so `error` means refused). Round 2 replaced that prediction with a timing prediction (the violation event is dispatched before the element's `error`) and an equality prediction (`blockedURI` is exactly `PROBE_URL`). Both hold in 800/800 probes per engine, and both fail closed. Still, it is the second round in a row that approximates "is this our policy?" by one more observable, and the reader now relies on an ordering that the specs do not fix. A shape with fewer predictions: resolve `true` on the matching violation event itself, and `false` on `load` or `error`. Then the ordering only decides between "opened" and "isolation", never more. That is still a prediction, so the alternative worth weighing is whether the outside-directory check pays for itself at all. It exists to refuse hand-weakened policies (`script-src 'self'`, `*`), and those only arise if someone edits `epubReaderCsp`, which unit tests already pin.
- **`restoreAnchor` — no second round.** Round 1 added the clamp to the inversion of foliate's placement formula. Round 2 did not touch it (prog-F2 recorded as B). One round, not two; the round-2 warning stands: another change there means restoring by a rescaled fraction is being patched.
- **Zoom guard:** round 1 changed which viewport is read; round 2 changed it again (`window.top` → `parentWindow`). Both are value changes, not branches, and under `frame-ancestors 'self'` both read the same window (Q1). Not a pattern.
