## Findings

### F1 [introduced] — the layout stub cannot see the clamp, so "measure while expanded" survives
- File: `frontend/LoftMetadataPanel.test.tsx` (`layOut`, ~line 234), guarding `frontend/LoftDescription.tsx:14`
  (`if (!el || expanded) return;`).
- `layOut(120, 45)` gives every element the same heights whether or not `line-clamp-3` is applied. Remove
  the `expanded` guard (M13) and the suite stays green. In a browser the effect then re-runs on expand, the
  unclamped paragraph measures `scrollHeight == clientHeight`, `overflows` becomes false, and the
  "Show less" button disappears at the moment the viewer expands. The text stays expanded with no control
  to collapse it (tapping expanded text does nothing by design) until the file changes.
- Invariant: 3 (only "Show less" collapses; with the button gone, nothing does).
- jsdom can hold this: make `clientHeight` depend on `classList.contains("line-clamp-3")` (probe P1
  kills M13).

### F2 [introduced] — the ResizeObserver path is unheld, and two of its mutations are real breaks
- File: `frontend/LoftDescription.tsx:17-21` (observer, cleanup, effect deps).
- jsdom has no ResizeObserver, so the effect returns at :17 and M14, M16, M17 all survive the suite.
  - M14 (deps `[text]`) / M17 (no disconnect): the observer attached in the collapsed state stays on
    after expand. The expansion itself resizes the `<p>`, the observer fires, `overflows` becomes false,
    and "Show less" vanishes (same symptom as F1). Probe P2 (stubbed global `ResizeObserver`, fire the
    live callbacks after expanding) kills both.
  - M16 (no observer): rotating a phone from wide to narrow leaves a now-clipped description selectable
    with no button (invariant 1); narrow to wide leaves `select-none` and "Show more" on text that fits
    (invariants 2, 4). Holdable with a stubbed observer plus a layout change before firing it; P2 as
    written does not kill M16.
- Invariants: 1, 2, 3, 4.
- Missing ResizeObserver in jsdom is not a reason this cannot be held: `vi.stubGlobal("ResizeObserver", Fake)`
  is enough. What jsdom cannot hold is whether a real WebKit reports `scrollHeight > clientHeight` for a
  `-webkit-line-clamp` box; that needs the running app (R-5) or `e2e-layout`.

### F3 [introduced] — "a different file starts collapsed" is not held by any test
- File: `frontend/LoftMetadataPanel.tsx:103` (`key={fileId}`); no test covers it.
- Drop the key (M20): suite green. A `rerender` of the panel with `fileId="f2"` after expanding (probe P3)
  shows "Show less" still up instead of "Show more", i.e. the expanded state carries to the next file,
  while the panel instance survives. The core host (`frontend/src/components/FileDetail/MediaPlayerBlock.tsx`,
  slot `loft-metadata`) passes `fileId` as a prop and does not key the slot by file, so whether a viewer
  reaches this depends on the page remounting on navigation; the key is the only thing in this change that
  guarantees it.
- Invariant: 5.

### F4 [introduced] — re-measure on a changed description (refresh re-read) is unheld
- File: `frontend/LoftDescription.tsx:21` (`text` in the deps).
- Drop `text` from the deps (M15): suite and probe green. In a browser, a metadata refresh that shortens a
  4-line description to 3 lines keeps the clamped box the same height, so the observer does not fire
  either; "Show more" and `select-none` stay on text that now fits. No test drives the refresh re-read
  (`notifyLoftRefreshed` + timers) with a changed description.
- Invariants: 2, 4 (only after a refresh on the same file; low reach).
- Related, not a defect: while expanded, measurement is skipped on purpose, so a refresh to a short text
  keeps "Show less"; pressing it collapses and the button then goes away. Reads fine.
