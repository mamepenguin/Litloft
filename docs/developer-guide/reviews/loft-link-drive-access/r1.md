## Findings

### F1 — Medium — [introduced] — invariant: none declared (see "missing from the list"); design-decisions "Access control" existence hiding
**The ordering that keeps a file on a locked / other drive indistinguishable from a nonexistent id is not held by any test.**
- Where: `backend/router.py:212` and `:233` (`_require_active_file_in_drive` before the `loft_metadata` lookup); tests `backend/tests/test_router.py` `TestLinkDriveAccess` assert status only.
- Reproduction: apply M8' (move the helper call below `if not row: raise HTTPException(404, "Metadata not found")` in `get_loft_metadata`); full suite 322 passed. Then with header `X-Lit-Drive: drv`:
  - `fsec000001` (on locked drive `secret`, has loft_metadata) -> `404 {"detail":"File not found"}`
  - `nonexist00` (no such id) -> `404 {"detail":"Metadata not found"}`
- Observed: under M8' the detail string tells a caller "this id exists on some other drive and is a .loft with metadata". At 5789513 as written both answer `404 "File not found"` (verified), so the code is correct today; the defect is that a reorder (an easy "fetch metadata first, then authorise" refactor) passes every test. `[introduced]`: the helper and its placement are new in this commit.
- Suggested hold: in the cross-drive / locked tests, also assert the response body equals the body for a nonexistent id.

### F2 — Medium — [introduced] — breaks invariant 7 (backend half) without a test failing
**No test sends a percent-encoded `X-Lit-Drive` to /metadata or /refresh; removing `unquote` survives.**
- Where: `backend/router.py:114` (`drive = unquote(x_lit_drive)`), now load-bearing for these two endpoints.
- Reproduction: M10 (`drive = x_lit_drive`), full suite 322 passed. Repro with drive `日本語` and header `quote("日本語")`:
  - 5789513: `jp-get: 200 {...metadata...}`, `jp-refresh: 200 queued`, enqueued `('fjp0000001','https://x','日本語')`
  - 5789513 + M10: `jp-get: 404 {"detail":"Drive not found"}`, `jp-refresh: 404`, enqueued `[]`
  - parent a63328b + M10: these endpoints ignore the header, so the panel is unaffected — hence `[introduced]` (this commit makes the endpoints depend on the decode).
- Observed: a regression that blanks the Loft metadata panel for every non-ASCII drive would ship green. Note the suite's `drive_path` fixture fakes `get_drive_path` to accept any name, so it cannot catch this class at all; the repro needed real `load_drives`.

### F3 — Medium — [introduced] — breaks invariant 7 (frontend half) without a test failing
**Nothing tests that `getLoftMetadata` / `refreshLoft` send `X-Lit-Drive`.**
- Where: `frontend/api.ts:64-85`, `frontend/LoftMetadataPanel.tsx:33,39,42`.
- Reproduction: grep for `getLoftMetadata|refreshLoft|LoftMetadataPanel|link/.*metadata` across `frontend/*.test.tsx` in the addon and core `frontend/src/**/__tests__` returns nothing. Dropping `headers: driveHeaders(drive)` (M16) therefore cannot fail a test. Not executed per brief (frontend jsdom tests read the live checkout).
- Observed effect of that regression: backend answers 400, `getLoftMetadata` maps any non-ok to `null`, panel renders nothing — silent, looks like "no metadata". `[introduced]`: before this commit these calls needed no header, so there was nothing to hold.

### F4 — Low — [introduced] — breaks invariant 4 (absent-header half) without a test failing
**Absent `X-Lit-Drive` is untested; only the empty-string case is.**
- Where: `backend/router.py:112` (`if not x_lit_drive`); `test_missing_drive_header_returns_400` sends `""`, and the `client` fixture always sets `X-Lit-Drive: drv`.
- Reproduction: M14 (`if x_lit_drive == ""`), full suite 322 passed. Repro GET /link/zzz/metadata with no header under M14 -> uncaught `TypeError: argument of type 'NoneType' is not iterable` from `urllib.parse.unquote` (a 500 in production). At 5789513 unmutated: `400 {"detail":"Drive context required"}` (correct). At parent + M14 these endpoints did not read the header, so the 500 path is new to them -> `[introduced]`.

### F5 — Medium — [pre-existing] — design-decisions "Access control" (locked drive existence must stay hidden); not on the R-0 list
**`_scoped_drive` answers a locked drive and an unknown drive with different bodies, which confirms a guessed locked-drive name.**
- Where: `backend/router.py:115-119`. Unknown -> `HTTPException(404, "Drive not found")`; locked -> core `check_drive_access` -> `404 "Drive not found: <name>"`.
- Reproduction (real `load_drives`, no unlocked groups), GET /link/zzz/metadata:
  - `X-Lit-Drive: secret` (locked) -> `404 {"detail":"Drive not found: secret"}`
  - `X-Lit-Drive: nosuch` -> `404 {"detail":"Drive not found"}`
  - Same pair at parent a63328b via `POST /link/zzz/stt` (identical bodies), so pre-existing; this commit adds two more routes exposing it. Core's own `check_drive_access` gives the same body for both cases, so the difference is addon-only.

### F6 — Low — [pre-existing] — cross-drive state oracle on `/link/{id}/stt`
- Where: `backend/service.py:731-735` (`enqueue_stt` returns `"already_queued"` before `_load_stt_item` applies the drive/active filter); route `backend/router.py:248-261`.
- Reproduction: file `fsec000009` on locked drive `secret` present in `loft_manager._stt_items` with status `queued`; `POST /link/fsec000009/stt` with `X-Lit-Drive: drv` -> `200 {"status":"already_queued"}`; nonexistent id -> `404`. Identical at parent a63328b. Requires knowing the 12-char id.

### F7 — Low — [pre-existing] — not reproduced, code read only
- `service.py:862-905` `_fetch_and_update` loads `File` by id alone and writes duration / chapters / thumbnail / `loft_metadata` without re-checking active state or drive. A refresh accepted at request time (active file) and trashed before the worker runs still mutates the trashed row. Not a request-time boundary break; recorded for the ledger.

## Is anything missing from the invariant list?
Yes:
1. **The 404 for a file on a locked / other drive carries the same body as the 404 for an id that does not exist** (F1). Invariants 1 and 3 fix the status only; M8' keeps every declared invariant and still leaks existence through `detail`.
2. **A locked drive and an unknown drive in `X-Lit-Drive` produce the same response** (F5). Pre-existing, but it is the same existence-hiding rule the change is for.
3. Invariant 4 should be read as "absent" and "empty" separately, each with a test; today only "empty" is held (F4).
4. Invariant 7 should name both halves: the frontend sends the encoded header (F3) and the backend decodes it on these two endpoints (F2).
