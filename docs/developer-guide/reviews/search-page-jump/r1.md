## Findings

### F1 [introduced] medium — invariant 4 — the "keeps a highlighted destination when file results arrive" test is timing-dependent
Mutation G6 (`setSelectedIndex(jumps.length + next)` for a held jump, which sends Enter to the first file instead of the Go to row) is killed in 5 of 8 runs of that test alone (`pnpm exec vitest run src/components/__tests__/GlobalSearch.jump.test.tsx -t "keeps a highlighted destination"` repeated), and it survived one full targeted run.
Observation: the test waits with `waitFor(() => getByText("trash-notes"))` and presses Enter immediately. The text appears on commit; the `rowOrder` effect that re-indexes the highlight is a passive effect and is sometimes not yet flushed, so Enter reads the old (still correct) index 0. The test then passes whether or not the re-index is right. Detector rule 3: wait for the thing asserted on (the highlight after the re-index), or resolve the files inside `act` as the "destinations arrive late" test does. Since this test is the only holder of this half of invariant 4, a test that lets it through part of the time is an A by R-4.

### F2 [introduced] medium — invariant 4 — the file-row and View-all identity paths with Go to rows present are not held
- G16b: recording a highlighted *file* while Go to rows are shown with the wrong offset survives. The only file-highlight test arrows onto the file while there are no Go to rows yet (`expect(screen.queryByText("Go to")).toBeNull()` before `ArrowDown`), so `merged[index - jumps.length]` is only exercised with `jumps.length === 0`. User path: type "trash", arrow past the Trash row to a file, the semantic stage reorders -> with G16b the highlight lands on a different file and Enter opens it.
- G5: re-indexing a held View-all row ignoring the jumps survives. User path: highlight "View all" and let pins arrive late -> with G5 the index lands on the last file, and Enter opens a file.
The code at this SHA is correct on both (read, and G7/G15 are killed); only the tests are missing.
