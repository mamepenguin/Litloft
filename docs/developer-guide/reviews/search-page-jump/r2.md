## Q1. F1: is the test now deterministic against G6?

Yes. Before the fix, `files.resolve(...)` could run inside `act` before the debounced `getDriveFiles` call had happened. The file results then arrived outside `act`, the test's `waitFor` found the text as soon as it was committed, and Enter was pressed before the passive re-index effect had run. Now the test waits for the request first, so both the resolve and the effects run inside `act`, and the synchronous `getByText` checks the state after the flush. G6 was killed 10/10 alone and 3/3 in the full file, against 5/8 in round 1. T1 shows the new wait carries weight and that removing it makes the test fail every time rather than letting bugs through.
