## Findings

### A-1 `[introduced]` — invariant 2 is false for 41 of the 43 added rows

**Invariant 2** reads: *"A source file keeps a `text/*` mime. `PUT
/api/files/{id}/content`, `GET /api/internal/files/{id}/content` and the
intelligence indexer read the mime, not the bucket, **so what each of them
accepts does not change**."* The commit message repeats it: *"so the
content-write allowlist, the addon read allowlist and the indexer accept
exactly what they accepted before."*

That holds for the fourteen **moved** rows and is false for the **added** ones.
Measured inside the image, parent module against HEAD module, against the real
frozensets (`backend/app/routers/files.py:105`,
`backend/app/routers/internal.py:43` — both `{"text/markdown", "text/plain"}`):

```
=== 14 MOVED_OUT_OF_DOCUMENT
.bat .c .css .h .js .ksh .mjs .n3 .pl .py .sgm .sgml .vcf .xml
  → write and read acceptance unchanged for all fourteen.   (claim holds)

=== 43 ADDED
41 of 43 changed:  other/application/octet-stream → */text/plain
  write False→True   read False→True
.adoc .cc .cfg .conf .cpp .cs .cts .cxx .dart .ex .exs .go .gradle .graphql
.hpp .ini .java .jsx .kt .kts .lua .mts .org .php .proto .r .rb .rs .scala
.sql .svelte .swift .tf .tfvars .toml .ts .tsx .vue .yaml .yml .zsh
```

(only `.webp` and `.m2ts` are unaffected, because they are not text.)

**Concrete failure scenario.** An operator has `infra/prod.tfvars`,
`app/config.ini` and `deploy/secrets.conf` on a drive. Before `a7c31aaa` each
was `application/octet-stream`, so `GET /api/internal/files/{id}/content`
answered **415** and `PUT /api/files/{id}/content` answered **415**. After a
rescan each is `text/plain`, so:

1. **Any addon container on the Docker-internal network** can now read their
   bytes through the Internal API — including on **protected drives**, because
   that endpoint deliberately bypasses `lit_token` drive-unlock checks
   (`internal.py:230-240` docstring). `internal-api-policy.md` describes this
   endpoint's defence as *"text mime allowlist + size cap +
   `CORE_INTERNAL_SECRET`"* and records that the secret here is the **optional**
   gate — a no-op when unset. This commit widens the first layer by 41
   extensions, and the widened set is exactly the file formats that hold
   credentials (`.tfvars`, `.conf`, `.ini`, `.cfg`, `.toml`, `.yaml`, `.yml`).
2. `PUT /api/files/{id}/content` now writes them, and `/versions`
   (`files.py:1676`) and the in-memory ETag branch of the stream endpoint
   (`files.py:866-879`) now include them.
3. By the same reasoning the invariant uses, the intelligence indexer's
   `TEXT_MIMES` now matches them too, so their contents become eligible to be
   sent to an LLM provider. I could not verify this (submodule not checked
   out) — it follows from the invariant's own premise that the indexer reads
   the mime.

**Why the tests do not catch it:** `test_a_source_file_is_still_text_to_everything_that_reads_the_mime`
(`test_classify_boundary.py`) asserts `mime.startswith("text/")` for the moved
rows **and for `.ts`, `.rs`, `.go`** — it asserts the widening rather than the
invariant. M17 confirms it: closing `.tfvars` back to `application/octet-stream`
**fails** the suite. Nothing anywhere compares the table against
`_TEXT_WRITE_ALLOWED_MIMES` or `_CONTENT_READ_ALLOWED_MIMES`, so a future row
added with `text/plain` extends the addon-read surface silently as well. Per
R-4, a test that lets an A through is an A.

This is not necessarily an argument to revert: giving source files a text mime
is defensible and may be wanted. What is not defensible is shipping it under an
invariant that says it did not happen. Either the mimes for configuration
formats close, or invariant 2 is rewritten to declare the widening and the
security review of the Internal API surface is redone against the new list.

### B-1 `[introduced]` — the folder card's text excerpt disappears for the fourteen moved rows

Three components gate the card's text preview on the bucket, not the mime:

- `frontend/src/components/FileCard.tsx:75-79`
- `frontend/src/components/FileListRow.tsx:88-92`
- `frontend/src/components/JustifiedFileCell.tsx:66-70`

all of the form:

```ts
const isTextPreviewable =
  !hasThumbnail &&
  file.file_type === "document" &&
  ((file.mime_type?.startsWith("text/") ?? false) || OFFICE_MIMES.has(...));
```

**Scenario.** A folder of `.py` / `.c` / `.css` / `.js` / `.xml` files. Before:
each card drew `<TextThumbnail>` — the first lines of the file. After the
rescan: `file_type === "other"`, the condition is false, and each card draws the
generic `<FileTypeIcon>` instead. The file-detail page is unaffected
(`FilePreview.tsx:206` uses the mime/extension-based
`TextPreview.isTextPreviewable`, whose `TEXT_SUFFIXES` already lists every new
extension), so only the listing loses the excerpt.

The user-guide sentence this commit adds
(`docs/user-guide/file-browsing.md:76`) states *"They still open in the text
viewer, and you can still edit and search them; **only which bucket they are
counted in changed**."* The last clause is false: the card excerpt changed too.
Delete that clause or name the excerpt.

The frontend is untouched by this commit, so the fix is a decision, not an
oversight to patch blindly — but it is the most visible thing a user will
notice, and no invariant names it.

### B-2 `[introduced]` — a saved smart folder with `file_type="document"` silently narrows, and `other` cannot be selected

Measured in the image, same fixture, parent classifier vs HEAD classifier. Ten
files seeded, a smart folder created with `file_type="document"` (accepted,

HEAD:    ?type=document -> guide.rst note.md sheet.csv        (3 rows)

The stored filter is a plain string (`schemas.py:883`,
`SidebarSmartFoldersSection.tsx:60` puts it straight into `?type=`), so the

And the operator cannot rebuild it:

```
POST /smart-folders {"file_type": "other"} → 422
  "file_type must be one of ['audio', 'document', 'image', 'video']"
```

`_SMART_FOLDER_FILE_TYPES` (`schemas.py:883`) has no `other`, so the bucket 57
extensions just moved into is not addressable from a smart folder at all. The
plan named this the HIGH risk; it is still unmitigated and unmentioned in
`known-issues.md`.

### B-4 `[introduced]` — the shell family answers three ways, which is the thing `.mts` was settled to avoid

The block comment says *"Source, configuration and **shell**: text a machine
reads. They keep a `text/*` mime"*. Measured against the table:

| | bucket | mime | write/read allowlist |
|---|---|---|---|
| `.bat`, `.ksh` | other | `text/plain` | yes |
| `.zsh` | other | `text/plain` | yes |
| `.sh` | other | `application/x-sh` | **no** |
| `.csh` | other | `application/x-csh` | **no** |
| `.bash` | *(no row)* | `application/octet-stream` | no |

So `script.zsh` is editable in the browser and readable by an addon and
`script.sh` is not, for no reason a reader can find. `.sh` and `.csh` are not
in the block the comment heads; they stay in the `other` block below. The
commit's own justification for `.mts` — *"so the family answers one way"* —
applies here and was not applied.

### B-5 `[introduced]` — `ADDED` is anchored only to itself; nothing asserts a count

M7: deleting `.tfvars` from the table **and** from `ADDED` leaves the suite
green (1236 passed — one parametrised case fewer, and nothing asserts the
number of cases). `MOVED_OUT_OF_DOCUMENT` does not have this property, because
those extensions are in `classify_golden.json` and M9 shows the golden kills
their deletion. The forty-three added rows are in no golden, so their only
anchor is the dict that declares them.

`review-workflow.md` detector rule 1 asks an enumerating assertion to be
`toBe(N)`. There is no count anywhere: not `len(ADDED)`, not
`len(MOVED_OUT_OF_DOCUMENT)`, not `len(_EXTENSION_TABLE)`. Adding
`assert len(_EXTENSION_TABLE) == 194` and `assert len(ADDED) == 43` makes a
silent removal an edit someone has to make deliberately.

### B-6 `[introduced]` — the duplicate-key detector sees only the first literal

M12: `_EXTENSION_TABLE.update({".mts": ("other", "text/plain")})` appended after
the dict leaves `test_no_extension_is_written_twice` green (1237 passed). The
test walks for the first `AnnAssign` whose target is `_EXTENSION_TABLE`, reads
`node.value.keys`, and `return`s (`test_classify_table.py`). A second write
outside that literal is invisible to it; the `len(keys) == len(table)` guard
does not fire because the update rebinds an existing key rather than adding one.

The blast radius is small — a second write with a *different* value is caught by
the declaration tests (M4/M5 pattern) — so this is not an A. It is worth one
line because invariant 7 is stated as *"No extension is written twice"*, which
is wider than what the detector holds. M13 also shows the detector is coupled to
one literal shape: a `{**A, **B}` reformat makes it raise `AttributeError`
rather than assert. That failure direction is the right one (it fails, loudly),
but the detector then holds nothing about the two halves.

### B-9 `[introduced]` — the ledger rewrite closes the `.webp`/`.m2ts` row but leaves `.ts` unnamed

`known-issues.md` now reads *"AVCHD footage named `.mts` has no player … `.m2ts`,
which is only ever AVCHD, plays."* `.ts` is the far more common
transport-stream extension (broadcast capture), and this commit newly claims it
as a TypeScript module with a `text/plain` mime. A user with `.ts` recordings
is in exactly the state the row describes and cannot find it by searching for
the extension they have. One sentence in that row, naming `.ts` beside `.mts`,
closes the gap.
