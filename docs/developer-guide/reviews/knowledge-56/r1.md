## Findings

### F1 — Page-level "no ?focus behaves as before" is unheld: a page that yields `""` instead of `null` shows the notice on every plain visit
- `[introduced]` (new code in `pages/connections.tsx` and new test file lines)
- Breaks: invariant 5 (as a test that lets a violation through)
- Observation: M15 (`?? null` -> `?? ""`) survives. With it, `initialFocusMissing` is `hasAnyContent && "" !== null && !nodeById.has("")` = true, so `/drive/d/addons/knowledge/connections` without a query shows "This file has no connections yet..." over the whole graph. The component-level test "stays unfocused when no file is given" does not render the page, and the page tests without `search` never assert the notice's absence (the "offers nothing that empties the graph" case checks buttons only).
- Related real-code seam: the effect treats `""` as "no focus" (`!initialFocusId`) while the notice treats only `null` as "no focus" (`!== null`). See F4 for the user-visible side.
- Rows: M15.

### F2 — Escape out of an initial focus (invariant 6) has no test
- `[introduced]` (the arrival-focused path is new; the Escape handler itself is pre-existing)
- Breaks: invariant 6 (as a test that lets a violation through). Current behaviour is correct (probe above).
- Observation: M19 removes the focus branch of the Escape handler; all 37 tests pass. Only the reset button path of invariant 6 is tested.
- Rows: M19.

### F3 — Changing `?focus` while the page stays mounted keeps the old focus; to a non-node it shows the old focus banner and the "no connections" notice together
- `[introduced]` (new effect / new `initialFocusMissing`)
- Breaks: invariant 3 on this path (whole graph is not drawn unfocused while the notice says it is); invariant 2/3 are only stated for "opening", so arguably out of the list's scope.
- Reproduction (rerender of `ConnectionsGraph` while mounted, same data):
  - `initialFocusId` `fB` -> `fO` (orphan): notice shown **and** banner still shown, rendered ids `[fA,fB,fC]`, detail card for B still open.
  - `fB` -> `fX` (another node): moves focus to fX correctly (`[fX,fY]`).
  - `fB` -> `null`: banner for B remains.
- Reachability: the `[slug]` addon page component persists across a search-param-only change, but I found no in-app path that changes `?focus` without leaving the route (the graph page has no Related tab; `/files/[id]` is a separate route that unmounts the graph; back/forward between two graph entries needs them adjacent in history). So not user-reachable today as far as I can tell — likely B.
- Rows: none (no test exercises a prop change; M5 only covers re-application after reset).

### F4 — `?focus=` with an empty value shows the "no connections" notice although nothing is focused
- `[introduced]`
- Breaks: none of the declared invariants literally (inv 5 is "without ?focus"); reads wrong.
- Reproduction: page with `search = "focus="` and a normal graph -> notice shown, no banner. Cause is the `!initialFocusId` vs `!== null` mismatch in F1. Only reachable by a hand-edited URL (ConnectionsLink always has a non-empty `fileId`). B.
- Rows: M15 is the same seam.

### F5 — On a truncated graph the notice asserts "This file has no connections yet" for a file whose connections may just have been cut
- `[introduced]`
- Breaks: none declared (inv 3 is satisfied literally); it is a false statement to the user. The backend sets `truncated` when `file_relations` returned a full page of 5000 (`app/routers/connections_graph.py`, "which ones is arbitrary"), so a connected file can be absent from `nodes`.
- Reproduction: `ConnectionsGraph` with `{...graph, truncated: true}` and `initialFocusId` not in nodes -> both `stats.truncatedWarning` and `focus.notInGraph` render; the notice's claim ("no connections yet") contradicts the Related tab the user just came from. Reachable only on drives at the relation cap. Likely B; raise only if the notice is meant to be a claim about the file rather than about the graph.
- Rows: none.

### F6 — The notice stays for the life of the page, including after the user focuses another node
- `[introduced]`
- Breaks: none. Probe: arrive with `fO` (not in graph) -> select fA -> "Center on this" -> banner for A shows and the notice about the arrived file is still displayed above it. The text remains true about the arrived file, so this reads slightly odd rather than wrong. B.
- Rows: none.
