## Findings

### R1-1 — Invariant 3's border width is compared to itself, so "no border at all" passes

- Severity: medium. Bucket: **A** (a test lets an invariant-3 break through). Label: [introduced] (new e2e file).
- What: `segmented-control.cases.ts` asserts `s.borderWidth` equals `m.segments[0].borderWidth`, an expectation built from the observation (Detector rule 5). `border-top-color` is computed regardless of width, so a selected segment with a 0px border still reports the accent colour.
- Reproduction (E3): add `border-0` to both `SELECTED_CLASS` and `UNSELECTED_CLASS` in `SegmentedControl.tsx`. Every segment then has no border, so the selected option is marked by nothing but `font-medium`. Vitest 205/205 and e2e-components `segmented-control` + `header-row-crowding` 43/43 stay green. The detector stays green too, because the `border` token is still in `SEGMENT_CLASS`.
- Fix: declare the width, e.g. `expect(s.borderWidth).toBe("1px")`, and keep the equality if you like.

### R1-2 — Invariant 6 "not drawn translucent" has no holder

- Severity: low. Bucket: **A**. Label: [introduced] (the invariant is new with this change, and so are the tests meant to hold it).
- What: the fixture opens the panel at `fontSize: 3`, so no disabled A button is ever drawn in a real browser. The unit tests check only `toBeDisabled()`.
- Reproduction (E9): pass `className="disabled:opacity-30"` to the "Smaller text" `Button` in `EpubTypographyPanel.tsx`. Vitest and e2e both stay green.
- Fix: add an arrangement or a case at step 0 (and/or step 6), and assert that the disabled button's computed `opacity` is `"1"`.

### R1-3 — The Markdown toggle's group name (invariant 1) is held only at the component level

- Severity: low. Bucket: **A**. Label: [introduced] (new key `file.markdownViewMode`, new wiring).
- What: `SegmentedControl`'s unit test holds "the group has a name" for a label that was passed in. For the panel, `EpubPreview.test` kills the equivalent mutation (M3). Nothing holds the `MarkdownViewModeToggle` caller.
- Reproduction (M6): `label={tFile("markdownViewMode")}` → `label=""` type-checks. The 205 vitest tests pass, including `MarkdownDocumentLayout` and the knowledge `Editor.focusOnEdit`, and so does e2e.
- Fix: add one assertion to `MarkdownDocumentLayout.test.tsx`: `getByRole("group", { name: <the view label> })`.

### R1-4 — Detector: a hand copy outside the three recognised class forms is not seen

- Severity: low. Bucket: **B**. Label: [introduced] (`drawsOutlinedSegments` is new; the `classStrings` extractor it relies on is pre-existing and shared with the older tab detector).
- What: `classStrings` reads only `className="…"`, ``className={`…`}``, `className={"…"}` and `*_CLASS` constants. The owner itself writes `className={[…].join(" ")}`, and that form, a ternary `className={on ? "…" : "…"}`, and `cn(…)`/`clsx(…)` are all invisible to it.
- Reproduction: D1, the recipe inlined as `className="…"` plus `aria-pressed`, is **killed**. D2, the same recipe written as `className={["…"].join(" ")}` for the group and a ternary for the segment, **survives**.
- Fix, if wanted: harvest every string literal in the comment-stripped file, or every literal inside a `className={…}` expression, instead of the three attribute forms. D3, a near variant with `p-1` in place of `p-0.5`, also survives. That follows from exact-recipe matching and is not worth chasing.

### R1-5 — The focus ring has no holder

- Severity: low. Bucket: **B** (not a declared invariant; raise for R-0 revision if keyboard focus is meant to be held). Label: [introduced] (new component).
- What: `SEGMENT_CLASS` carries `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-focus-ring`. If the ring half is deleted, `outline-none` leaves keyboard users with no focus indicator on any segment.
- Reproduction (E16): delete ` focus-visible:ring-2 focus-visible:ring-focus-ring`. Vitest 205/205 and e2e 43/43 stay green.
- Measured at `ac67437bb` (a scratch Playwright run on the desktop project, since deleted): Tab visits Reset, Smaller, Larger, then all 9 segments in order. Each focused control shows `box-shadow … rgb(67, 94, 229) 0 0 0 2px`, which is the `--focus-ring` colour. Nothing clips it: the group's `p-0.5` plus its border keeps the 2px ring inside the group, and the panel's `overflow-y-auto` does not cut it.
- Fix: in the e2e case, focus one segment by keyboard and assert a non-`none` `box-shadow`, or `outline`.

### R1-6 — "Text segments share the group's width" is not held

- Severity: low. Bucket: **B**. Label: [introduced].
- Reproduction (E14): make the text group `inline-flex` instead of `flex w-full`. The labels still fit, and every test stays green. The panel then draws three short, left-packed groups.
- Fix (optional): in the e2e case, assert that each text group's width equals its field's width.

### R1-7 — Panel fields announce their label twice

- Severity: info. Bucket: **B**. Label: [introduced].
- What: `Field` renders a visible `<span>` label, and the `SegmentedControl` beneath it gets the same string as `aria-label`. Nothing connects the two, so a screen reader reads the span text and then "Line spacing, group".
- Fix (optional): let `SegmentedControl` accept `aria-labelledby` and have `Field` give its span an id. Or keep it as it is, since it is harmless.

### R1-8 — Survivors that also survive at the parent (ledger only)

- [pre-existing] M11: dropping the font options' `style: { fontFamily: SAMPLE_FACE[o] }` survives. At `00721f7dd`, `EpubPreview.test.tsx` had no assertion on the sample face either (checked by grep).
- [pre-existing] M15: dropping `aria-live="polite"` from the percentage survives. No test at the parent held it.
- [pre-existing] `tab-styles.test.ts` `sourceFiles`: `readdirSync(ADDONS_DIR, { withFileTypes: true }).filter(e => e.isDirectory())` drops any addon that is a symlink, because `Dirent.isDirectory()` is false for a link. Measured in this worktree, where all four addons are symlinks, both detectors scan no addon code, and "reads the whole tree" still passes: it checks only `> 100` files and `PageTabs`. In a normal checkout the submodules are directories, so this bites only in link layouts like this one. Separately, I grepped the real addon trees and none of them match `drawsOutlinedSegments`, so there are no false positives there today.

## Answers to the brief

**Places the diff reaches that are not in the touch-point list.**
- `e2e-components/projects.ts` and `spec-viewport.spec.ts` (project assignment lists), and `componentFixtureParity.test.tsx` (arrangement list). These are mechanical registration and not invariant candidates.
- The existing key `file.epubTypography`, previously only the dialog's `aria-label`, is now also the panel's visible title. Harmless.
- `components/Button.tsx` is now what paints the A buttons and Reset, through its disabled recipe and its coarse overhang. The panel item names `Button` iconOnly, so this is effectively covered. Its disabled appearance is not measured: see R1-2.
- The one real candidate is the knowledge editor's **standalone** headers (`Editor.tsx`, inline `py-1.5` and full `py-2.5` rows). They receive the wider coarse toggle (about 64 → 96 px) without a measurement. Only the file-detail chrome row is measured. The toggle stays 32 px tall, so these rows cannot grow in height; the width they give up comes from `min-w-0 flex-1` title fields. Low risk.

**Is the tab-styles detector sound?**
- Comments: it does not match them. The body goes through `stripComments`, and D4 (the recipe in a `//` comment) lives.
- Vacuous passes: guarded. "keeps the owner drawing it" fails if the owner is missing or drops the recipe (E13 is killed). The addon half can be empty in link layouts (R1-8).
- Expectations: the token sets are declared constants, not built from observation.
- False positives: none in core or in the real addon trees. Scope is per file, the same trade-off as the older detector.
- False negatives: R1-4 (unrecognised class forms). Near-variants are out of scope by design.
- One brittleness: E13 (`p-0.5` → `p-1` in the owner) fails the owner check, so a legitimate tweak to the recipe needs the token list updated in the same change. That is the intended "the edit is the point".

**Accessibility.**
- Group naming: every group is named; the Markdown caller's name is not held (R1-3). Labels are doubled in the panel (R1-7).
- `aria-pressed`: exactly one true per group, verified in the browser (`Line spacing: true,false,false` and so on) and held (M2 killed).
- Focus ring: visible and not clipped, but not held (R1-5).
- Icon segment names: `aria-label` and `title` are both the label, and the icon is `aria-hidden`. Held (M4 killed).
- Keyboard: native buttons in DOM order, Space and Enter work, no roving tabindex (per the spec's "Checked, no action"). The A glyphs are `aria-hidden`, and removing that (M14) is equivalent because `aria-label` wins. This is the deliberate deviation recorded in the spec.

**Other checks.**
- `tsc --noEmit`: no output.
- eslint on the changed files: 0 errors, and 1 warning at `fixtures/app.tsx:1539` (`<img>`, not in this diff).
- `test:e2e:epub`: 206 passed, 4 skipped.
- Worktree restored: `git diff --stat -- frontend DESIGN.md` is empty.
