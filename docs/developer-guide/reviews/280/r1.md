## Invariant 5 revision (the `@/addons/*` stub)

The stub hides nothing a test here should see. The `add-menu` arrangement mounts no
`AddonSlotsProvider`, so `useAddonSlots()` returns the default context (`hasSlot: () => false`),
and no `addonProps` is passed; `showAddonRows` is false and `AddonSlot` never renders. The stub
replaces only the addon slot modules that `AddonSlot` / `AddonSlotsProvider` import dynamically,
which this arrangement never reaches; without it the bundle does not build (M31). The one thing it
would mask (M32) is a static core → addon import added to AddButton, which the real Next build
would not flag either (the `src/addons` link tree resolves it) — that rule is held by review, not
by this suite. The `next/navigation` stub is reached only through `CurrentDriveProvider` (imported
by `AddonSlotsProvider`), whose hook is not called here.

## Findings

### F1 — Medium — [introduced] — `frontend/e2e-components/add-menu.cases.ts:48` (also `:15`)

Invariant 3 ("on both desktop and Pixel 5, pressing a menu row runs that row's action once and
closes the menu") is not held on Pixel 5 for a touch press. `getByRole("menuitem", …).click()`
dispatches a mouse sequence even in the `hasTouch`/`isMobile` project (measured
`pointerType: ["mouse"]`), so the Pixel 5 row case is the desktop case at a narrower width.

Reproduction: apply M29 (or M15) at `DismissScrim.tsx:151` — the inside-popup exemption only for
mouse (or not for touch). `add-menu.spec.ts` stays 3/3 green under `[chromium]`, while a real
`touchscreen.tap` on New Folder in the built page leaves `data-created="0"` on Pixel 5 (menu
dismissed on `pointerdown`, click swallowed) versus `"1"` on real code. Remedy direction: tap the
row (and the trigger, for consistency) by touchscreen when `isMobile`, as the outside-press case
already does.

### F2 — Low — [introduced] — `frontend/e2e-components/add-menu.cases.ts:50`

"runs its action once" passes as soon as `data-created` reads `1`; a second invocation that
arrives later is not seen. Reproduction: M27 (`setTimeout(onCreateFolder, 300)` after the real
call) — 6/6 green. A second invocation in the same task (M12) is killed, so the realistic
double-fire shapes are held; this is the late-arrival window only (detector rule 3). Invariant 3.

### F3 — Medium — [introduced] (invariant gap, for the supervisor) — `frontend/e2e-components/add-menu.cases.ts`

No case presses Add while the menu is open. M14 (trigger always opens, never toggles) survives on
both projects; the probe shows real code closes on a second press by touch and by mouse, and M9
turns that into "menu stays open" on both. Not a declared invariant, so the bucket is the
supervisor's (see the R-0 answer).

### F4 — Low — [introduced] (prose) — `frontend/e2e-components/fixtures/app.tsx:1-4`

The file header says "`ShortcutsProvider` is deliberately absent … Escape does nothing here".
This commit imports and mounts `ShortcutsProvider` in the `add-menu` arrangement, whose Escape
case depends on it. A reader following the header could remove it from `AddMenu`; the Escape case
would go red (as M3/M6 do), so it would not pass silently. Remedy: delete the header (or scope it
to the arrangements it describes). Bucket B.
