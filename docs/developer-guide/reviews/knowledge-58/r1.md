## Findings

### F1 — A late answer from an unmounted All notes list writes its count onto the current screen
`[introduced]` (the `onTotal` path and the scope-line count are new in this commit; at the parent an unmounted list's `setTotal` was a no-op on a dead component and no scope count existed)
R-0: **4** ("A count never belongs to another drive or another scope than the one on screen"; "on search results … no number").
Location: `frontend/AllNotes.tsx:77-100` (`loadNext` has no cancellation, calls `onTotal` after `await`), `frontend/NotesPage.tsx:78-81` (reset runs only at the key change, before the stale answer).
Severity: **Medium** (user-reachable by clicking while a page is loading; wrong number persists until the next reset — indefinitely if the new list answered first).

`RecentNotes` guards with `cancelled`; `AllNotesList` does not. When the list is remounted (scope or drive key change) or unmounted (leaving `view=all`), its in-flight request still resolves and calls the parent's `setTotal`, which the parent's reset has already run past.

Reproductions (probe, deferred `getDriveFiles`):
- P1 `view=all&folder=A` → `folder=B`; B answers 5, then A answers 99 → scope line `d · 99 items` (list below says 5).
- P2 `view=all&folder=A` → landing (the "Notes" back link); landing answers 3, then A answers 99 → `d · 99 items`.
- P3 `view=all` → `q=x` (search results) → old answer 99 → `d · 99 items` on results.
- P4 `view=all` on drive `d` → drive `e` (NotesPage kept mounted) → old answer 99 → `e · 99 items`, a count of drive `d`.
- Control P7: the same drive change on the landing stays `e` — `RecentNotes` cancels.
