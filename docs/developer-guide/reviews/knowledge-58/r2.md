## Checked, no finding
- Withdrawal ordering: React runs every passive cleanup of a commit before its passive setups, so the leaving list's `onTotal(null)` precedes the arriving list's request; the arriving list's answer is always a later microtask (P8, P12, P14).
- `RecentNotes` cleanup on a drive change (not unmount): withdraws the old drive's count while the new fetch is in flight (P12), then reports the new one.
- `[onTotal]` dependency: `onTotal` is `setTotal` from `useState`, stable; M13 live as expected. If the identity ever changed, the count would be withdrawn and not re-reported (M9) — held by two suite tests.
- StrictMode: `mounted.current` ends `true`; the dev cleanup's `onTotal(null)` is followed by the second fetch effect run (the `[]` effect re-runs on the simulated remount), which reports again (S1, S3). `RecentNotes` likewise (S2, S4).
- `finally { if (mounted.current) setLoading(false) }` and the early `return`: every path on a live instance has `mounted.current === true`, so `loading` is cleared (P15, M17). Only an unmounted instance skips it.
- Siblings: `ContinueWriting` calls `getWatchHistory`, not `getDriveFiles`, and reports no count. `AllNotes`/`RecentNotes` have no other caller than `NotesPage`. `NoteResults` reports none.
- Suite tests relying on the JSON-formatting next-intl mock (`count\":5`): non-vacuous — M1, M4, M6, M7, M8, M15 each fail one of them.
- `tsc --noEmit` clean; tree restored, `git -C addons/knowledge status` clean at `68f8030`.

## Trajectory
`4c1ab67` added a prediction in the parent: `listKey`, a second model of when the child list is replaced, plus a reset effect and failure-path `onTotal(null)` branches. `68f8030` **removes** that prediction, the reset state and both failure branches, and moves the rule into the component that knows its own lifetime (withdraw on cleanup, ignore answers after unmount). It does add a state (`mounted` ref) and three guards in `AllNotesList`, but these are the same cancellation `RecentNotes` already had, not a new case the original anticipated; the extra `mounted.current = true` re-set is the cost of using a ref instead of an effect-local `cancelled` flag (F3). Two independent sources of the count's lifetime became one. **Converging, not being patched.** Only one fix round exists, so the two-rounds rule cannot yet apply.
