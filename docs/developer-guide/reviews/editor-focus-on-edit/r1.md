## Findings

### F1 - Medium - [introduced] - test gap: the null-editor guard is reached in real navigation and no test holds it
File: `frontend/Editor.tsx:468-469` (`const editor = editorRef.current; if (!editor) return;`).
Observation: M12 (remove the guard) survives the whole suite (540 passed). Probe tests, with the guard removed:
- A: host in preview, click host-edit while the `/stream` fetch is pending, then resolve -> `TypeError: Cannot read properties of null (reading 'focus')`.
- B: host in preview on f1 (loaded), rerender with fileId f2 while the host's reset effect sets `edit` (the `?edit=1` + `resetKey` path in `MarkdownDocumentLayout.tsx:67-76`) -> same TypeError.
With the guard present (as committed) both probes pass: no error, and the editor is not focused after load.
So B shows the preview->edit transition fires while the editor is unmounted on an ordinary navigation (file change into `?edit=1` from a note shown in preview), not only on a user toggling during load. The code is correct; nothing holds it. A throw in this effect would take down the note page.
Invariant: 6 (and 5, since the `?edit=1` path depends on this effect not throwing before autoFocus runs). A test that lets an A through.
Suggested hold: a test that switches preview->edit while the load is pending, then resolves, and asserts no error and no focus (probe A shape).

### F2 - Medium - [introduced] - test gap: nothing asserts the document text or the absence of a save after a mode switch
File: `frontend/__tests__/Editor.focusOnEdit.test.tsx` (whole file); code under test `frontend/MarkdownEditor.tsx:451-460`.
Observation: M19 makes `revealSelection` dispatch `changes: { from: doc.length, insert: "x" }` alongside the scroll effect. Whole suite: 540 passed. That mutation changes the document on every preview->edit and fires `onChange` -> autosave. M18 (insert at 0) was killed only because it shifts the caret the "keeps the caret" test checks.
Invariants: 2 (text unchanged) and 4 (no save/autosave/version) are not held by any test. The committed code does not break them (dispatch carries only `effects`; the update listener fires onChange only on `docChanged`).
Suggested hold: in "keeps the caret", also assert the editor text is unchanged and that no PUT was issued to the content endpoint after the switch (with fake timers past the autosave debounce).

### F3 - Low - [introduced] - during a restore, preview->edit still scrolls although it cannot focus
File: `frontend/Editor.tsx:470-471`.
Observation (by reading, plus the CM6 source): during a restore `MarkdownEditor` gets `disabled`, CodeMirror sets `contenteditable="false"` on `.cm-content` (`@codemirror/view` dist/index.js:8275) and sets no tabindex, so in a browser `view.focus()` is a no-op, as the spec says. `revealSelection()` is not gated and still dispatches `scrollIntoView`, so the editor scrolls to the caret while not focused. The spec's Behaviour section says the whole action is "Skipped ... while a version restore is running". No declared invariant is broken (6 is about input; the dispatch has no doc change, and the header toggle is not disabled during restore so this is reachable).
Note for the jsdom tests: jsdom's focusability check treats any element with a `contenteditable` attribute as focusable (`jsdom/lib/jsdom/living/helpers/focusing.js:55`), including `contenteditable="false"`, so a jsdom test cannot hold the "focus cannot enter during restore" claim; it would need a real browser.
Bucket suggestion: B.

### F4 - Low - [introduced] - head vs anchor not held
File: `frontend/MarkdownEditor.tsx:456`.
Observation: M7 (`head` -> `anchor`) survives; the scroll test uses a collapsed selection (5..5). For a backward range the two differ. The spec names `head`; no invariant names it. Bucket suggestion: B.

## Is anything missing from the list? (round 1 only)

- **A mode switch before the editor is mounted is a no-op and does not throw.** Invariant 6 speaks only of "accept input"; probe B shows this state is reached on ordinary navigation (preview note -> file change with `?edit=1`), and a throw here breaks the page, not the editor. Suggested wording: "Switching into edit/split while the note is loading, including a file change that lands in edit, throws nothing and leaves focus where it was."
- **Nothing scrolls while the transition does not focus.** Invariant 3 covers split<->edit and ->preview, but not preview->edit during a restore (F3). Worth deciding whether "no scroll without focus" is an invariant or not.
- Mobile soft keyboard on tap Edit is an R-5 manual check in the spec, not something a mutation can hold; not proposed as an invariant.
